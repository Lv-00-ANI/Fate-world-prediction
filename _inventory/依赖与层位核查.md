# 依赖与层位核查

> **本文件记录 FateV2 的依赖结构实测结果，以及迁移时的层位判据。**
> 所有数字由 `_migration/depcycle.py` 与 `_migration/layercheck.py` 生成，可复现。

---

## 一、首要结论：依赖图是 DAG，无环

```
FateV2 模块: 305
真正的循环依赖（强连通分量 > 1）: 0
✅ 无环
```

**检测方法**：Tarjan 强连通分量算法，在**模块级**（不是域级）判断。

### 为什么域级别会「看起来有环」

域级矩阵同时出现 `Loop → Error`（19 处）与 `Error → Loop`（17 处），
容易误判为环。但真正的环要看**具体模块**：

```
Loop/Convergence     → Error/ErrorBand
Error/ErrorBand      → Loop/Residual      ← 这两个之间不是环
```

只有 `A → B → ... → A` 走回**同一个模块**才是环。实测一个都没有。

**⟹ 依赖本身是健康的，不需要「打破环」。**

## 二、真实存在的问题：29 处反向依赖

按 `09-总设计` 的六层链路（`docs/archive/09-总设计/README.md:60-117`）：

```
基底   Core / Classical / Bridge     （构造性核）
第 0 层 Modeling   数学建模
第 1 层 Model      模型
第 2 层 Rules      规则 / IR
第 3 层 Predict    预测
第 4 层 Export     导出
第 5 层 Error      误差
第 6 层 Loop       闭环
横切   Meta
```

`layercheck.py` 检测「下层 import 上层」，结果 **29 处**：

| 从 | 到 | 处数 |
|---|---|---:|
| Error | Loop | 13 |
| Core | Model | 3 |
| Predict | Loop | 3 |
| Modeling | Predict | 2 |
| Predict | Error | 2 |
| 其余 | — | 各 1 |

## 三、这 29 处**不都是错误**——必须分两类

### 【甲】验证性引用（设计固有，不该移动）

模块的**职责就是检查上层**，所以必须 import 上层。

| 模块 | 性质 | 为什么必须引用上层 |
|---|---|---|
| `Core/Pointwise` | T16 专项 | 把上层各模块里用 `funext` 的证明**逐点改写**，必须 import 那些模块 |
| `Core/VerdictAlgebra` | T52 专项 | 判据的**层谱**，要跨层比对 |
| `Core/Cardinality` / `Core/Unified` | 专项 | 同上 |
| `Error/*` → `Loop/*` (13 处) | 误差层评估闭环 | 例：`VerdictTheory` 研究「闭环**回写之后**边界点还算不算」 |
| `Modeling/Construction` | 建模假设登记 | 构造模型时要登记引用了哪些误差/模型概念 |

**判据**：看模块的文件头是否声明为「专项 / 验证 / 审计 / 只读引用 / 改写成 / 归零」。
这 4 个 Core 模块全部命中。

**⟹ 这类反向依赖是架构的**有意设计**，记载在案，不视为缺陷。**

### 【乙】真错放（应当移动）

概念本身属于低层，却因为历史原因放在高层。

**目前发现 1 个明确案例：**

| 模块 | 现状 | 内容 | 应当 |
|---|---|---|---|
| `Loop/CoreBasics` | Loop 域，71 行，**0 定理** | `gradForce` / `histInertia` / `ShouldStop` / `tauOf` | 这些是**误差动态的基础量**，不是闭环专有概念 ⟹ 应下沉 |

`Error/FitBoundary`（1019 行）为了用 `gradForce`/`histInertia` 而 import 了整个 `Loop.CoreBasics`，
这是典型的「为 5 个定义付一次跨层依赖」。

## 四、迁移时的层位判据（本轮确立）

迁入一个新模块时，**不能按 Legacy 原目录或模块名归域**，按下面顺序判定：

| 步骤 | 判据 | 例 |
|---|---|---|
| 1 | 若模块**职责是检查/改写其他模块**（专项）→ 放在被检查者的**相邻下层**，并登记为验证层 | `Core/Pointwise` |
| 2 | 否则看它**依赖谁**：放在「它依赖的最高层的上一层」 | 依赖 Modeling 与 Model ⟹ 放 Rules 或更高 |
| 3 | 若它**只定义概念、不含定理**（如 `CoreBasics`）→ 应尽量下沉到最底层需要它的那一层 | `gradForce` ⟹ Error/Modeling |
| 4 | 归域后**必须重新测 DAG**：`python _migration/depcycle.py` 要求 0 环 | — |

**硬约束**：迁入后全库 `lake build` 必须通过，且 `depcycle.py` 仍报 0 环。
