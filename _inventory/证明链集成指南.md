# 证明链集成指南

> 迁移完成后的第二阶段：把 975 个「能编译」的模块变成「真正可用」的证明链。
> 本文件记录判据、方法、已完成清单与失败模式，供接续者直接使用。

## 一、为什么需要这一阶段

第 33 轮全量验证发现：`FateV2` 975 个模块全部能编译，但**能编译 ≠ 可用**。

第 119 轮修正引用图测量后（`IMPORT_RE` 缺 `(?m)` 导致 import 边大量丢失），
得到真实分布：

| 状态 | 定义 | 数量（第 119 轮） |
|---|---|---:|
| **真消费** | 被 import，且其某个定义名出现在对方**代码**里 | 319（32%） |
| **假接线** | 被 import，但没有任何名字被实际调用 | 351（35%） |
| **孤立** | 没有任何模块 import 它 | 309（31%） |

「假接线」是最值得修的一类 —— 下游已经 import 了它，只差真实引用。

## 二、判据：优先做哪些模块

按价值排序的三条判据（第 122–125 轮验证有效）：

### 判据 1：被 import 次数多，但无名字被调用

这类不是「无人需要」，而是**接线丢失**。修复价值最高。

用 `_migration/_topfake.py` 列出。实测榜首：

| 模块 | 被 import | 定义数 |
|---|---:|---:|
| `Predict.SeparableCondMul` | 12 | 1 |
| `Error.ChainBudgetBound` | 11 | 28 |
| `Predict.BridgeA1` | 9 | 15 |
| `Modeling.NaryAlgebra` | 9 | 1 |
| `Rules.Completeness` | 8 | 39 |
| `Predict.DoCalculus` | 8 | 10 |
| `Error.ScoreK` | 8 | 7 |

### 判据 2：签名清晰

优先选**参数显式、结论是 `Prop`** 的定理。
带大量 `variable` / 实例参数的定理组合起来容易失败（见 §四）。

### 判据 3：组合要有实质

最好的组合是「**单看任一条只是半个故事**」的定理对。例：

- `do_idempotent`（重复干预无效）+ `do_comp`（后者覆盖前者）
  ⟹ 合起来才是「`do` 构成幂等半群作用」
- `eta_one_iff_one_step_exact`（η=1 最快）+ `eta_iff_fails_at_fixed_point`（η=0 停滞）
  ⟹ 合起来才是对 η 两端的完整刻画
- `pseudoIntent_closure_closed`（闭包是闭集）+ `pseudoIntent_closure_strict`（闭包严格更大）
  ⟹ 合起来才是「迭代能推进且落在闭集上」

**反面例子**：纯粹把两条无关定理用 `∧` 连起来。技术上能通过，
但没有数学价值，不要这样做。

## 三、方法：怎么写一个集成模块

### 结构模板

```lean
import FateWorld.FateV2.<域>.<源模块A>
import FateWorld.FateV2.<域>.<源模块B>

/-!
# Integration · <域> · <主题>

## 本文件做什么
（说明消费了哪几个模块、哪些定理）

## 组合的实质
（说明为什么这些定理需要并置，而不是简单罗列）

## 不引入新数学
全部为既有定理的组合。
-/

namespace FateV2.Integration
namespace <名字>Capstone

open <域命名空间>
open <源模块的完整命名空间>

variable <照抄源文件的variable声明>

theorem <组合名> <参数> :
    <结论1> ∧ <结论2> :=
  ⟨<源定理1> <参数>, <源定理2> <参数>⟩

end <名字>Capstone
end FateV2.Integration
```

### 必须做的四件事

1. **先读源文件的真实签名**（不要凭名字猜 —— 见 §四第 4 条）
2. **`open` 到最内层命名空间**（外层 open 不递归）
3. **`variable` 声明照抄源文件**（含所有实例参数）
4. **参数全部显式传入**（`variable` 里的变量如果隐式，需要 `(K := K)` 这样指定）

## 四、失败模式清单（每条都实际踩过）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `Unknown identifier X` | `X` 在更深的命名空间 | `open` 到最内层 |
| 2 | `Unknown identifier Ns.X`（带前缀） | 需要 `Ns` 本身可见 | `open` **父层** |
| 3 | `Function expected at X ... ?m.N` + autoImplicit Hint | 其实是缺 open/import | 查 `name_index.py` |
| 4 | `unexpected token 'in'` / `Application type mismatch` | **凭印象猜了源定理的结论** | 先读源文件签名 |
| 5 | `invalid binder annotation, type is not a class instance`（`?m.N`） | 名字未入作用域 | 补 import + open |
| 6 | `pseudoIntent_closure_closed hP` 把 `hP` 当成了 `K` | 隐式变量被当成首个显式参数 | `(K := K) hP` |
| 7 | `Measure` 未知 | 缺 `open MeasureTheory` | 补 |
| 8 | 缺 `[IsProbabilityMeasure P]` | 源定理带实例参数 | 补进 `variable` |
| 9 | `Invalid field` / `Field projection operates on types of form C ...` | 字段记法在**类型的命名空间**里找 | 改全限定或调整命名空间 |

### 特别提示

**失败模式 3 和 5 会伪装成类型错误。** 见到 `?m.N` 一律先怀疑「名字不在作用域」，
而不是「类型不对」。

### 6.3 自动化尝试的结论（已失败，勿重复）

第 121 轮试过用生成器批量产出「定理汇总 capstone」：

```lean
theorem cap_X : T1 ∧ T2 ∧ T3 := ⟨T1, T2, T3⟩
```

在 `Error` 域 6 个模块上**全部失败**。根因：被重述的定理普遍**带自由变量**
（section 的 `variable` 或隐式参数），裸引时 Lean 无法推断，报
`Application type mismatch`。

**结论：自动重述只在定理完全闭合时成立，而这样的定理是少数。
集成必须人工做。**

工具保留在 `_migration/gen_capstone.py` / `gen_capstone2.py`，
可用于**发现**哪些模块有闭合定理。

## 八、验证纪律

每写一个集成模块：

1. `lake build FateWorld.FateV2.Integration.<名字>` —— 必须 `olean=True`
2. 跑 `refgraph.py --csv` —— 确认目标模块的状态确实从「假接线」变为「真消费」
3. 提交时在 message 里写清：消费了哪些定理、组合的实质是什么

**不要只凭编译通过就声称「已接入」** —— 必须用引用图确认状态真的变了。
