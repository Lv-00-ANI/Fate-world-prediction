# 迁移完整性问题（重要）

> **状态**：已发现、已量化、**未修复**
> **发现轮次**：第 30 轮
> **性质**：流程缺陷导致大批模块从未被编译过

---

## 一、问题

`FateWorld.lean`（总入口）停在 **1105 条 import**，而实际模块已达 **1828 个**。

`lake build FateWorld` 只构建入口文件的 import 闭包。
**入口没列出的模块，从来不会被编译。**

### 后果

批量迁移工具 `batch_all.py` 的验证步骤是：

```
写入 N 个模块 → lake build FateWorld → 解析错误 → 回滚失败项
```

由于新模块不在入口的 import 闭包里，`lake build FateWorld`
**根本没有编译它们**，于是「无错误」不成立 —— 验证是**空洞的**。

从第 11 轮改用批量模式起，到第 29 轮，累计约 600 个模块的
「迁移成功」结论都建立在这个空洞验证之上。

## 四、根因

三个独立缺陷叠加：

### 1. 入口文件没有随迁移更新

迁移工具只写目标模块，**不更新 `FateWorld.lean`**。
入口是无状态的快照，一旦有新模块加入就过期。

### 2. 批量验证依赖入口闭包

`lake build FateWorld` 不是「构建目录下所有文件」，
而是「构建入口及其 import 闭包」。工具误以为它能覆盖全库。

### 3. 域间搬移不更新引用

把模块从 A 域移到 B 域后，引用它的文件仍指向旧路径。
`import` 报 `bad import`，`open` 后名字解析变化导致 `Function expected`
这类隐蔽错误。

---

## 五、正确的做法

### 验证必须覆盖真实文件集

```powershell
# 逐模块验证（慢但准确）
Get-ChildItem FateWorld\FateV2 -Recurse -Filter *.lean | ForEach-Object {
  $mod = 'FateWorld.FateV2.' + ($_.FullName -replace [regex]::Escape("$PWD\FateWorld\FateV2\"),'' -replace '\\','.' -replace '\.lean$','')
  lake build $mod
}
```

或 **每次迁移后重新生成入口**，再跑全库构建。

### 迁移工具必须

1. 写完模块后**重新生成 `FateWorld.lean`**
2. 移动模块时**扫描并更新所有引用它的 import**
3. 规则 8（包 namespace）必须先判断定义是否在注释/代码围栏内
4. 迁移头必须插在 **import 之后**，而不是文件开头
