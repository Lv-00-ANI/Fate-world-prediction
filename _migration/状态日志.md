## 方法论：为什么这次能收敛

前三次尝试都失败了，共同的失败模式是：

> **跑 `lake build` 一把梭 → 卡住 → 不知道卡在哪 → 整株重来**

第四次改变策略：

| 之前 | 现在 |
|---|---|
| 一把梭，等结果 | 先修可见错误，再跑 |
| 看 Job 状态 | **看文件系统产物数**（`olen` 计数不会骗人） |
| 「改了 N 个文件」当成功 | **统计「改写了多少处 import」** 才能发现漏网 |
| 卡住就重跑 | 卡住先**定位是哪个模块、什么错误** |

**关键教训**：`lake build` 的「成功/失败」是二值的，但**进度是一维的**。
用产物计数代替 Job 状态，才能区分「在编译大模块」与「真的卡死」。
