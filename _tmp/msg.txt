结论（否定）：批量自动集成不可行 —— 定理普遍带自由变量

## 本轮做了什么

尝试用生成器批量把「假接线」模块转为真消费：
    _migration/gen_capstone.py    导出「无参定理」汇总骨架
    _migration/gen_capstone2.py   加上完整命名空间限定

在 Error 域试跑 6 个模块，**全部编译失败**，已删除生成文件。

## 失败的根本原因

自动重述的形态是：

    theorem cap_X : T1 ∧ T2 ∧ T3 := ⟨T1, T2, T3⟩

但被重述的定理普遍**带自由变量**（section 里的 variable 或隐式参数）。
在项位置裸引时，Lean 无法推断这些变量，报：

    error: Application type mismatch: The argument
      ErrorN.var_monotone_breaks_errAt
    has type
      ∃ b v, (∀ γ, Antitone ...) ∧ ...
    of sort Prop but is expected to have type ...

即：定理本身是「一个 ∃ 命题」，但它在源文件里其实被 section variable
参数化（例如 b、v 由上下文给出），裸引时变量未实例化。

**这不是我代码的 bug，而是「定理不是闭合项」这一事实。**
自动重述只有在定理真正闭合（无自由变量）时才成立，
而这样的定理在库里是少数。

## 这意味着什么

「把证明整合到证明链」**本质上需要人工判断**：
- 要引用一条带假设的定理，必须自己提供实例或把它放进合适的上下文
- 真正的组合定理（如 SemigraphoidCapstone 的 condRel_locate_symm）
  需要理解两条定理如何协同，这是模板做不到的
