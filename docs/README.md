# docs · 文档层说明

> **这里放的是「判断」，不是「代码」。**
> 代码可以重写，判断不能重建——所以文档比代码更需要可读的入口。

## 为什么单独设一层

上游 `../理论-文档/` 里有 504 个文件，是**一年工作的全部判断**：

| 内容 | 数量 |
|---|---:|
| 作者裁决 | 24 条 |
| 概念级冲突 | 9 条 |
| 可拼装环节 | 240 个 |
| 主定理路线 | 833 条 |
| 全量扫描 `.md` | 1,400 份（去重后 1,069） |

**但它们散在 11 个编号目录里，没有一个「从哪读起」的入口。**

本目录的任务不是复制它们，而是：**建立入口 + 标注优先级 + 指向原文**。

## 一个必须知道的事实

**文档与代码经常不一致，而且数字会过期。**

实测例子：

| 说法 | 实际情况 |
|---|---|
| 「18 条裁决」 | **24 条**（D-019～D-024 未被引用） |
| 「已迁入 143 个模块」 | 映射表登记 145，实际迁了 **126**，**99 个从没迁** |
| 「进度停在 B5」 | 实际已到 **T61**，落后 30 天 |

**⟹ 引用任何数字前，先去 `_inventory/` 或现场跑一遍。**

## 与上游的关系

`docs/` **不取代** `../理论-文档/`。后者是原始材料（只读），本目录是**索引与导读**。

凡本目录与 `理论-文档/` 冲突，**以原文为准**，本目录为误。
