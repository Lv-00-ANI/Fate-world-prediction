## 一、四类文档，各管一件事

```
docs/
├── README.md            ← 本文件：文档入口
├── _归档说明.md          ← 归档层的说明与阅读顺序
├── 证明架构索引.md        ⭐ 1106 个模块的导航（我要找的证明在哪）
└── archive/             ← 上游 `理论-文档/` 完整镜像（254 文件，零差异）
```

| 目录/文件 | 管什么 | 可信度 |
|---|---|---|
| **仓库根 `README.md`** | 项目是什么、怎么构建、当前状态、下一步 | 当前有效 |
| `docs/证明架构索引.md` | 证明的组织方式、分类、导航 | 当前有效 |
| `docs/_归档说明.md` | 归档层怎么读、哪里过期 | 说明性 |
| `docs/archive/` | **上游全部判断原文**（24 条裁决、9 条冲突、总设计…） | **原始史料，含已知过期内容** |
| `_inventory/` | 迁移与治理清单（分类表、缺陷登记、空壳补全） | 当前有效 |
| `_migration/` | 迁移过程记录与规则 | 历史记录 |

## 三、三层可信度（重要）

引用任何结论前，先确认它来自哪一层：

| 层 | 位置 | 可信度 | 怎么验证 |
|---|---|---|---|
| **已验证实现** | `FateWorld/FateV2/` | 过了 10 项门禁；核内 423 条定理零公理 | `lake build` + `#print axioms` |
| **历史收容** | `FateWorld/Legacy/` | **仅保证可编译** | `#print axioms`（未逐个判定） |
| **原始史料** | `docs/archive/` | 原样保存，**含已知过期内容** | 对照 `_inventory/` 与现行 README |

**⟹ 「能编译」≠「定理正确」≠「设计仍有效」。** 三者是不同的事。

## 五、文档维护约定

| 约定 | 说明 |
|---|---|
| **`archive/` 只读** | 上游原文不改。需要订正时在 `docs/` 顶层新建文件说明 |
| **数字必须带口径** | 任何「多少条/多少份」都要能复现（上游 `_约束.md` 的纪律） |
| **过期内容要标注** | 归档里的过期说法在 `_归档说明.md` 里列了对照表 |
| **不写开源协议** | 按项目方要求，暂不添加 LICENSE |
