## 一、架构级（动主链，风险最高）

### 待裁-01 · `discPushFamily` 默认路径仍是错的

**现状**（我核实过源码）：

```lean
-- FateV2/Predict/Predict.lean:182
def discPushFamily : PushFamily DiscLaw SynthE Real Real where
  push := fun L f => rawMap L f      -- ← 丢质量的旧版
```

**问题**：专项 T13 交付了正确的 `discPushFamilyM`（用 `pushMerge`），
专项 T22 的 G14 会**报警**指出 4 处违规，但**`predict` 的默认族没换**。

⟹ **正确的实现存在，但默认路径仍然是错的。调用方忘记传合并版就用回有 bug 的。**

**三条路**：

| 方案 | 代价 |
|---|---|
| **甲** 改 `discPushFamily` 返回合并版 | 需 `Real` 上的 `DecidableEq`（走 `Classical`），影响所有调用方；`Demo` 的数值可能要重算 |
| **乙** 改 `PushFamily` 结构加实例槽 | ❌ T13 实测：测度侧再也建不出族，**违 D-019** |
| **丙** 留现状 + G14 报警 | ✅ 当前做法，**不根治** |

**我的倾向**：**甲**（默认安全优于兼容），但它会波及 `Demo` 的数值链。

**需要你定**：甲／乙／丙。

### 待裁-02 · `Real` 承载类型是否换成刻度化整数

**背景事实**（T13/T15/T17 三轮实测确立）：

```lean
theorem tSelf : (1:Real) = 1 := rfl   -- 三公理
structure Qty where v : Real
theorem c : q = q := rfl              -- 三公理（签名里没有 Real）
```

**`Real` 的四种隐蔽形态**（显式 / 字面量 / 结构体字段 / 引用的 def 返回类型）
使 **2415 条定理（81%）带公理**，其中 **1831 条（75.8%）由 `Real` 根因锁定**。

**选项**：

| 方案 | 收益 | 代价 |
|---|---|---|
| **甲** 核心数据类型换刻度化整数/有理数 | 356 条可摆脱公理；`ExportVal`/`ErrProfile` 可清零 | 全库核心类型改动；`Demo` 数值全部重算；`Error`/`Loop` 的 98% 未必能降（它们大量用 `Real` 做数学分析，换掉可能失去定理） |
| **乙** 接受现状：`Core/` 零公理（270 条），其余允许经典 | 不动 | 81% 带公理比例不变 |

**我的倾向**：**乙**。理由：`Core/` 的零公理已保证 IR 层是构造性的；其余层用 `Real` 是数学建模的必然需要。T17 实测「C 类可降级」命中率仅 1.9%，说明靠改写证明降不下来。

**需要你定**：甲／乙。
