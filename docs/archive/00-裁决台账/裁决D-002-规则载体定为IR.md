## 一、裁决内容

**规则（Rule）的主载体 = 基于 CIC 的中间表示（IR），并约束到与 Lean 相同的三条公理。**

具体：

| 项 | 裁决 |
|---|---|
| **载体** | `F3-14` 的 **V5 IR（CIC 语法项）** — `Fate/RuleSyntax.lean:85` `inductive RuleTerm` |
| **公理约束** | 只允许 `propext` / `Classical.choice` / `Quot.sound`（与 `_约束.md` D 节入库门禁一致） |
| **不再采用** | V1 映射式、V2 核式、V4 蕴含式 **作为主载体**（降为 IR 的解释目标或下游形态） |
| **V3 分布集合式** | **保留，但降为语义层**——见 §三「两层结构」 |

## 二、为什么这个裁决有现成依据

`Fate/RuleSyntax.lean` 的模块头**逐字**写了为什么它满足这个要求：

> ## 为什么这满足「直接基于 CIC 和三条公理」
> * `RuleTerm` 是 Lean 的 **`inductive` 类型** ⟹ 本身就在 CIC 里；
> * `eval` / `holds` / `toLawRuleWith` 都是**普通 `def`** ⟹ 它们的每条等式定理只用 `rfl`（不引新公理、不用 `sorry`）；
> * 因此「IR 嵌入 Lean」不是翻译，而是**同一个类型论内的构造**。

**⟹ 你的裁决与已有实现的设计理由完全一致。** 这不是新立方向，是确认一条已铺好一半的路。

### IR 第一版的实际内容（已实现，非声明）

| 项 | 内容 |
|---|---|
| `RuleTerm` | `inductive`，10 个构造子：`const` / `var` / `add` / `mul` / `eq` / `le` / `lt` / `and` / `or` / `not` |
| `Env` | `ℕ → ℝ`，变量环境 |
| `RuleTerm.eval` | 算术语义：语法项 → ℝ |
| `RuleTerm.holds` | 断言语义：语法项 → `Prop` |
| `toLawRuleWith` | ⭐ 语法项 → `LawRule`（IR 到语义层的接口） |
| 定理 | `eval_*` / `holds_*` / `toLawRuleWith_apply` 均为 `rfl` 级 |

## 三、必须一起承接的代价（`RuleSyntax.lean` 自己声明的诚实边界）

### 3.1 它是**语法层**，不是语义层

IR 本身不产生预测，必须经 `toLawRuleWith` 解释到 `LawRule`（即 V3 分布集合）。

**所以 V5 与 V3 不是二选一，是两层叠加**：

```
RuleTerm（语法层，CIC）
    │  toLawRuleWith  ← 需要 interp 参数
    ▼
LawRule（语义层，Set (Measure Y)）
    │  单点档提取 IsPoint
    ▼
Pred（预测分布）
```

**⟹ 「规则 → 预测」的链条从一段变成两段，而且两段都还不通。**

### 3.2 `interp` 未构造

`RuleSyntax.lean` 逐字写：

> **`interp : Measure Y.Carrier → Env` 是参数，未定**。本模块只声明「若给定分布→环境的解释，则约束项可解释为 `LawRule`」，**不构造任何具体的 `interp`**。**这是「桥的接口」，不是桥的实现。**

**⟹ 新增一个缺口：`interp` 的构造。**

### 3.3 IR 第一版表达能力有限

`RuleSyntax.lean` 逐字写：

> **只做算术与逻辑约束**：`const / var / add / mul / eq / le / lt / and / or / not`。**无概率、无微分、无积分、无归纳迭代**。

**⟹ 当前 IR 表达不了**：
- 概率规则（`R : P(y|x,c)` 的分布语义）
- 微分方程（连续形式的 `μ, σ`）
- FCA 蕴含规则（`A ⇒ B` 的全称形式——虽然可用 `and`/`not` 编码一部分，但概念格的集合语义不在）
- 归纳/迭代定义的规则
