## 一、裁决内容

### 1.1 架构

```
┌──────────────────────────────────┐
│  IR 之上的全部内容 —— 都是「规则」   │  ← 无第二类公民：没有独立的类型层/算子层/语义层
├──────────────────────────────────┤
│  底座：CIC + 三条公理               │  ← propext / Classical.choice / Quot.sound
└──────────────────────────────────┘
```

**判据**：凡是底座之上的东西，**必须是规则**。若某物既不是 CIC/公理、又不是规则，它就不该存在。

### 1.2 三条立项（确认「都是」）

| # | 项 | 裁决 |
|---|---|---|
| 1 | `interp : Measure Y → Env` | ✅ **立项为必做** |
| 2 | IR 扩到能表达概率 / 微分 / 积分 | ✅ **立项** |
| 3 | 四算子（γ/∘/υ）在 IR 层重做 | ✅ **立项** |

### 1.3 拓展方式

| 阶段 | 方式 |
|---|---|
| **现在** | **人工拓展** —— 已人工拓到当前 10 个构造子（`const`/`var`/`add`/`mul`/`eq`/`le`/`lt`/`and`/`or`/`not`） |
| **后续** | **自行拓展** —— 由系统自己扩展，不再靠人工加构造子 |

## 二、依据

- D-002 已定：规则主载体 = CIC 层面的 IR（`RuleTerm`），约束三条公理。
- `Fate/RuleSyntax.lean` 模块头自证「`RuleTerm` 是 Lean 的 `inductive` 类型 ⟹ 本身就在 CIC 里；`eval`/`holds`/`toLawRuleWith` 都是普通 `def` ⟹ 每条等式定理只用 `rfl`」。
- 本裁决在此之上补两点：**（a）底座之外只准有规则；（b）IR 要能自己长。**

## 三、必须一起承接的代价

> 三条都是**实测出的结构性障碍**，不是推测。

### 代价 1 · 当前 IR 是**封闭** inductive，与「自行拓展」直接冲突

`Fate/RuleSyntax.lean` 实测：

```lean
inductive RuleTerm : Type
  | const (c : ℝ) | var (n : ℕ) | add (a b : RuleTerm) | mul (a b : RuleTerm)
  | eq (a b : RuleTerm) | le (a b : RuleTerm) | lt (a b : RuleTerm)
  | and (a b : RuleTerm) | or (a b : RuleTerm) | not (a : RuleTerm)
```

**恰好 10 个构造子，没有任何 `ext` / 开放钩子。**

⟹ **加一个构造子 = 改 `inductive` = 所有下游 `match` 全部要改。**
「人工拓展」现在是可行的（就改这一处）；「自行拓展」在**封闭归纳类型上不可能**——必须先把类型设计改成可扩展的。

### 代价 2 · 「全是规则」要求 IR 能表示「关于规则的规则」

若 γ/∘/υ 本身就是规则（而不是套在 IR 外的算子），那 IR 必须能表达**规则值**。

但当前 `Env := ℕ → ℝ` —— **环境只能承载实数值**，承载不了规则。
`eval : RuleTerm → Env → ℝ` 也只能产出实数值。

⟹ **当前 IR 无法表达「复合一条规则」「泛化一条规则」——即它表达不了自己的算子。**
「全是规则」+「自行拓展」合起来，等于要求 IR 具备**自描述能力**。

### 代价 3 · 扩到概率/微分/积分，不是「加几个构造子」

| 要表达 | 需要什么 | 当前有无 |
|---|---|---|
| 概率规则 `P(y\|x,c)` | 测度值；或 probability monad | ❌ `eval` 值域是 `ℝ` |
| 微分 / SDE | **绑定结构**（λ、导数算子、积分变量） | ❌ 一阶项代数，无 binder |
| 积分 `∫ f dμ` | 同上 + 测度参数 | ❌ 同上 |
| FCA 蕴含 `A ⇒ B` | 集合语义 / 二阶 | ❌ 只有 `and`/`not` 在 `ℝ` 上 |

⟹ **表达力扩张很可能是「改语义函数类型」而不是「加构造子」**：
`eval : Term → Env → ℝ` 可能需要变成 `denote : Term → Env → Measure`（或 `Prop`）。

**这是破坏性变更，波及 `holds` / `toLawRuleWith` / 全部 `rfl` 定理。**

### 代价 4 · `interp` 有损，且对任意分布未必存在

`interp : Measure Y.Carrier → Env`，而 `Env := ℕ → ℝ`。
把一个概率分布编码成一列实数——**必然有损**，且对一般分布**未必可构造**（如无有限矩的分布）。

⟹ 立项时必须同时定：`interp` 的**适用范围**（只支持点质量？有限支撑？有矩？）。

## 五、未决尾巴（比 D-002 更细）

| # | 未决问题 | 不定的后果 |
|---|---|---|
| **1** | 「γ/∘/υ 是 IR 内的规则」需要 **反射**（IR 能引用自身项）还是 **分层**（Rule₀, Rule₁ = 关于 Rule₀ 的规则, …）？ | 这决定整个类型设计。反射 → 需要 quotation/名字；分层 → 需要宇宙层次 |
| **2** | `LawRule`（分布集合）作为语义层，是否也算「底座之外的规则」？若是，它应被 IR 表达；若不是，它就在「全是规则」之外 | 决定 `LawRule` 是否保留为独立类型 |
| **3** | `interp` 的适用范围：点质量 / 有限支撑 / 有矩 / 一般 | 决定 IR 能表达哪类规则 |
| **4** | 语义函数值域是否从 `ℝ` 改为 `Measure`（或 `Prop`）？ | 破坏性变更，波及全部 `rfl` 定理 |
| **5** | 「自行拓展」的具体机制：**（A）开放类型**（加构造子不改核心）/ **（B）自描述**（IR 能表达 IR）/ **（C）自动搜索**（系统发现表达不了并自动提议）？ | 三者的工程量差一个数量级 |

**我认为 §五.5 是最需要你先定的**——它是「后续自行拓展」这句的唯一落点，而 A/B/C 三条路的技术含量完全不同。
