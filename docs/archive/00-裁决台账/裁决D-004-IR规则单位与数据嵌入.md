## 一、裁决内容（七条）

| # | 裁决 |
|---|---|
| **1** | **IR 的基本单位 = 条件定理（`Judgment`）**，不是项。当前 `RuleTerm` 把项与命题混装在一个类型里，是设计缺陷，须拆成 `Term` / `Formula` 两层 |
| **2** | **反射（乙）+ 分层**。`J₀`（条件定理）→ `J₁`（关于 J₀ 的定理）→ …，`Jₙ` 只能引用 `J_{n-1}`，predicative，避开 Girard 悖论 |
| **3** | **四算子有两张脸**：J₀ 层是实现（可算），J₁ 层是规格（可证）。这就是「变换本身是定理」 |
| **4** | **`Judgment` 必须携带 `support`**（靠哪些未证前件 + **靠哪批数据**）与 `status`（已证/条件/经验/已反驳） |
| **5** | **数据可直接嵌入**：数值用**精确有理数 `ℚ`**；大数据用 `DataId` 引用并**登记为经验输入**；**不使用** `native_decide` |
| **6** | **自我拓展 = C1 + C2，C3 列入待研究**。C1 规则集自长、C2 语法可扩（`ext` + 注册表）；C3（自动发现缺口）研究级 |
| **7** | **语法开闭（Q2）先按「弱」做**：开放 `ext` + 注册表，运行时扩**规则集与注册表**，不扩类型定义；给「强」（运行时扩语法，需 `Expr`）留升级口 |

## 二、依据

- **「所有东西都是定理」** → 单位必须是判断（条件定理），不是项。
- **「定理都是再变换的」** → 变换必须作用在判断上，且变换自身要可证 → 两张脸 + 反射。
- **「大多数来自外界的都是条件定理」** → `status` 默认值应为 `conditional`/`empirical`，不是 `proven`。
- **「接受物理世界的不干净」** → `support` 两个维度（假设 + 数据），且**没有任何算子能减少 support**。
- **「运行时规则变化」** → C1（规则集）+ C2（注册表）在运行时增长。
- **「直接嵌入数据」** → `Data` 层，`ℚ` 字面量 + `DataId` 引用。

## 三、必须一起承接的代价

### 代价 1 · 破坏性重构

`RuleTerm` 拆成 `Term` + `Formula`，`eval`/`holds` 改名加参，`RuleSyntaxOps` 淘汰。
**波及**：`WorldModel.rules`、`Rules`、四算子、`apply`、`toLawRuleWith`。

### 代价 2 · 反射需要真构造，不是声明

本裁决要求「变换本身是定理」，但 `quoteJudgment : Judgment → Term` 的**具体构造尚未给出**。
只给接口不算落地。

### 代价 3 · support 会无限增长

运行时每轮 α/υ 都把数据批次加进 `support.data`，跑久了会爆。
**必须配套「来源剪枝」规则**，本裁决未定该规则（列入 D-004 的尾巴）。

### 代价 4 · 不用 `native_decide` ⟹ 数值验证很慢

三条公理保住，但大数据的内核规约不可行。
出口：数值结论登记为 `empirical`，不当定理。

### 代价 5 · 「运行时」的强度受限

Lean 里语法是编译期的。本裁决的「运行时拓展」= 规则集 + 注册表增长，**不是**类型定义变化。
若要后者，需换 `Expr` 路线（丢类型保证），已登记为升级口。
