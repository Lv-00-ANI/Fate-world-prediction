## 一、裁决内容

| # | 裁决 |
|---|---|
| **1** | **数据是可消融的**。数据的作用可以被完全吸收进形式化产物，此后定理不再需要数据本身 |
| **2** | **只要能形式掉，数据就直接归档保留，但不嵌入定理** |
| **3** | 因此 `Judgment.support` **不含数据字段**，只有 `assumptions` |
| **4** | `Data` 类型**不设 `ref`（数据引用）构造子**，只留 `rat` / `vec` / `tup`，用于**见证与反例** |
| **5** | 数据本身进 **`DataArchive`**（带 hash），只有 `Assumption.evidence` 引用它 |

---

## 二、消融的具体机制

数据 `D` 到达后，α/υ 执行：

```
① 形式化：把 D 中可形式化的内容抽成公式 φ
   │
   ├── φ 可在此框架内证明 ──▶ 产出「具体定理」（support = ∅）
   │                          D 归档，不进定理
   │
   └── φ 不可证（真经验内容）──▶ 登记为「经验假设」a
                                a.evidence := [D.id]
                                定理只引用 a.id，不进 D
```

**判据**：「可形式化」= 能写成一个不含自由数据引用的公式，且该公式可在此框架内处理（证或登记）。

---

## 三、为什么这解决了 support 无限增长

| 原问题 | 消融后的结果 |
|---|---|
| 每轮 α/υ 都把 `D.id` 加入 `support.data`，跑久必爆 | `support` 里**没有 data 字段** |
| 可形式化的数据 | 变成**具体定理**，`support = ∅`，**零增长** |
| 不可形式化的数据 | 变成**少量、稳定**的经验假设（A1–A34 那一类） |
| 数据本身 | 在档案里，**不进定理** |

**⟹ 增长只发生在经验假设上，而那一类应当少而稳，不是每批数据加一条。**

**⟹ 不需要「来源剪枝」这种补丁。** 增长问题在消融这一步就消掉了。

**替代机制**：引用计数式**自然淘汰**——某条经验假设不再被任何 `Judgment` 引用时，可移出支撑集（仍留档）。这不是剪枝。

## 四、数据「直接嵌入」的能力保留在哪

前面说数据不嵌入，但**能力要保留**——否则写不出见证与反例：

| 情形 | 形式 | 是否嵌入 |
|---|---|---|
| 具体数值见证（「取 x=3/4 使 f(x)=0」） | `lit (.rat 3/4)` | ✅ 嵌入 |
| 反例（几个具体点） | `lit (.rat …)` | ✅ 嵌入 |
| 大规模数据集 | —— | ❌ 归档 |

**判据**：**能写成精确有理数字面量的，嵌入；写不下的，归档。**

## 五、必须一起承接的代价

### 代价 1 · 需要「消融」这一步真的被实现

消融不是自动的：必须有人（或程序）**判断给定数据里哪部分可形式化、哪部分不可**。
这一步的判断质量决定整个系统的诚实度——**判错就等于把经验伪装成定理**。

⟹ 消融必须是**显式步骤**，且每次消融要留记录（哪部分成了定理、哪部分成了假设）。

### 代价 2 · 具体定理可能爆炸

若每批数据都产出「具体定理」（形如「D 上这个多项式取值满足 …」），定理数量会爆炸。

⟹ 需要**具体定理的压缩机制**（如按模式归并），但这条**本裁决未定**。

### 代价 3 · 档案的可信度依赖 hash 纪律

数据归档后不再进定理，所以**档案是唯一的溯源入口**。
若 hash 不校验、来源不记录，则「可复现」是空话。

⟹ 每条被 `evidence` 引用的数据必须有可校验的 hash。
