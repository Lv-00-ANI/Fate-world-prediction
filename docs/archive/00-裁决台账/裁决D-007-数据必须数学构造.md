# D-007 · 数据必须用数学语言构造（全链强制）

> **裁决日期**：2026-10-28
> **裁决人**：作者
> **裁决原话**：「a　以及嵌入数据是要求强制用数学语言描述的虽然可能会很大　说一个裁决　从整个链的开始　所有数据强制要求用数学语言构造出来」
> **触发**：`裁决D-006` 尾#1（「某种和某种」是实体还是类别）
> **设计稿**：[`07-IR设计/README.md`](../07-IR设计/README.md)

---

## 一、裁决内容（五条）

| # | 裁决 |
|---|---|
| **1** | **嵌入的数据可以是复杂逻辑结构**。`Data` 增加 `logic : Formula → Data`；`Term` / `Formula` / `Data` 三者**互相递归**（正向归纳，CIC 合法） |
| **2** | **全链强制**：从链条**起点**开始，**所有数据都必须用数学语言构造出来**。没有例外 |
| **3** | 「虽然可能会很大」——接受构造规模大，不以规模为由退回原始字节 |
| **4** | 因此**不存在「原始数据」这一层**，只有「构造好的数据对象」 |
| **5** | `ref` 指向**已构造的数据声明**，不指向文件；原始字节只进档案做溯源（hash） |

## 二、为什么这条重要

### 2.1 它把「脏」从逃避变成义务

原来的做法：数据是字节，脏（缺失、噪声、采样偏差）**藏在数据里**，谁也说不清。
现在的做法：数据必须被构造成数学对象，**脏必须被显式建模**——作为误差项、缺失掩码、分布假设写出来。

> **「不接受物理世界的不干净」不是靠容忍，是靠把它写进数学。**
> 不建模的脏 = 不存在的脏 = 假装干净。

### 2.2 它把「经验内容」集中成一条可审计的假设

这是本裁决最深的后果。

数据被构造成数学对象后，命题里不再有「外部世界」。但**经验内容没有消失**，它转移到了唯一的地方：

> **「这个构造忠实反映了真实世界」**

这是一条**新建的经验假设**，而它是：
- 显式的（写在假设账本里）
- 可审计的（对照构造与档案）
- 可反驳的（若预测系统性偏差，就是构造不忠实）

⟹ **从「散落在数据里的隐性经验」变成「一条显式的经验假设」。** 这正是本项目「假设必须登记」纪律的终点。

### 2.3 它让链条起点从「加载」变成「构造」

| | 原来 | 现在 |
|---|---|---|
| 链的第 1 环 | `F1-13 原始数据载体`（加载 csv / 字节） | **数据构造层**（把真实数据构造成数学对象） |
| 数据形态 | 字节 / 表格 | `ℚ` 序列、有限测度、函数、复杂逻辑结构 |
| 脏 | 藏在数据里 | **必须建模** |
| 经验假设 | 隐含 | **显式：构造忠实性** |

## 三、类型定义（受本裁决影响的）

```lean
mutual
  inductive Term : Type
    | lit   (d : Data)
    | var   (n : ℕ)
    | add   (a b : Term)
    | mul   (a b : Term)
    | neg   (a : Term)
    | ext   (op : OpId) (args : List Term)

  inductive Formula : Type
    | eq  (a b : Term) | le | lt
    | and (a b : Formula) | or | not | true | false
    | all (body : Formula) | ex (body : Formula)
    | ext (pred : PredId) (args : List Term)

  inductive Data : Type
    | rat   (q : ℚ)
    | vec   (xs : List Data)
    | tup   (xs : List Data)
    | ent   (id : EntityId)
    | logic (f : Formula)        -- ★ 复杂逻辑结构直接当数据嵌入
    | ref   (id : DataId)        -- 指向「已构造的数据声明」
end
```

**合法性**：三者互相递归但**严格正向**（`Data.logic : Formula → Data`、`Term.lit : Data → Term`，都只作为参数出现），CIC 的正性检查通过。Lean 自己的 `Expr` 就是这样互相递归的。

## 四、必须一起承接的代价

### 代价 1 · 语义必须升级为多类

`denoteTerm : Term → Env → ℝ` **不够用**：`lit (.logic f)` 不是实数。

```lean
inductive Value
  | real  (x : ℝ)
  | prop  (p : Prop)
  | ent   (id : EntityId)
  | logic (f : Formula)

def denoteTerm : Term → Env → Value
```

**新增义务**：需要 `WellSorted : Term → Prop`，排除无意义组合（如 `add (lit (.logic f)) (lit (.rat 1))`）。

### 代价 2 · 构造层成为**必经环节**，工作量大

每个数据集都要有人（或程序）把它构造成数学对象，且**构造要经得起审**。
这不是「加载」，是「建模」。

### 代价 3 · 大数据构造会很重

百万行序列构造成 `List ℚ` 会让内核检查不可用。
**作者已明确接受**（「虽然可能会很大」）。但仍需一条工程纪律：构造产物应当**分层**（如分段 + 摘要 + 引用），否则实际不可用。

### 代价 4 · 「构造忠实性」是不可证的

这条新经验假设**无法在框架内证明**，只能登记。
⟹ 必须进假设账本，且**每条构造都要能被追溯**（档案 hash）。

### 代价 5 · 破坏性

`F1-13 原始数据载体` 这个环节要**重新定义**（从「加载」变「构造」）；
链条第 1 段整体要改；`Data` 的递归结构会影响所有 `match`。
