# D-011 · 多模态 = 原数据模态 ∪ 模型可推导模态（开放集）

> **裁决日期**：2026-10-28
> **裁决人**：作者
> **裁决原话**：「不是只有这些模态而是模型能根据这些数据推导出的所有模态」
> **修订**：[`D-009`](裁决D-009-可逆建模与多模态预测.md)「原数据有的所有数据类型」的范围
> **设计稿**：[`07-IR设计/README.md`](../07-IR设计/README.md)

---

## 一、裁决内容（四条）

| # | 裁决 |
|---|---|
| **1** | 多模态**不止**原数据里出现的模态，还包括**模型能从这批数据推导出的所有模态** |
| **2** | 因此模态集合是**开放集**，不是一张固定的表 |
| **3** | `view` 从「渲染器」变为**「推导器」**：给定 `Model` 与模态标识，产出该模态的值 |
| **4** | **完备性要求**：原数据出现的每一个模态，都必须能被 `view` 产出（否则预测结果不可比） |

---

## 二、结构

```lean
/-- 模态标识：开放，可不断注册 -/
abbrev ModalityId := String

/-- **模态**：一个可被 Model 产出的视图。
    `extract` 是推导函数——它从 Model 算出这个模态的值。 -/
structure Modality where
  id        : ModalityId
  carrier   : Type                    -- 该模态的值类型
  observed  : Bool                    -- 是否来自原数据（false = 推导出来的）
  extract   : Model → carrier

/-- **模型**：不再含 raw 数据；只含内部状态 -/
structure Model where
  core : StateCarrier                 -- 内部表示（实现自由）

/-- **模态注册表**：开放列表，加模态 = 加一条，不改 `Model` -/
structure ModalityRegistry where
  mods : List Modality

/-- **呈现（现在是推导）**：给定注册表 + 模态 + 模型，产出值。 -/
def view (reg : ModalityRegistry) (M : Model) (id : ModalityId) : Option (…)
```

## 三、两类模态

| 类 | `observed` | 例子 | 义务 |
|---|---|---|---|
| **观测模态** | `true` | 温度、价格、标签 | **必须全覆盖**（完备性） |
| **推导模态** | `false` | 变化率 `dT/dt`、频谱、极值事件、与其它量的相关、不确定性区间 | 按需注册；每个都自带 σ |

**⟹ 多模态产出的完整含义**：
> **预测一次，能同时给出「原数据的那些形态」和「从它推出来的那些形态」**——
> 且后者可以随建模需求不断增加。

---

## 四、一个具体例子

假设原数据只有一列：**温度时间序列**。

| 模态 | `observed` | 怎么来 |
|---|---|---|
| 温度 `T(t)` | ✅ | 原数据 |
| 变化率 `dT/dt` | ❌ | 从 `T` 推导 |
| 滑动均值 | ❌ | 推导 |
| 频谱 | ❌ | 推导 |
| 极值事件 | ❌ | 推导 |
| 未来 24h 轨迹 | ❌ | **模型预测** |
| 预测区间 | ❌ | 由 σ 推导 |

**⟹ 一条温度序列，输出可以是 6–7 个模态。**

## 五、必须一起承接的代价

### 代价 1 · 模态可无限膨胀

「能推导出来的」在数学上是**无界**的：任意函数复合都能算一个「模态」。
⟹ **必须有「什么算有意义模态」的判据**，否则输出集不可控、也没法验收。

### 代价 2 · 每个模态都要有自己的 σ

裁决 K 要求「误差 ≈ σ」，多模态意味着**σ 是多维的**。
推导模态的 σ 不是原始噪声——它由**推导链传播**得来（如 `dT/dt` 的 σ 与 `T` 的 σ 和采样间隔有关）。

⟹ 需要**模态间的 σ 传播规则**。这条目前完全没有。

### 代价 3 · `view` 的依赖类型签名较重

`Option (carrier of the modality)` 在 Lean 里需要依赖类型 + 查表，实现成本不低。

### 代价 4 · 完备性只能逐模态验

「原数据的模态全覆盖」需要在建模时**先枚举原数据模态**，而这一步本身就是建模的一部分。
⟹ 完备性判据依赖「模态枚举的忠实性」。

## 七、未决尾巴

| # | 问题 | 不定的后果 |
|---|---|---|
| **1** | **「有意义的模态」判据**（防模态无限膨胀） | 输出集不可控，无法验收 |
