# D-013 · 模型是一个完整系统，不按模态拆分；模态只是导出轴

> **裁决日期**：2026-10-28
> **裁决人**：作者
> **裁决原话**：「现实是怎么样的模型就是怎么样的　是一个完整的系统　而不是拆分成几个模态　**那个是供于导出才需要拆分**」
> **修订**：[`D-009`](裁决D-009-可逆建模与多模态预测.md)、[`D-011`](裁决D-011-多模态含可推导模态.md) 中 `Model` 的结构
> **设计稿**：[`07-IR设计/README.md`](../07-IR设计/README.md)

## 一、修订了什么

我之前把模型写成按模态拆开的结构（**错**）：

```lean
-- ✗ 错：把系统按模态切开了
structure Model where
  modalities : List ModalityView      -- 每模态一个分量
  coupling   : Coupling               -- 跨模态耦合（还得另外造）
  noise      : ∀ m, NoiseScale
```

**本裁决改为**（模型是一体化的，模态只用于导出）：

```lean
/-- **模型 = 一个完整系统**。对应现实本身，**不按模态拆分**。 -/
structure Model where
  state     : WholeState          -- 系统的完整状态（一体化）
  mechanism : WholeMechanism      -- 机制 / 动力学（一体化）
  noise     : NoiseStructure      -- 噪声结构（一体化，不是每模态一个）

/-- **模态只是导出轴**：从完整模型投影出一个可看的视图。
    它不在模型里，在「导出」这一步。 -/
structure Modality where
  id      : ModalityId
  carrier : Type
  project : Model → carrier       -- ★ 投影，不是分量

/-- 导出：能导出多少取决于注册了多少投影（D-012）。 -/
def export (reg : List Modality) (M : Model) (scope : ExportScope)
    : List (ModalityId × Value)
```

---

## 二、为什么这个改法是对的

| 论点 | 说明 |
|---|---|
| **现实不是「几个模态的积」** | 现实是一个整体；把它写成 `List ModalityView` 等于**先验地**规定了它由几块拼成 |
| **耦合不该是独立组件** | 若模型是整体，「跨模态耦合」就是**内在的**，不需要另造一个 `Coupling` 字段 |
| **模态是观察方式，不是存在方式** | 「温度」与「温度的变化率」不是系统的两个零件，而是对同一个整体的两种投影 |
| **导出才需要拆** | 拆分的唯一理由是「给人看 / 给下游比」——那是 `export` 的事 |

**⟹ 模型负责「是什么」，导出负责「怎么看」。**

---

## 三、这条改动带来的三个连带简化

### 3.1 `Coupling` 字段消失

一体化模型里，跨模态的关系是**模型自身的推论**，不是需要单独建模的组件。
导出时如果需要「联合视图」，那是一个**联合投影**（`project : Model → carrier₁ × carrier₂`），不是模型的字段。

### 3.2 模型只有一个噪声结构

`noise : NoiseStructure` 是**整体的**，不是每模态一个。

**但这不等于「只有一个标量 σ」**——模态的 σ 是**投影诱导**出来的：

```
模型有一个噪声结构 N
     │
     │ 导出模态 m（project_m : Model → carrier_m）
     ▼
该模态的噪声尺度  σ_m := induce(N, project_m)
```

**⟹ 这就是我之前标记「缺失」的「模态间 σ 传播」的自然位置。**

它不再是「每模态独立定 σ」，而是「**一个 N，多个投影，σ 由投影诱导**」。
例如 `dT/dt` 的 σ 由 `T` 的噪声结构 + 求导投影共同决定——这在数学上就说得通了。

### 3.3 可呈现（D-010）更自然

`Model` 不含原始数据，也不含各模态视图；只含一体化系统。
`view` 就是 `project`——**投影**，不是「还原」。

---

## 四、必须一起承接的代价

### 代价 1 · 「完整系统」怎么定义

`WholeState` / `WholeMechanism` / `NoiseStructure` 三个类型都未定义。
这是本裁决最大的空白：**「一体化」不是说没有结构，而是说结构**不按导出轴**切。**
⟹ 它们的内部结构仍需设计，只是不按模态分。

### 代价 2 · 投影的完整性义务仍在

D-011 的「观测模态必须全覆盖」变成：**原数据出现的每个模态，都必须有一个可执行的 `project`**。
这仍需逐模态验。

### 代价 3 · σ 诱导规则未定

`induce : NoiseStructure → (Model → carrier) → NoiseScale` 是目前**完全空白**的函数。
没有它，裁决 K 在多模态下就无法执行。

## 五、对既有裁决的影响

| 裁决 | 变化 |
|---|---|
| D-009「`Model` 含 modalities / coupling」 | ⚠️ **撤销**该结构 |
| D-009「多模态产出」 | ✅ 保留，但改为「导出时投影」 |
| D-010「可呈现 / `view`」 | ✅ 保留，`view` = `project` |
| D-011「模态开放」 | ✅ 保留，模态 = 可注册的投影 |
| D-012「能导出就导出」 | ✅ 保留，边界 = 注册了多少 `project` |
| **σ 传播**（原为缺口） | ✅ **有了位置**：`σ_m := induce(N, project_m)` |

## 六、未决尾巴

| # | 问题 | 不定的后果 |
|---|---|---|
| **1** | **`WholeState` / `WholeMechanism` / `NoiseStructure` 的结构** | 模型无法定义 |
| **2** | **`induce`：噪声结构 + 投影 → 模态 σ** | 多模态下裁决 K 无法执行 |
| **3** | 联合投影（多模态联合视图）的表示 | 「完整模型导出」缺一块 |
| **4** | 一体化模型怎么与 `X = Model` 对齐（状态空间元素是 Model） | 与 D-009 的 `X = Model` 需对齐 |
| 5 | 投影的完备性判据（观测模态全覆盖怎么验） | 可能漏模态 |
