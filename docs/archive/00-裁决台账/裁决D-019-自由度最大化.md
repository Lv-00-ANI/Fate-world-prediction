# D-019 · 自由度最大化：一切可参数化的都参数化，不写死

> **裁决日期**：2026-10-29
> **裁决人**：作者
> **裁决原话**：「可以然后我想所有东西尽量都别写死自由度最大化」
> **地位**：**元设计原则**，与 D-015（细节下放实现期）并列，共同约束全部实现

---

## 一、裁决内容

| # | 原则 |
|---|---|
| **1** | **不写死任何可参数化的东西**：载体类型、域、度量、噪声、时间、模态、选择器、σ 来源，一律参数化 |
| **2** | **每个抽象必须有至少一个具体实例**，否则是空谈 |
| **3** | **抽象层只放签名与结构，定理放实例层或泛化层** |
| **4** | **参数化不得引入公理**：参数是**假设**（typeclass / 结构体字段），不是公理 |
| **5** | 与 D-015 的关系：D-015 管「细节何时定」，D-019 管「定了之后长什么样」 |

---

## 二、落到具体的对照表

| 维度 | 不写死的做法 | 默认实例 |
|---|---|---|
| **语义值域** | 参数化有序域 `K` | `ℚ` |
| **数据字面量** | 参数化 `L`（`Data L`） | `ℚ` |
| 恒等/名称 | `OpId`/`PredId`/`EntityId`/`DataId` = `String` | 不变 |
| 状态载体 | 参数 `X` | `Model` |
| 时间 | 参数 `TimeIdx` | `ℕ` |
| 度量/距离 | 参数 `Dist` | ℝ 上的欧氏距离 |
| 噪声 | 参数 `NoiseModel` | 高斯 |
| σ 来源 | 参数 `SigmaSource` | `inf E_W`（定理 3.2） |
| 模态 | 开放注册表 | 按需注册 |
| 误差传播 | 参数 `Propagation` | 无（已证不存在） |
| 选择器 | 参数 `Selector` | 贪心 |
| 概率/测度 | 参数 `MeasureLike` 抽象 | 有限支撑 |

**⟹ 连 `ℚ` 都不写死在核里**：`Data L` / `Term L` 的 `L` 才是字面量类型，`ℚ` 只是一个实例。

---

## 三、过度参数化的防线（三条）

自由度最大化不等于无限抽象，必须守三条：

| 防线 | 内容 |
|---|---|
| **最小签名** | 抽象接口只暴露**必要**操作。如语法层只需要「构造子」，不需要「域运算」 |
| **必须有实例** | 每个抽象在 `Instances/` 下至少一个具体实例，否则不许合并 |
| **抽象层不放定理** | 定理一律在实例层或泛化层（`∀ K, …`），避免抽象层变成定理坟场 |

**判断标准**：**如果去掉这个参数，会不会损失一种合法的使用方式？**
会 → 参数化。不会 → 写死。

---

## 四、对 B1 的直接后果

原计划 `Core/Term.lean` / `Formula.lean` / `Data.lean` 三个文件。

**但 `Data.logic : Formula → Data` 迫使三者互相递归**（D-007），Lean 的 `mutual` 要求同文件。

⟹ **B1 改为单文件 `Core/Syntax.lean`**，内含：
- `Term (L)` / `Formula (L)` / `Data (L)` 三者 mutual
- `WellSorted`（mutual def）

**核内不出现 `ℚ`、不出现 `ℝ`、不出现 `Measure`。**

---

## 五、代价

| 代价 | 说明 |
|---|---|
| 签名变长 | 每个定义多几个类型参数 |
| 实例化样板 | 每个抽象要写实例 |
| 证明需要泛化 | `∀ K, …` 形式的定理比具体实例难证 |
| 门禁复杂度 | 需检查「每个抽象都有实例」 |
