# D-024 · 「时空可组合」的精确含义（依 DeepSeek 论文校正）

> **裁决日期**：2026-10-30
> **裁决人**：作者（指令：「你去网上搜」）

> Yifan Shi, Wei Zhang, Tianyi Cui（Peking University / DeepSeek-AI），arXiv:2608.25512，2026-08-26，92 页
> **修订**：[`D-023`](裁决D-023-背景信息答复一.md) §二 中对 D5 的**字面理解**

## 一、校正：我原来的理解是错的

D-023 §二 我把「时空可组合」落成「注册项带 `(时间区间, 空间区域)` 标签」。**这不是论文的意思。**

论文的两个维度是**软件组件的行为性质**，与「时间/空间标签」无关：

| 维度 | 论文原义 | 关键词 |
|---|---|---|
| **时间可组合**（temporal） | 组件被移除时，其副作用能被**完全撤销**——每次上下文变换都携带一个**逆**，逆由运行时持有 | revertible effects |
| **空间可组合**（spatial） | 组件**声明**它对其它组件的依赖（coeffect 规格）；上下文变化按该规格分类，**反应式**地驱动组件激活/停用 | reactive coeffects |
| **统一机制** | effect 上下文与 coeffect 上下文并成**单一 context 类型**，一切 effect/coeffect 都经它中介 → **context paradigm**；诱导出一个**观测等价**，使不同组件的副作用**交错而不互相干扰** | context paradigm |

**⟹ 「时空可组合」= 组件既可逆转（时间）、又能声明依赖并被反应式管理（空间）。**

---

## 二、映射到 FateV2

论文的 **component** 就是我们说的**插件**（模态 / 算子 / 注册项）。

| 论文 | FateV2 | 现状 |
|---|---|---|
| component | `Modality` / `OpId` 注册项 | 有注册表（D-006 §6.2、D-012），但**无 coeffect 规格、无逆** |
| effect（上下文变换） | 算子对 `Model` / 规则集的作用 | 四算子已有（`Core/Ops`），**都没有逆** |
| coeffect（依赖规格） | 模态依赖哪些内生变量；算子依赖哪些假设 | **完全缺失** |
| reactive activation | 运行时按依赖启用/停用插件 | **完全缺失** |
| observational equivalence | 「不同插件互不干扰」的可证形式 | **完全缺失** |
| context（统一中介） | 应有一个统一的「运行上下文」 | **完全缺失** |

**⟹ 我们现在只有一个「注册表」，离「上下文范式」还差三层：coeffect 规格、逆、统一上下文。**

## 三、一个必须解决的冲突：`support` 只增不减 vs 副作用可逆

| 我们的铁律 | 论文要求 | 冲突？ |
|---|---|---|
| 铁律 3：`support` **只增不减**（D-004） | 时间可组合：副作用**可完全撤销** | ⚠️ 表面冲突 |

**不冲突，但必须分层说清**：

| 概念 | 性质 | 理由 |
|---|---|---|
| **证据 / 来源**（`Support`） | **append-only（只增）** | 它是「这条结论靠过什么」的**审计记录**。撤销插件不该抹掉「曾经依赖过它」这件事 |
| **状态副作用**（插件对 `Model` 的改动） | **必须可逆** | 卸载插件后，模型必须回到装之前的样子 |

**⟹ 两者是不同层**：
- `Support` 记「
历史」，只增；
- 插件 effect 记「当前状态」，必须带逆。

**但有一个真问题**：若一个插件产生的**规则**（`Judgment`）被卸载，那些规则的 `support` 还在别处被引用怎么办？
——这正是论文「观测等价」要处理的事（卸载后系统行为与从未装过等价）。我们**目前没有这个机制**。

## 四、对 `Core/Ops` 的直接后果（**读原文后已修正**）

**原判断（错）**：四算子都没有逆，故都不满足时间可组合。

**修正依据**：论文 §3.1.1 明确——**撤销是单向的**：

> 「Undoing is one-sided: what an inverse is held to is `g ∘ f` and never `f ∘ g`.」

只要求**左逆** `g ∘ f = id`。在左逆意义下，**快照式撤销恒可行**：

```
正向 fwd : 保存旧值 γ，返回新值 γ′
左逆 inv : 忽略输入，返回 γ
⟹ inv (fwd γ) = γ   定义性成立
```

| 算子 | 左逆？ | 怎么实现 |
|---|---|---|
| `γ` 泛化 | ✅ | 快照旧 `Judgment` |
| `υ` 完善 | ✅ | 同上 |
| `∘` 组合 | ✅ | 快照两端 |
| `α` 抽象 | ✅ | 快照输入数据（若允许保留） |

**⟹ 结论改为**：四算子**都**可满足时间可组合；代价只是「运行时要持有旧状态」——
这正是论文让上下文**自带累积器**（`∂Γ = Γ × (Γ→Γ)`）的原因。

剩下的不是**机制**问题，而是**语义**问题：

| 问题 | 论文怎么处理 | 我们 |
|---|---|---|
| 撤销一条已推导的规则，认知上成立吗？ | 不问（软件语境） | 知识是累积的 → 默认不撤 |
| 撤销时引用过它的下游怎么办？ | **观测等价**（§3.3.2） | ❌ 未实现 |

**⟹ 落到 FateV2 的处置**：

- **机制上允许**可逆（`Meta/Context` 的 `Step` 已实现，四条定理零公理）
- **语义上默认不撤销规则**（保 D-004 铁律 3）
- **只在「插件 / 模态」这类纯投影上启用撤销**（投影无副作用，天然可逆）

**⟹ 这不是照抄论文，是划定它适用的边界。**

## 五、落地要求（可执行）

### 5.1 注册项升级为「组件」

```lean
/-- 组件 = 插件。带 coeffect 规格与（可选的）逆。 -/
structure Component (Ctx : Type u) where
  id        : ComponentId
  /-- 空间维：依赖规格——上下文满足它才激活 -/
  coeffect  : Ctx → Prop
  /-- 时间维：副作用变换 -/
  effect    : Ctx → Ctx
  /-- 时间维：逆变换（无副作用组件为 none） -/
  inverse   : Option (Ctx → Ctx)
```

### 5.2 两条可证性质（对应论文的 metatheory）

| 性质 | 形式 | 可否现在做 |
|---|---|---|
| **时间可组合** | `inverse = some g → g (effect c) = c` | ✅ 可做（纯函数版） |
| **空间可组合** | `coeffect c → 组件激活；¬coeffect c → 停用` | ✅ 可做（判据版） |
| **观测等价** | 装卸一组组件后，`Ctx` 的观测值不变 | ⏳ 需要「观测」的定义 |

### 5.3 模态天然满足时间可组合

`Modality.project : Model → carrier` 是**纯投影**（无 effect）→ `inverse = none`，可自由装卸。
**⟹ 模态注册表可以立刻按论文标准做，不需要改算子。**

## 六、边界与不确定

| # | 项 |
|---|---|
| 1 | 我只拿到**摘要**（PDF 92 页，抓取受限）。上述映射基于摘要，**未见正文的形式化细节**（尤其 coeffect 规格的具体语法、观测等价的定义） |
| 2 | 论文的实现 **Cordis** 是 TypeScript 生态，与 Lean 的类型论不同；「运行时持有逆」在 Lean 里只能靠**数据化**（把逆存进结构体），不能靠语言机制 |
| 3 | 论文处理的是**同层组件交错**；我们的分层是**纵向依赖**，两者正交，不能直接套 |
