> **严重度：最高。这条决定主线依赖方向、第 3/5 章接口、全部 `Caus*` 模块族的地位。**

## 分歧点

因果层（SCM 结构因果模型）在所有设计文档中究竟是——

- **说法甲**：规则的**上游**（`SCM → 规则` 依赖边成立，"因果优先"是第一原则）

三种说法在 18 份文档里同时存在，且**互相宣布对方作废**。

## 冲突的精确形态

**这不是简单的"甲 vs 乙"，而是三方互相矛盾：**

```
裁决 A（最早）       ── 因果降旁路、废止 SCM→规则
     │
     ├─→ 裁决 L（后）  ── 整层翻回：恢复 SCM→规则、因果可作主线来源之一
     │
     └─→ 第 380 轮    ── 因果不是旁路（但没说 SCM→规则 是否恢复）
                          │
                          └─→ 作废声明只在本文件内生效（"本文件中"）
                              ⟹ 787 / 1050 / 1329L82 三处仍按旁路写
```

**三个未解的问题**：
1. 第 380 轮的"因果不是旁路"，与裁决 L 的"因果可作主线来源之一"，是**同一件事还是两件事**？（两者方向一致，但表述不同）
2. 作废声明写的是"**本文件中**一切……作废"——**这个作废的效力范围是全项目，还是仅限该文件？**
3. `SCM → 规则` 这条依赖边，**到底恢复了没有**？（裁决 L 说恢复，第 380 轮没说）

## 候选处置

1. **以第 380 轮为准**（因果不是旁路），并显式补充：`SCM → 规则` 边是否恢复。
2. **以裁决 L 为准**（因果可作主线来源之一），并把第 380 轮的"因果不是旁路"解释为对裁决 L 的确认。
3. **以说法丙/戊为准**（因果是主干的一部分 / 闭环一环），把 A、L 都降为历史。
4. **先定义"作废声明的效力范围"再定**——若"本文件中"是文件级效力，需要逐文件补标注；若应是全项目级，则 787/1050/1329 三处必须改。

## ✅ 已终结（2026-10-28）—— 由 `裁决 D-014` 关闭

**终结理由**：`D-014` 裁决「**模型 = SCM**」，即整个预测系统的模型**本身就是因果结构** `⟨V, U, F, P_U⟩`。

| 原争点 | 终结后的情形 |
|---|---|
| 因果是「旁路」还是「主干的一部分」 | **问题消失**——因果不在「要不要接入」的层面，它**就是模型的定义** |
| `SCM → 规则` 这条边是否恢复 | 不再需要这条边：SCM 是模型，规则是从模型抽出的判断 |
