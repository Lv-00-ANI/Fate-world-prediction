### 1. F3-14 · 规则载体 —— ✅ **已裁决（2026-10-28）**

> **裁决原话**：「裁决1 应该是基于 cic 和 lean 一样的那三条公理的 ir」
>
> **裁决结果**：规则主载体 = **CIC 层面的 IR（`RuleTerm`）**，约束到 `propext` / `Classical.choice` / `Quot.sound` 三条公理。
> 完整裁决记录见 [`00-裁决台账/裁决D-002-规则载体定为IR.md`](../00-裁决台账/裁决D-002-规则载体定为IR.md)。

**这个裁决与已有实现完全吻合** —— `Fate/RuleSyntax.lean` 模块头逐字写着：

> * `RuleTerm` 是 Lean 的 **`inductive` 类型** ⟹ 本身就在 CIC 里；
> * `eval` / `holds` / `toLawRuleWith` 都是**普通 `def`** ⟹ 每条等式定理只用 `rfl`（不引新公理、不用 `sorry`）；
> * 因此「IR 嵌入 Lean」不是翻译，而是**同一个类型论内的构造**。

**⚠ 但要承接三个代价**（文件自己声明的，不是我加的）：

1. **IR 是语法层，不是语义层** —— 必须经 `toLawRuleWith` 解释到 `LawRule`，所以 V5 与 V3 是**两层叠加**，不是二选一。
2. **`interp : Measure Y → Env` 未构造** —— 文件明写「这是『桥的接口』，不是桥的实现」。
3. **IR 第一版无概率、无微分、无积分、无归纳迭代** —— 表达不了概率规则、SDE、FCA 蕴含。

**⟹ 「规则→预测」的链条从一段变两段**，且两段都不通：

```
RuleTerm ──(interp，未定)──▶ LawRule ──(单点档提取)──▶ Pred
```

**剩余待确认的三件事**：

- [ ] `interp` 是否立项为必做？（不立项则 IR 永远停在语法层）
- [ ] IR 是否扩到能表达概率/微分/积分？（不扩则概率规则、SDE、FCA 蕴含进不了 IR）
- [ ] 四算子是否在 IR 层重做？（现 `RuleSyntaxOps` 自陈「与语义层无同态映射」）
