# 环节接口约定

> **为什么需要这份文件**
> 「把链拆成最小环节」之后，你要能自己拼。拼接的前提是**类型对得上**：
> 环节 A 输出「规则集」，环节 B 要的是「转移核」——那它们就接不上，中间缺一个转换器。
>
> 所以本文先定死一套**数据类型词汇表**。所有环节的输入/输出都必须用这套词汇标注。
> 这样「能不能拼」就变成一个机械问题：`A.输出 == B.输入` 就能拼，否则不能。

---

## 一、数据类型词汇表（14 个）

| ID | 类型名 | 数学定义 | 典型来源 | 典型去向 |
|---|---|---|---|---|
| **T1** | `原始数据` | 观测序列 `{y_t}_{t∈T}`，或属性表 `(对象×属性)`，或 csv | 外部输入 | T4、T2 |
| **T2** | `状态空间` | 二元组 `(X, τ, Σ)`：集合 + 拓扑 + σ-代数 | Basic / ObservationUnified | T3、T8、T9 |
| **T3** | `轨迹` | 序列 `{x_t}_{t∈T}`，`x_t ∈ X` | T51Trajectory | T4、T9 |
| **T4** | `实例集` | `E`，每个实例是一组属性取值 | 从 T1 抽属性 | T5、T7 |
| **T5** | `形式背景` | `𝔹 = (G, M, I)`，`I ⊆ G×M` 二值关系 | 从 T4 编码 | T6 |
| **T6** | `概念格` | `𝔅(𝔹) = {(A,B) : A' = B, B' = A}`，Galois 不动点集 | FCA | T7 |
| **T7** | `规则集` | `R`，元素是条件分布核 `R : X → C → Measure Y` 或蕴含规则 `A ⇒ B` | F3/F4 族 | T8、T9 |
| **T8** | `转移核` | `K : X → Measure X`（马尔可夫核） | 规则组合 `∘` / `pow` | T9 |
| **T9** | `预测分布` | `φ(x_t) = P(x_{t+1} \mid x_t)`，即 `X → Measure X` | 预测层 | T10、T11 |
| **T10** | `误差剖面` | `err : ℝ → ℝ` 或 `γ ↦ ε(γ)`；含 `ErrProfile` / `IsFitBoundary` | F7 族 | T9、T12 |
| **T11** | `场景树` | `Scenario` / `ScenarioTree`：多条分支 + 每支概率 | WorldScenario | T12 |
| **T12** | `干预方案` | `a ∈ A`，或 `Policy : State → Action` | Selector / Policy | 外部输出 |
| **T13** | `参数` | `θ ∈ Θ`（命），或 `(u_t, ε_t)`（运） | 估计 / 领域给定 | T8、T9 |
| **T14** | `因果图` | DAG / CPDAG / MEC，`G = (V, E)` | 因果发现 / 先验 | T7、T9 |
| **T15** | `单步机制` | `f : X × U × E × Θ × A → X`（离散单步转移函数，**不是轨迹**） | F2-01 | T8、T3 |
| **T16** | `路径测度` | 路径空间 `(X^T, Σ)` 上的概率测度 `P` | F2-06/08 | T3、T9 |
| **T17** | `可预测性指标` | `λ_max`（Lyapunov 指数）/ `t_pred`（可预测时域） | F2-18/19 | 外部输出 |

> **⚠ T11 更正**（F6 子代理实测）：`Scenario` 结构体**没有概率字段**，`ScenarioTree` 是 `Set (Scenario)` 而非真树。
> 原描述「多条分支 + 每支概率」与实现不符，已按实测改为「多条分支（无概率权重）」。

> **辅助类型**（不是数据流节点，是约束）：
> - **C-假设**：一条未证前提（A1–A34）
> - **C-判据**：验收/入域判据
> - **C-开关**：影响某环节是否接入的裁决（如「因果是否入主干」）

## 二、环节的标注格式

每个环节必须标成：

```
F<N>-<NN>  名字
  输入: T<a>              （可以多个：T1 + T13）
  输出: T<b>
  数学核心: <类型签名或方程>
  状态: 已实现 / 部分 / 仅文档 / 被推翻 / 缺失
  变体: <同一 I/O 下的互斥实现>
```

**判据**：如果两个环节的 `输出` 与 `输入` 类型相同，它们**可以直接拼**；如果不同，中间必须有转换环节。

## 四、装配规则

**一条完整项目链** = 从 `T1 原始数据` 出发，经过若干环节，到达 `T12 干预方案` 或 `T9 预测分布` 的一条**类型相容路径**。

规则：
1. 起点必须是 `T1`（原始数据）——否则不是「从数据出发」的系统
2. 终点可以是 `T9`（预测）、`T12`（干预）、或 `T11`（场景树）
3. 相邻环节的类型必须相等（`前.输出 == 后.输入`）
4. 允许跳过环节，但跳过的那段必须标「**缺失**」——那正是断点
5. 同一环节的**不同变体**互斥：一条链里只能选一个变体

---

## 五、怎么用这份约定拼链

```
1. 从候选池里挑一个 T1 的产出环节（如 F1-01 观测数据接入）
2. 看它输出什么类型（T1 或 T3）
3. 在池子里找输入类型 == 它的输出的环节
4. 重复，直到到达 T9 / T12
5. 如果找不到匹配的环节 → 这里就是断点，记录下来
```

拼完之后，你得到的就是一条完整链：**每一环都有明确的输入输出、每一环都有实现状态与证据**。
