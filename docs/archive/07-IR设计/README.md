# IR 设计稿

> **一句话**
> 底座是 CIC + 三条公理；底座之上**全是规则**；规则的单位是**条件定理**（不是项）；
> 条件定理携带**来源**（靠哪些未证前件、靠哪批数据）；规则在运行时**带着数据长出来**；
> 变换（γ/∘/υ）本身也是规则，靠**分层反射**自洽。

**依据裁决**：[D-002](../00-裁决台账/裁决D-002-规则载体定为IR.md)、[D-003](../00-裁决台账/裁决D-003-IR完备性要求.md)、本稿讨论结论。

## 一、总体分层

```
            真实世界
               │
               ▼  ★ 数学建模层（D-007/D-008/D-014 · IR 之外，产出 IR 的输入）
               │    · 数据构造（数学语言，无"原始数据"层）
               │    · 定 SCM：V / U / F / 图
               │    · 外生律 P_U（= 噪声结构）→ σ_model 由推前诱导
               │    · 观测模型 h, η + A14 分支（无损 / 估计，须显式选一）
               │    · 建模假设（含构造忠实性）· 脏的建模
               ▼
┌─────────────────────────────────────────────────────────┐
│  J₂ : Type 4   关于 J₁ 的定理（目前不需要，留位）          │
├─────────────────────────────────────────────────────────┤

│  J₀ : Type 1   条件定理（= 规则）                         │

├─────────────────────────────────────────────────────────┤

│    → 提供 ℝ、Measure、拓扑                                │
│    → 用它的定理：support ⊇ {那三条}，status = conditional  │
```

### 十二条铁律

| # | 铁律 | 含义 |
|---|---|---|
| **1** | **底座之上全是规则** | 底座 = **纯 CIC**；三条公理降为**假设**（D-016）。J₀ 及以上**全部**是条件定理，不存在非规则成分 |
| **2** | **层间只能向上引用** | `Jₙ` 可以引用 `J_{n-1}` 的对象，**不能**引用自己。这保证 predicative，避开 Girard 悖论 |
| **3** | **来源不可丢弃** | 任何判断都必须携带它的 support。组合/变换**只能增加或保持**来源，不能假装来源不存在 |
| **4** | **数据必须数学构造** | 从链条起点开始，所有数据都必须用数学语言构造（D-007）。不存在「原始数据」这一层 |
| **5** | **误差以 σ 为判据** | 合格标准不是「越小越好」，而是**误差 ≈ 噪声尺度 σ**（裁决 K）。σ 由建模层产出 |
| **6** | **建模可呈现** | `Model` 不保留原始数据；`view` 能把结果产出为与原数据同类型的可看值（D-010） |
| **7** | **状态即模型** | 状态空间 `X` 的元素是 `Model`，不是标量向量（D-009） |
| **7b** | **模型是一体化完整系统** | `Model` **不按模态拆分**，只有 `state`/`mechanism`/`noise` 三块整体；模态是**导出投影**（D-013） |
| **8** | **模态是开放的** | 多模态 = 原数据模态 ∪ **模型可推导模态**；`view` 是**推导器**不是渲染器；观测模态必须全覆盖（D-011） |
| **9** | **能导出就导出** | 不设「有意义」判据；**边界 = 注册表**（实现多少 `project` 就导出多少）；可用 `scope` 限定范围；受限导出须标记（D-012） |
| **10** | **模型 = SCM** | 模型按**因果结构**组织 `⟨V,U,F,P_U⟩`；`state`=内生赋值、`mechanism`=结构方程、`noise`=外生律（D-014） |
| **11** | **账实相符** | `#print axioms` 必须**等于** `support.assumptions`——用了什么就登记什么（D-016） |
| **12** | **核内不用 `Quot`** | Lean 4 无 HIT，`Quot.sound` 是公理 ⟹ 商改用**不变谓词**；`ℝ`/`Measure` 归经典外壳（D-017） |

> **铁律 1 的精确表述**：`Term`/`Formula` 是规则的**语法材料**，不是「第二类公民」；
> 语义域（实数、测度）是规则**指向的靶子**，在 IR 之外，不受此限。

### 三层损失全部显式，全部用裁决 K 判（D-010）

| 阶段 | 有损？ | 损失名 | 判据 |
|---|---|---|---|
| 建模层 `construct` | ✅ 有损（**可测**） | **建模误差 `ε_model`** | ≈ σ |
| 规则层 `α` 抽象 | ✅ 有损 | 抽象损失 | ≈ σ |
| 预测层 | ✅ 可能有损 | 预测损失 | ≈ σ |
| 呈现层 `view` | ❌ 无额外损失 | —— | —— |

**⟹ 三层损失全部显式报数，不允许「假装无损」。**
D-009 曾想靠「可逆」把建模损失设为 0（免检），D-010 改为**必须报出来并受检**——更严，也更诚实。

### 误差判据（裁决 K，全链强制）

| 情形 | 判定 |
|---|---|
| 误差**大到影响结论** | ❌ 不合格 |
| 误差**小到开始拟合噪声** | ❌ 不合格（过拟合） |
| 误差**恰好等于信号/噪声分界尺度 σ** | ✅ **合格** |

> 原话：「误差必须小到不影响　就是刚好拟合和过拟合的边界」——`作者裁决K-误差准则.md:10`
> **适用范围**：全部误差相关项（编码误差、误差界、分辨率），**强制**。
> **前提**：σ 由数学建模层产出；σ 给不出时，必须显式写「σ 不可识别」，不得随便填数。

<a name="二类型"></a>
## 二、数据类型定义

### 2.1 数据（**必须用数学语言构造**）

> **铁律 4（D-007）**：从链条起点开始，**所有数据都必须用数学语言构造出来**。
> 不存在「原始数据」这一层——只有「构造好的数学对象」。原始字节只进档案做溯源。

```lean
abbrev DataId   := String   -- 已构造的数据声明的名字
abbrev EntityId := String   -- 实体 / 类别的标识

mutual
  inductive Term : Type
    | lit   (d : Data)
    | var   (n : ℕ)
    | add   (a b : Term)
    | mul   (a b : Term)
    | neg   (a : Term)
    | ext   (op : OpId) (args : List Term)

  inductive Formula : Type
    | eq  (a b : Term)
    | le  (a b : Term)
    | lt  (a b : Term)
    | and (a b : Formula)
    | or  (a b : Formula)
    | not (a : Formula)
    | true | false
    | all (body : Formula)          -- ∀ x₀
    | ex  (body : Formula)          -- ∃ x₀
    | ext (pred : PredId) (args : List Term)

  inductive Data : Type
    | rat   (q : ℚ)                 -- 精确有理数
    | vec   (xs : List Data)        -- 向量 / 序列
    | tup   (xs : List Data)        -- 元组
    | ent   (id : EntityId)         -- 实体 / 类别引用
    | logic (f : Formula)           -- ★ 复杂逻辑结构直接当数据嵌入
    | ref   (id : DataId)           -- 指向「已构造的数据声明」
end
```

**三个类型互相递归是合法的**：`Data.logic : Formula → Data` 与 `Term.lit : Data → Term` 都只把目标作为**参数**，满足严格正性。Lean 自己的 `Expr` 就是这样互相递归的。

**三层使用策略（作用在「已构造的数据」之上）**：

| 层 | 条件 | 处理 | support 影响 |
|---|---|---|---|
| **① 消融**（首选） | 能抽出等价公式，且**消融后命题含义不变** | 转具体定理或经验假设；数据留档 | 具体定理 **support = ∅** |
| **② 嵌入** | 消融会**改变命题含义**（规则本身就在说「这个」） | 用 `rat`/`vec`/`tup`/`ent`/`logic` 写进定理；**规模大也接受** | 不增加（是语法） |
| **③ 引用** | 不可消融，且构造产物本身很大 | `ref DataId`，指向已构造的声明 | 不增加，但引入追溯义务 |

> **判据**：**消融掉之后，这条规则还是不是原来那条？** 是 → 消融。不是 → 嵌入或引用。

**典型情形**：

| 规则 | 属于哪层 |
|---|---|
| 「这类实例满足 P」 | ① 消融（`all` 量化表达） |
| 「A 与 B 同属性」（A、B 具体个体） | ② 嵌入（`ent "A"`） |
| 「A 与 B 满足『∀x∈A, ∃y∈B, R(x,y)』」 | ② 嵌入（`logic` 装那个量词式）★ |
| 「取 x = 3/4 时 f(x) = 0」 | ② 嵌入（`rat 3/4`） |
| 「在本批构造 D 上误差 < 0.05」 | ③ 引用（`ref "D-…"`） |

### 2.2 项与公式（已在 §2.1 的 mutual 块中定义）

`Term` 与 `Formula` 与 `Data` 三者互相递归，见 §2.1。

> **为什么用 de Bruijn + 绑定在语法里**：`∀`/`∃`/`∫`/`d/dt` 都需要绑定变量。
> 用 de Bruijn 索引则**环境只需装值**，无需装函数；绑定通过 `subst` 处理。

### 2.3 语义值域：多类（因 `Data.logic` 而必须）

```lean
/-- 项的值不再只有实数——因为 `lit (.logic f)` 是个公式，不是数。 -/
inductive Value : Type
  | real  (x : ℝ)
  | prop  (p : Prop)
  | ent   (id : EntityId)
  | logic (f : Formula)

/-- 类正确性：排除无意义组合（如 `add (lit (.logic f)) (lit (.rat 1))`）。 -/
def WellSorted : Term → Prop
```

**⟹ 这是 D-007 的直接代价**：IR 从「单类」变成「无类型语法 + 类正确性谓词」。

### 2.4 来源与状态

```lean
/-- 假设标识（对应项目里的 A1–A34 之类） -/
abbrev AssumptionId := String

/-- **来源**：这条判断靠哪些**未证前件**成立。
    ⚠ 不含数据——数据**不进入定理**（见 §5 消融）。 -/
structure Support where
  assumptions : Finset AssumptionId   -- 未证前件
  deriving DecidableEq

/-- **假设账本**：未证前件的本体。
    数据只在这里以「证据」身份出现，不在定理里。 -/
structure Assumption where
  id        : AssumptionId
  statement : Formula        -- 形式化后的内容
  evidence  : List DataId    -- 支持它的数据批次（指向 §5 档案）
  status    : Status

/-- 判断的状态。四档，与理论的三类陈述判据对齐并细化。 -/
inductive Status : Type
  | proven       -- 框架内已证（无未证前件）
  | conditional  -- 条件定理（前件未证，但推导链完整）
  | empirical    -- 经验陈述（无法证明，只能登记）
  | refuted      -- 已被反驳
```

### 2.5 判断（= 规则）★

```lean
/-- **条件定理 = 规则**。这是 IR 的基本单位。 -/
structure Judgment where
  hyp     : Formula     -- 前件（可为 true）
  concl   : Formula     -- 结论
  support : Support     -- 来源（铁律 3）
  status  : Status      -- 状态
```

### 2.6 反射层（J₁）

```lean
/-- 把 J₀ 的判断**编码**成项，让高层公式可以谈论它。 -/
def quoteTerm    : Term → Term := id          -- 项自引用（同层）
def quoteFormula : Formula → Term             -- 公式 → 项（构造码）
def quoteJudgment : Judgment → Term           -- 判断 → 项（构造码）

/-- **J₁ 的判断**：它的公式里可以出现 `quoteJudgment j`，
    于是能说「对任意判断 j，若 … 则 …」。 -/
structure MetaJudgment where
  hyp   : Formula     -- 可含 quote*
  concl : Formula
  support : Support
  status : Status
```

**反射的用途**（这正是你选「乙」的理由）：

| 用途 | 形式 |
|---|---|
| 说「γ 保来源」 | `MetaJudgment : ∀ j, support (γ j) ⊇ support j` |
| 说「∘ 的来源是并集」 | `MetaJudgment : ∀ j₁ j₂, support (j₂ ∘ j₁) = support j₁ ∪ support j₂` |
| 说「γ 放宽前件」 | `MetaJudgment : ∀ j, ⟦γ j⟧.hyp ⊇ ⟦j⟧.hyp` |

**⟹ 四算子的正确性本身是可证的**，这就是「变换本身是定理」。

<a name="三语义"></a>
## 三、语义

### 3.1 环境

```lean
/-- 变量环境：de Bruijn 索引 → 实数值。 -/
abbrev Env := ℕ → ℝ

/-- 扩展算子注册表（§6 的自拓展机制） -/
structure Registry where
  ops   : List (OpId × OpSig)
  preds : List (PredId × PredSig)
```

### 3.2 语义函数

```lean
/-- 项 → 实数 -/
def denoteTerm (R : Registry) : Term → Env → ℝ
  | .lit (.rat q), _ => (q : ℝ)
  | .var n,       e => e n
  | .add a b,     e => denoteTerm R a e + denoteTerm R b e
  | .mul a b,     e => denoteTerm R a e * denoteTerm R b e
  | .neg a,       e => - denoteTerm R a e
  | .ext op args, e => (R.lookup op).denot (args.map (denoteTerm R · |>.flip · e))

/-- 公式 → 命题 -/
def denoteFormula (R : Registry) : Formula → Env → Prop
  | .eq a b, e => denoteTerm R a e = denoteTerm R b e
  | .le a b, e => denoteTerm R a e ≤ denoteTerm R b e
  | ...
  | .all b,  e => ∀ x : ℝ, denoteFormula R b (extend e x)

/-- 判断 → 命题：「在任意环境下，前件成立则结论成立」 -/
def denoteJudgment (R : Registry) (j : Judgment) : Prop :=
  ∀ e, denoteFormula R j.hyp e → denoteFormula R j.concl e
```

### 3.3 语义域（IR 之外）

| 名称 | 内容 | 位置 |
|---|---|---|
| `denoteJudgment` | 判断的真值（`Prop`） | IR 的语义 |
| `LawRule` | 分布集合 | 既有代码，**保留为语义靶子** |

> **注意**：`LawRule` 不在 IR 内。它是 IR 指向的语义对象之一。
> 若要「规则 → 预测分布」，需一条从 `Judgment` 到 `LawRule` 的解释桥（§8）。

<a name="四算子"></a>
## 四、四算子与来源传播

**核心设计**：每个算子有**两张脸**——

1. **实现**：`J₀ → J₀` 的函数（可算）
2. **规格**：`J₁` 的判断（可证）

这就是「变换本身是定理」。

### 4.1 α 抽象

```lean
/-- α：从实例/数据抽出条件定理（**含消融**，见 §5） -/
def alpha : InstanceSet → Judgment × List Assumption
-- 规格（J₁）：α 不直接引用数据；它把数据消融成「具体定理」或「经验假设」
MetaJudgment : ∀ D, support (alpha D).1 ⊆ (alpha D).2.map (·.id).toFinset
```

| 项 | 值 |
|---|---|
| 前件 | 由数据生成的适用条件 |
| 结论 | 数据中观察到的规律 |
| support.assumptions | **消融后剩下的经验假设**（可形式化的部分已经变成具体定理，不占 support） |
| status | 若前件全可证 → `proven`；否则 `conditional`；不可证 → `empirical` |

**⟹ 「规则在运行时带着数据长出来」在这里落地：α 的产出**遗传自**数据，但**不携带**数据。**
数据的去向见 §5（消融 + 归档）。

### 4.2 γ 泛化

```lean
def gamma : Judgment → Judgment
```

| 项 | 变化 | 理由 |
|---|---|---|
| 前件 | **放宽**（⊇ 原前件） | 从局部到全局，适用面变宽 |
| 结论 | **变弱**（⊆ 原结论） | 代价 |
| support.assumptions | **只增不减** | 放宽前件不能凭空减少依赖 |
| status | 可升（若结论可证）或**降**（通常降为 conditional） | 泛化常使结论变弱、条件变多 |

### 4.3 ∘ 组合

```lean
def compose : Judgment → Judgment → Judgment
--  j₂ ∘ j₁：j₁ 的结论能推出 j₂ 的前件时，串成 j₁.hyp ⊢ j₂.concl
```

| 项 | 变化 |
|---|---|
| 前件 | `j₁.hyp`（上游前件） |
| 结论 | `j₂.concl`（下游结论） |
| **support** | **并集**：`supp(j₁) ∪ supp(j₂)` |
| status | `proven` 只在前者都 `proven` 时；否则取较弱 |

**这是「脏会传播」的形式化**：两条条件定理串起来，脏的还是脏的，且**脏只增不减**。

### 4.4 υ 完善

```lean
def upsilon : Judgment → Data → Judgment × List Assumption
```

| 项 | 变化 |
|---|---|
| 结论 | 用新数据修正 |
| support.assumptions | 新数据消融后新增/修改的经验假设（见 §5） |
| status | 可能升级（数据支持增强）或**降级**（数据反驳） |

### 4.5 来源传播的统一规则（J₁ 层可证）

| 算子 | support.assumptions | status |
|---|---|---|
| α | 消融后的经验假设（可形式化部分已转为具体定理，不占 support） | → `proven` / `conditional` / `empirical` |
| γ | 只增 | → 常降为 `conditional` |
| ∘ | **并** | 取较弱 |
| υ | 不变 | **+{D.id}** | 可升可降 |

**⟹ 铁律 3 的可执行形式：没有任何算子能减少 support。**
这条本身就是一个 `MetaJudgment`（J₁），可以证，也可以机检（扫一遍所有算子实现）。

<a name="五数据"></a>
## 五、数据：消融优先，嵌入与引用兜底

> **核心原则**：**能消融就消融；消融会改变命题含义时才嵌入或引用。**
>
> | 情形 | 处理 |
> |---|---|
> | 可形式化，且消融后命题含义不变 | **消融** → 具体定理（support = ∅）或经验假设；数据归档 |
> | 消融会改变含义，规模小 | **嵌入**（`rat` / `vec` / `tup` / `ent`） |
> | 消融会改变含义，规模大 | **引用**（`ref DataId`）+ 档案登记 + hash |
>
> **判据一句话**：**消融掉之后，这条规则还是不是原来那条？**
> 是 → 消融。不是 → 嵌入或引用。

### 5.0 为什么不能一律消融

有一条规则类型**消融掉就不再是它**：

> 「**A 与 B 同属性**」「**这类与那类满足关系 R**」「**在 D 上误差 < 0.05**」

这类规则的**指称对象本身就是内容**。把 A、B 消融成「某实例」，规则就从「关于这两个」变成了「关于所有」——**换了命题**。

⟹ 所以 `Data` 必须保留 `ent`（实体引用）与 `ref`（数据引用）两个构造子。

### 5.1 消融（dissolution）——首选路径

数据 `D` 到达后，α/υ 执行三步：

```
① 形式化：把 D 中「可形式化」的内容抽成公式 φ
        │
        ├── 若 φ 可在此框架内证明 ──▶ 产出**具体定理**（support = ∅）
        │                             D 归档，不进定理
        │
        └── 若 φ 不可证（真经验内容）──▶ 登记为**经验假设** a
                                      a.evidence := [D.id]
                                      定理只引用 a.id（不进 D）
```

**「可消融」= 数据的作用被完全吸收进形式化产物，此后定理不再需要数据本身。**

### 5.2 这解决了 support 无限增长

| 原来的问题 | 消融后的结果 |
|---|---|
| 每轮 α/υ 都把 `D.id` 加进 `support.data`，跑久必爆 | **`support` 里没有 data 字段**，只有 `assumptions` |
| —— | 可形式化的数据 → 变成具体定理，**support 为空，零增长** |
| —— | 不可形式化的数据 → 变成**少量、稳定**的经验假设（A1–A34 那一类） |
| —— | 数据本身在档案里，**不进定理** |

**⟹ 增长只发生在「经验假设」上，而那一类应当是少而稳的，不是每批数据加一条。**

### 5.3 嵌入与引用——兜底路径

**嵌入**（规模小，消融会改含义时）：

| 情形 | 形式 | example |
|---|---|---|
| 具体数值见证 | `lit (.rat 3/4)` | 「取 x=3/4 使 f(x)=0」 |
| 具体数值对 | `vec [.rat 3, .rat 5]` | 「x=3 与 y=5 满足 …」 |
| **具体个体** | `lit (.ent "A")` | 「**A 与 B 同属性**」 |
| **类别** | `lit (.ent "kind:person")` | 「**这类与那类**满足 R」 |

**引用**（规模大，不可消融）：

| 情形 | 形式 | 义务 |
|---|---|---|
| 规则直接引用一批数据 | `lit (.ref "D-2026-10-28-01")` | 必须进 `DataArchive`，有 hash、来源、caveat |

> **注意**：嵌入与引用**不增加 `support`**——它们是**语法的一部分**（规则本身就在说这个）。
> 但 `ref` 引入**可追溯性义务**：档案里必须有对应记录。

### 5.4 证据档案

```lean
/-- 数据档案：保留数据的全部出处，供复现与审计。
    定理不引用它，只有「经验假设」和「具体定理的证明记录」引用。 -/
structure DataArchive where
  id       : DataId
  source   : String      -- 文件 / 传感器 / 外部库
  hash     : String      -- 内容指纹
  size     : ℕ           -- 规模
  caveats  : List String -- 已知的脏（缺失、噪声、采样偏差）
  status   : Status      -- 默认 empirical
```

**义务**：凡被 `Assumption.evidence` 引用的 `DataId`，必须在档案里有记录且 hash 可校验。

### 5.5 不用 `native_decide`

**决定**：IR 不用 `native_decide` / `ofReduceBool`，保住三条公理。

**后果（必须接受）**：数值验证靠内核规约，**大数据会慢**。

**出口**：需要数值结论时，把结果作为**经验假设**登记，而不是当作定理。

> 若将来必须放开，那是**新增第 4 条信任**，须单独立项并经作者裁决。

<a name="六拓展"></a>
## 六、自我拓展

### 6.1 三个层次（对应 C1/C2/C3）

| 层 | 名称 | 机制 | 状态 |
|---|---|---|---|
| **C1** | 规则集自长 | `upsilon` 迭代：规则组合出新规则，**语言不变** | ✅ 已有骨架（`upsilonIter`），需接到 IR |
| **C2** | 语法可扩 | `ext op args` + 注册表：**加算子 = 注册一条语义，不改 `denote` 定义** | ⬜ 本稿设计 |
| **C3** | 自动发现缺口 | 系统检测「表达不了」并自动生成新算子 | 🔬 **待研究** |

### 6.2 C2 的机制（关键）

```lean
/-- 算子标识：可以是内置的，也可以是后加的 -/
inductive OpId : Type
  | arith (s : String)          -- 内置
  | user  (s : String)          -- 后加

/-- 算子签名 + 语义 -/
structure OpSig where
  arity : ℕ
  denot : List ℝ → ℝ

/-- 注册表是**数据**，不是类型定义 -/
structure Registry where
  ops : List (OpId × OpSig)
```

**⟹ 加一个新算子，只需往 `Registry` 里加一条**：

```lean
-- 例：加一个「平方」算子
def sq : OpSig := { arity := 1, denot := fun | [x] => x * x | _ => 0 }

def R₁ : Registry := { ops := R₀.ops ++ [(OpId.user "sq", sq)], preds := R₀.preds }
```

**`denote` 的定义一行不改。** 这就是「语法可扩」而不破坏下游。

### 6.3 「运行时」到什么程度

**必须说清**：Lean 里语法是**编译期**的。运行时能变的是**数据**（注册表、规则集）。

| 强度 | 含义 | 本稿 |
|---|---|---|
| **弱** | 运行时：规则集增长、注册表增长 | ✅ **本稿采用** |
| **强** | 运行时：语法本身变化（新的构造子改变 `denote` 的类型） | ❌ 需要 `Expr` 路线，丢类型保证 |

**「运行时规则变化」在本稿里 = 规则集与注册表增长**，不是类型定义变化。

<a name="七循环"></a>
## 七、运行时循环

```
        ┌──────────────────────────────────────────────┐
        │                                              │
        ▼                                              │
   R_t  （规则集：Judgment 的集合）                      │
        │                                              │
        │ ① 观测：拿到数据 D_t                          │
        ▼                                              │
     D_t ──▶ ② 消融（§5）：可形式化 → 具体定理（support=∅）
        │                    不可形式化 → 经验假设（evidence=[D_t]）
        │                    D_t 本身 ──▶ 归档
        ▼                                              │
      Φ_t  （新增的具体定理 + 经验假设）                  │
        │                                              │
        │ ③ 抽象：α 抽出条件定理                        │
        ▼                                              │
      J_t  （新 Judgment，support 只含经验假设 id）       │
        │                                              │
        │ ④ 变换：γ / ∘ / υ                             │
        ▼                                              │
   R_{t+1} = υ(∘(γ(R_t)), Φ_t)                          │
        │                                              │
        │ ⑤ 预测：解释到 Pred                           │
        ▼                                              │
     预测分布 ──▶ ⑥ 残差 ──▶ ⑦ 回写 ────────────────────┘
```

**关键**：数据在 ② 就被**消融**了，不进 `Judgment`。
所以 ⑦ 回写时，`support` **不会累积数据**——它只累积**经验假设**，而经验假设应当少而稳。

**⟹ 不需要「来源剪枝」这种补丁。增长问题在 ② 就消掉了。**

> **但有一条新的义务**：必须能说清「哪些经验假设是承重的」。
> 若某条经验假设不再被任何 `Judgment` 引用，它可以**退役**（移出支撑集，仍留档）。
> 这不是剪枝，是**引用计数式的自然淘汰**。

<a name="九验收"></a>
## 九、验收标准

设计「落地了」的判据——**每条都要能机检**：

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | `Term` / `Formula` 已拆开 | 两个 `inductive` 存在，且 `denoteTerm` / `denoteFormula` 类型不同 |
| 2 | `Judgment` 带 `support` + `status` | 结构体字段存在 |
| 3 | **没有算子能减少 support** | 扫 §4 四个算子的实现，逐条检查单调性（或证一条 `MetaJudgment`） |
| **3b** | **`support` 里没有数据字段** | 结构体定义里无 `data : Finset DataId`；只有 `assumptions` |
| **3c** | **消融判定留痕** | 每次消融必须有记录：数据 `D` → 产出了哪些具体定理 / 哪些经验假设 / 是否嵌入或引用 |
| **3d** | **每条经验假设都有证据或明确标「无证据」** | 交叉核对 `Assumption.evidence` vs `DataArchive` |
| 4 | 数值只以 `ℚ` 进入 | 扫 `Data` 构造子：`rat`/`vec`/`tup`/`ent`/`ref`，无 `Float`/`ℝ` 字面量 |
| **4b** | **每个 `ref` 与 `ent` 都能解析** | `ref` → `DataArchive` 有记录；`ent` → `EntityTable` 有记录 |
| 5 | 每个被引用的 `DataId` 都在档案且有 hash | 交叉核对 `Assumption.evidence` vs `DataArchive` |
| 6 | `denote` 不依赖 `native_decide` | 全文检索 `native_decide` / `ofReduceBool` = 0 |
| 7 | `#print axioms` 只有三条 | 对核心定理跑 `#print axioms` |
| 8 | 加一个算子不改 `denote` | 实测：只改 `Registry`，`denote` 源码 diff = 0 |
| 9 | 四算子各有 J₁ 规格 | 每个算子至少有 1 条 `MetaJudgment` |
| 10 | 反射可用 | 能写出「∀ j, support (γ j) ⊇ support j」并在 J₁ 里证 |
| **11** | **消融闭环** | 给一批数据，跑 α → 检查：(a) 产出了具体定理或经验假设；(b) 数据进了档案；(c) 没有任何 `Judgment` 直接引用该数据 |
