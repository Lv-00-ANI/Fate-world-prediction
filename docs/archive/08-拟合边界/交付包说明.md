## 一、阅读优先级

本交付包含**论文正文、形式化工程附录**、实现与核验工具。若受时间限制只能阅读其中一部分，建议按下表取舍。

### 1.1 两篇论文的关系

| 文件 | 结构 | 特点 |
|---|---|---|
| `paper/半启发式判据.docx` | 十四节、三个附录、二十三条参考文献 | **正文**。以「严格核 / 约定层 / 经验层」三层划分组织，第 12 节与 discrepancy principle、early stopping、AIC/BIC/交叉验证及形式化的统计学习理论逐一对话 |
| `paper/附录-形式化工程.docx` | 八节（A–H）、含 74 条定理对照 | **独立附录**，讲实现的工程结构：模块划分、形式化暴露的问题（量纲、类型别名、依赖结构）、两次由验证驱动的修正（紧界、Lipschitz 传递）、验证基础设施与可复现清单 |

两者共享同一实现：正文给出数学主张，附录给出「怎么做的、撞到了什么」。附录不是另一篇论文——它的每一条陈述都指向正文的某个定理或某段工程事实。

### 1.2 阅读优先级

以 `半启发式判据` 为准，按可支配时间取舍：

| 可支配时间 | 建议阅读范围 | 取舍理由 |

## 四、关于实验数据的说明

两篇论文都对「判据能否被实际满足」给出了可证伪的命题，其形式为

$$\frac{s}{\sigma}\ \le\ n\ \le\ B^{1/d}-1,$$

左端来自几何（格宽下界），右端来自组合（胞腔数紧界），二者都是定理（定理 10.3 与 10.7）。

**关于是否执行过实验，两篇论文的表述不同，须按各自版本理解：**

| 文件 | 表述 | 原因 |
|---|---|---|
| `paper/恰当拟合边界.docx` | **实验实际执行过**，但代码与原始数据因脱敏而未公开；论文不报告结果 | 该版本成稿较早，当时以「已执行、数据脱敏」处理 |
| `paper/半启发式判据.docx` | **列为后续工作**（§13 表中记为「待检验」），只给出命题、检验方案与三种可能结局的判读方式 | 该版本把实证定位为尚未完成的独立工作 |

两种表述不矛盾：实验确曾执行，其数据因涉及不宜公开的内部材料而全部删除，因此在正式论文中无法作为证据引用。

| 项目 | 状态 |
|---|---|
| 论文中的定理 | 全部经机器检验，可复现（见 `lib/`） |
| 论文 §11 的命题 | 曾在早期版本中检验；检验数据未随本包提供 |
| 现交付的表述 | 不以**真实系统**的实验数据作为论据 |
| 论文 §11.5 的实验 | **合成数据，已随包提供**：代码在 `experiments/`，产物在 `results/`，可一键重跑。它只检验界的收紧，不涉及真实系统的可满足性 |

读者对此应注意三点。

其一，论文的数学部分（第 3 至 10 节、第 12 节）不依赖任何实验数据，可独立核验。

其二，该命题是一个可证伪的断言，其真伪不因数据未公开而改变。

其三，若需独立验证，论文 §11 载有完整的实验设计，包括数据规模、扫描网格、记录项与判据。

将数据删除而不含糊其辞，优于提供一个来源无法核实的数据集。

> **`real_data.py` 需要联网**：它首次运行时从 UCI 机器学习库下载三个公开数据集（road3d / protein / beijing），缓存在 `data/`。数据集本身不随包提供，以免包体积过大；下载地址写在脚本顶部的 `LOADERS` 中，可自行核对。

**需要区分两类实验。**

其一，§11.5 是**合成数据**实验，用于核验定理 10.7 的界是否成立且更紧。它完全可复现，代码与产物均已随包提供，且**结论为正**：新界处处成立、比旧界紧两个数量级。

其二，§11.6 是**真实数据**实验，用于检验几何—组合双界是否刻画真实数据的可满足性。它有可复现代码（`experiments/real_data.py`，首次运行需联网下载公开数据集），且**结论为负**：真实数据的误差衰减指数为 $0.08$–$0.30$，远低于几何界隐含的 $1$，故从胞腔宽度到误差的 Lipschitz 传递在真实数据上失效。

两者都是本文的一部分：前者支持定理的实用价值，后者界定定理的适用边界。

## 五、生成方式与责任划分

**本交付包由人类与 AI 共同生成。**

人类负责研究方向的确定、核心数学对象的选定、关键判断的取舍，以及对 AI 输出的审核与否决，并承担全部结论的最终责任。具体而言，以下判断由人类作出：恰当拟合边界应以最小点而非上界来刻画；唯一性应当来自严格凸性；噪声尺度应被证明为由误差剖面决定，而非作为外部参数引入。

AI 在人类指导下执行具体工作，包括 Lean 代码的组织与重构、证明的编写与调试、论文草稿的撰写、文献检索，以及自动化核验工具的开发。

人类指导的痕迹可自工作记录中查见。以下三例为 AI 提出方案、经人类纠正后重做的记录。

| AI 的原始判断 | 人类的纠正 | 结果 |
|---|---|---|
| 「噪声尺度不能从系统内部推出」属不可形式化的元命题 | 要求重新检查该判断 | 由一条新定理推翻：噪声尺度恒等于误差剖面的下确界 |
| 以符号出现次数判断模块间的依赖关系 | 要求改为定位定义处并剥离注释后再判断 | 纠正三处误判，其中两处会导致编译失败 |
| 提议以脚本批量删除注释中的项目标识 | 要求先逐文件阅读内容再处理 | 避免误删数学论证。经核查，二百零八处标识分属一百九十二种不同句式，机械替换会产生病句 |

## 六、验证方法

### 6.1 构建 Lean 库

前置条件为 `elan`（Lean 版本管理器）与网络连接（首次需获取 Mathlib）。

```powershell
cd lib
lake exe cache get
lake build ProperFit
```

第一行获取 Mathlib 的预编译产物，建议执行，否则需数小时编译。第二行构建论文入口。

工具链为 `leanprover/lean4:v4.33.0-rc1`，见 `lib/lean-toolchain`。Mathlib 版本由 `lib/lakefile.toml` 中的 `rev` 字段锁定。

库为**单入口**。

| 入口 | 规模 | 用途 |
|---|---|---|
| `ProperFit` | **四十四模块、六百七十九条定理、一百八十二个定义** | 论文正文引用的全部内容 |

库中已不含任何与论文无关的模块：原先另有约九十八个来自另一条理论线的模块，已全部移除。现存的四十四个模块均为论文入口的构建所必需（其中二十一个被正文与附录直接引用，二十三个为传递依赖）。

### 6.2 核验论文与实现的一致性

```powershell
python tools/verify_paper_claims.py
```

该脚本自论文附录 B 提取全部定理名，逐一在库中核验，能够区分同名声明。

当前结果：引用七十一条，命中七十一条，缺失零条。

若某条论文陈述在附录 B 中找不到对应定理，即视为本文的缺陷。

### 6.3 检查计数与标记语法

```powershell
python tools/count_decls.py
python tools/check_md.py
```

第一条统计定理与定义的数量，第二条检查论文的 Markdown 语法。

计数脚本采用剥离注释的口径。若使用 `grep '^\s*def '` 统计，会把注释中的示例代码计为真实定义；实测会使定理数虚高四、定义数虚高十六。

## 七、已知边界

以下列出未完成与不可完成的事项。

| 序号 | 事项 | 性质 |
|---|---|---|
| 1 | 误差剖面的下确界是否等于统计学意义上的噪声尺度 | 经验命题，非数学命题 |
| 2 | 可满足性不等式是否成立 | 已经实验检验，数据未随包提供，见第四节 |
| 3 | 偏差项与方差项的具体解析形式 | 建模选择。本文仅要求二者可加且非负 |
| 4 | 满足强层全部前件的剖面能否边界不唯一 | 已知单调性不能排除（已证），一般情形未决 |
| 5 | 阈值与噪声尺度的数值标定 | 需 StudentT 分位数，Mathlib 未提供 |
| 6 | 真正的多值编码（pattern structure） | 未建模 |
| 7 | `le_err_of_isFitBoundary` 的定义投射状态 | 未闭合的工程债。原定义未改，该定理仍在库中 |
| 8 | 判据系数 $[1/2,2]$ 的来源 | 非数学命题。论文 §8.2 已声明其中一个系数可能不具判据意义 |
| 9 | 参考文献中二十二条未核实 | 详见 `paper/参考文献.docx` 末尾清单 |

第七项需读者特别注意。论文 §7 已给出不经过该分量的独立刻画（经 `IsMinOn` 中转），但原定义并未修改。若读者只查阅 `le_err_of_isFitBoundary`，所见仍为定义展开。
