# 理论-文档

> **对整个项目既往所有设计的提取与整理。**
> 本文件夹不产生新设计，不合并冲突，不裁决，不删原话。

---

## 这是什么

《命运》项目在过去一年里产出了大量文档：理论正文、证明路线、裁决记录、审计报告、轮次记录。
这些内容散布在 1,400 份 `.md` 里，**彼此之间大量重复、互相矛盾、有的已被后续裁决推翻但正文没改**。

本文件夹要做的事只有一件：

> **把每一处设计连同它的出处、原表述、当前状态、冲突对象，登记成一个可独立裁决的最小单元。**

它**不是**新理论，**不是**实现方案，**不是**进度报告。

---

## 它在整条链上的位置

```
理论-文档（本文件夹）  →  修正后的《命运》理论  →  按修正后理论重写代码
     ↑ 这里只管原料与问题清单          ↑ 不在本文件夹
```

**产出物是原料，不是成品。** 最终交付物见 `05-修正清单/`——一份"逐条改动指令表"，
作者把每行的「裁决结果」填完后，修正版理论就是机械回填的结果。

---

## 目录结构

```
理论-文档/
├── README.md              ← 本文件
├── _怎么做.md             ← 作业规程（必读）
├── _约束.md               ← 作者已表态的约束（不可擅改）
├── 00-裁决台账/            ← ⭐ 作者所有最终裁决的唯一存放处
│   ├── README.md          ← 裁决总表（一行一条）
│   ├── _模板.md           ← 新裁决照这个写
│   └── 裁决台账.csv        ← 机器可读
├── _扫描/                 ← 全部扫描脚本与原始输出（可复现）
│   ├── 精读输出规范.md
│   ├── 精读任务/          ← 19 批任务清单
│   ├── 精读结果/          ← 逐份读原文的产出
│   └── …
├── 01-裁决层/             ← 材料里的裁决原文与出处（不是你的裁决）
├── 02-理论层/             ← 按概念切的理论卡（按章分）
├── 03-冲突登记/           ← 概念级冲突，待作者裁决
├── 04-状态核对/           ← 文档 vs 产物的冲突（机器可定案，不装裁决）
├── 05-修正清单/           ← 主定理路线图（833 条主定理 + 依赖）
├── 06-项目链/             ← 预测系统的候选形态 + 240 个可拼装环节
├── 07-IR设计/             ← 规则语言 IR 的完整设计稿
├── 08-拟合边界/           ← σ 的来源与裁决 K 的精确数学形式（已机检）
└── 09-总设计/             ← ⭐ 整个预测系统/世界模型的总设计（唯一入口）
```

> **`00-裁决台账/` 与 `01-裁决层/` 的区别**：
> - `00-裁决台账/` = **你**拍板的决定（D-001、D-002…）
> - `01-裁决层/` = **材料里**原有的裁决原文（裁决 A/B/C…），是史料

---

## 三条纪律

1. **原表述必须逐字**。改写原话 = 换了结论。
2. **数字必须带口径**。任何"多少条/多少份/多少已实现"，后续必须能复现。
3. **冲突只能并列，不能合并**。同一概念的多个说法全部保留，等作者裁决。
