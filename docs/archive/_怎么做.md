# 怎么做 —— 《命运》理论提取与修正作业规程

> **本文件是作业手册，不是成果。**
> 它规定了「理论-文档」这个文件夹里每一份文档**如何产生、如何验收、如何被推翻**。
> 任何人（含 AI 代理）在本文件夹里产出内容，必须先读过本文。

---

## 〇、一句话

> **把素材夹里全部 1,400 份 `.md`（1,979 万字符），经四道筛子过滤后，
> 拆成「一个概念一张卡」的最小可裁决单元；
> 每张卡原话入档、状态标注、冲突归并、代码指认；
> 卡池产出一份「修正清单」；修正清单被作者裁决后回填，生成《命运》修正版理论。**

**链条是单向的**：

```
理论-文档（提取整理）  →  修正后的《命运》理论  →  按修正后理论重写代码
        ↑ 本文件夹管到这里为止                          ↑ 本文件夹不管
```

本文件夹**不产生新设计、不合并冲突、不裁决、不删原话**。它的唯一交付物是**原料**与**问题清单**。

---

## 一、为什么不能"读一遍然后写"

因为旧项目最大的失败模式是**「假转项」**：动作合规、仪式齐全，但对象是坏的、内容没变。它在文档层面的四种形态，本规程必须逐条堵死：

| 旧项目的病 | 本规程的堵法 |
|---|---|
| **前件恒真**（`∀ z ux, fX z ux = fX z ux`） | 每张卡必须有 ② 出处（文件+行号），指不到行号的不许立卡 |
| **前件被丢弃**（`have _hd_witness := hd`） | 每张卡的 ③ 必须是**逐字引用**，且必须带行号；改写即视为作废 |
| **空洞登记**（`_Gap : Prop := True`） | 每张卡的 ⑤ 状态必须是五选一，**不允许"待定"**；给不出就写"仅文档" |
| **登记只是句子**（文档声称、grep 为零） | 每张卡的 ⑦ 证据必须是**产物存在性检查的实际输出**，不是"应该存在" |

**核心判据**：一张卡如果**只有文档、没有产物**，它的 ⑤ 状态**必须**写「仅文档」或「已作废」，不许写「已实现」。

## 二、三层作业顺序（不可颠倒）

顺序颠倒会产出大量**假冲突**——净版里很多"看起来矛盾"的地方，其实已经被裁决推翻了；如果先提净版，会浪费时间登记一堆早有定论的条目。

| 层 | 干什么 | 产出 | 为什么先做它 |
|---|---|---|---|
| **第 1 层 · 锁宪法** | 提取全部裁决与作者修正 | `01-裁决层/` 约 25 份 | **裁决优先级最高，能推翻一切**。先锁死判准，后面提取才有准绳 |
| **第 2 层 · 提概念** | 按概念切净版 8 章 | `02-理论层/` 约 120 张卡 | 理论本体，是修正版理论的骨架 |
| **第 3 层 · 并冲突** | 概念级冲突归并成条 | `03-冲突登记/` 约 40 条 | 这是**作者真正要裁决的东西**，也是最终交付物 |

**每层完成即验收**，验收不过不进下一层。

## 三、范围与四道筛子（1400 份怎么变成可读的量）

### 3.0 为什么不能直接精读 1,400 份

实测：`命运-素材-原始文件-不可更改/` 下全部 `.md` = **1,400 份 / 1,979 万字符**。
但其中**约 70% 是副本与过程产物**，真正承载设计的是少数。全量精读既不可能，也没必要。

**但"筛掉"不等于"不管"——每一道筛都必须留账，禁止静默丢弃。**

### 3.1 四道筛子

| 筛 | 判据 | 预计影响 | 处置 | 落账文件 |
|---|---|---|---|---|
| **筛 1 · 去转储** | 单文件 > 400KB 且非理论正文 | 约 2 份 / 32% 字符 | 只记录"它是什么、为什么排除"，**不精读** | `_扫描/筛1-转储清单.md` |
| **筛 2 · 归版本族** | 同名文件按版本族归并 | 约 60 份同名 | **每族的全部成员都要精读**——版本差异本身是证据 | `_扫描/筛2-版本族.md` |
| **筛 3 · 抽推翻句** | 轮次报告 / 审计中间产物 / `_pending` `_chunks` | 约 900 份 | **不精读，只做句子级抽取**：凡含「推翻/作废/改为/不再/已撤回/更正/前提被否/重写」的句子，连文件路径+行号抽出 | `_扫描/筛3-推翻句.csv` |
| **筛 4 · 定设计源** | 剩下的是真设计文档 | 约 100–150 份 | **逐份精读，进卡池** | `_扫描/筛4-设计源清单.md` |

### 3.2 筛 3 为什么这么重要

旧项目所有"推翻/修正/作废"的**原话几乎全在轮次报告里**，而不在裁决书里。裁决书是后写的总结，轮次报告是**当场说的**。

> **筛 3 抽出来的句子，是「裁决层」的第一手原料，可能比 `作者裁决*.md` 本身更全。**

筛 3 的产出必须可核对：给出**命中数 / 命中文件数 / 抽样 20 条人工复核**。

### 3.3 同名多版本的处置原则（已定）

**全部并列进卡池，冲突另行登记。** 不预选"哪个是权威版"——那本身是需要作者裁决的事。

代价：同一概念会有多份原话，卡会变厚。
收益：**"净版到底改过没有"这个前提被验证过**（`theory/` 569KB vs 成品 291KB，差 278KB，必须比出来）。

## 四、扫描 → 定卡（机械步骤，不许凭印象）

### 4.1 为什么必须先扫描

净版 `命运理论-成品/01-理论/10-命运理论-净版.md` 实测：**152,333 字符 / 3,373 行 / 8 章**。
但它不是卡池的全部母体——**筛 2 归并出的每个版本族成员，都要各扫一遍**。
按概念切会切出几张卡，**不能估**——估出来的数字正是旧项目"汇报夸大 1.5–2.75 倍"的来源。

### 4.2 扫描脚本（第一步就是它）

写一个扫描器，对**筛 4 的设计源 + 筛 2 的全部版本族成员**，把正文里**每一个可独立裁决的语义单元**的位置打出来。识别五类锚点：

| 锚点类型 | 正则特征 | 例 |
|---|---|---|
| 标题 | `^#{2,4}\s` | `### 约定 3.5（= A24）` |
| 定义 | `定义\s*[\d.]` / `^\*\*定义` | `## 1.4 命运的定义` |
| 假设 | `假设\s*[\d.]` / `A\d{1,2}` | `### 假设 3.3（= A23）` |
| 约定 | `约定\s*[\d.]` | `### 约定 4.4（= A27）` |
| 开放问题 | `开放问题\s*[\d.]` | `### 开放问题 4.2` |

**输出格式**（CSV，一行一个锚点）：

```
anchor_id, 类型, 行号区间, 原文首句摘要, 所属章, 所属节
```

### 4.3 扫描结果必须人工核对三件事

脚本只给位置，**不判断"这是不是一个概念"**。核对：

1. **合并**：同一概念被拆成多个锚点的，合成一张卡（如「命」在 2.2 节有定义、在 2.6 节有对偶、在 2.7 节被废乘号 → 三处并入「命」这一张卡）。
2. **拆分**：一个锚点里塞了多个概念的，拆成父子卡（如 3.5 节同时装「后门准则」「约定 3.5 因果可绕过」「A23」「A22」→ 拆 4 张）。
3. **落空**：锚点是空标题（如 `## 本章职责` 这种纯说明）的，不立卡，只在章级目录里记一笔。

### 4.4 定卡判据（唯一标准）

> **如果你能对这条下一句「就这么定」，它就够一张卡；
> 如果它必须和别的绑在一起才能裁决，就合并。**

补充：**卡名必须是名词性概念**（「因果在主干的定位」「命运的观测性」），不是句子（「因果不是旁路」）。句子是卡里的内容，不是卡的身份。

## 五、卡片格式（硬要求，缺项写"无"，不得省略）

### 5.1 八段骨架

> 注意：模板内部以 `## ① …` 起头的那几行是**卡文件里的标题**，不是本文的小节。


```
# 卡名（名词性概念）

## ① 一句话说明
[不超过 40 字，说清这个概念在理论里是干什么的]

## ② 出处
| 文件 | 行号 | 章/节 | 版本/轮次 |
|---|---|---|---|
| 路径（相对只读素材夹根） | L起-L止 | 第X章 X.X节 | 净版 v2.0 / 第N轮裁决 |

## ③ 原表述（逐字引用，一个字不改）
> [原文原话]
> —— 出处 L起-L止

[如有多处出处，逐处列，每处都逐字]

## ④ 提取（去掉过程话术后的净陈述）
[把原文里的"我们决定""本文认为""必须指出"这类过程话术去掉后，
 剩下的事实性陈述。不得增加原文没有的结论，不得减少原文有的限定词。]

## ⑤ 状态
[五选一：已实现 / 部分 / 仅文档 / 已作废 / 冲突中]

判定依据：
- **已实现**：有 Lean 产物 + 机器验证记录（lake build 通过 / 定理名可查）
- **部分**：产物存在但未验证，或只覆盖了主张的一部分
- **仅文档**：只有文字，无任何产物
- **已作废**：有明确裁决/作者修正推翻它
- **冲突中**：与另一处表述不可同时成立，且尚无裁决

## ⑥ 冲突
[指向 03-冲突登记/ 的具体条目号，如 C-012；无冲突写"无"]

## ⑦ 证据
[产物存在性检查的实际输出。必须贴命令和结果，不许写"应该存在"]

示例：
```
$ Test-Path "Fate/CausSeparation.lean"   → True
$ (Get-ChildItem Fate -Recurse -Filter *.olean).Count   → 0
⟹ 源码在，但从未编译，状态只能是「部分」
```
无产物写「无证据」。

## ⑧ 代码对应
| 模块族 | 具体文件 | 关系 |
|---|---|---|
| RealFCA | `Fate/RealFCA.lean` | 实现本概念的 α 层 |
| (无) | — | 本概念在旧代码中无对应实现 |

判定口径：
- **实现**：该模块直接定义了本概念
- **消费**：该模块引用了本概念
- **名义**：文件名叫这个，但内容不相关（旧项目常见，必须标出来）
- **无**：旧代码里找不到
```

### 5.2 三条禁律

1. **③ 必须逐字**。改写原话 = 换了结论 = 假转项。发现原文有错，也先原样抄，把纠错写进 ⑥。
2. **⑤ 不许写"待定"**。五选一，给不出依据就写「仅文档」。
3. **⑦ 不许写推断**。只写命令和输出。看不到 `.olean` 就是看不到。

## 六、冲突登记格式（概念级归并）

### 6.1 一条冲突 = 一个概念

**不是**一处原话一条冲突。同一个概念下的所有互相矛盾的出处，全部挂在同一条下面。理由：作者裁决时应该**一次裁决到位**，而不是裁决四次互相不一致。

### 6.2 冲突卡模板

```
# C-012 · 因果在主干的定位

## 分歧点
[一句话说清到底在争什么]

## 并列说法（不排序、不判对错）
| 编号 | 说法 | 出处（文件 L行） | 当前是否有效 |
|---|---|---|---|
| A | 因果是规则的旁路/可选层，可绕过点预测 | `00-作者裁决A-B.md` L?? | 已作废（第 380 轮） |
| B | 因果不是旁路，是主干的一部分 | 第 376 轮作者原话 | 现行 |
| C | 净版正文仍按 A 写（约定 3.5 等） | `10-命运理论-净版.md` L1215 | 残留 |

## 影响面
[这条冲突一旦裁决，会波及哪些卡、哪些模块族、哪些九要件]
- 卡：`因果结构层`、`主线方向`、`约定3.5`
- 代码：`Fate/CausDAG.lean` 等全部 `Caus*` 模块族
- 九要件：⑧ 因果结构

## 候选处置
① …… ② …… ③ ……
（只列选项，**不给推荐**）

## 状态
待裁决 / 已裁决（记裁决出处）
```

### 6.3 冲突的三种性质，必须分开登记

| 性质 | 定义 | 处置方式 | 放哪 |
|---|---|---|---|
| **设计冲突** | 两处设计不可同时成立 | 作者裁决用哪版 | `03-冲突登记/` |
| **状态冲突** | 文档说没做，产物说做了（或反之） | **跑一次机器验证就能定案**，不需要裁决 | `04-状态核对/` |
| **表述冲突** | 同一设计两种说法，实质一致 | 归并措辞，不算冲突 | 在卡内注明，不立冲突条 |

**必须分开的理由**：三类处置成本差一个数量级。状态冲突只要 `lake build` 一次就能定，混进裁决清单会稀释作者真正要看的条目。

## 七、验收（每层完成即验，不过不进下一层）

### 7.1 第 0 层（四道筛）验收

- [ ] 1,400 份 `.md` 全部进过某道筛，**无一份未归类**（`_扫描/清单总表.csv` 行数 = 1400）
- [ ] 筛 1 排除的每份都写了"是什么、为什么排除"
- [ ] 筛 2 每个版本族列出了全部成员，**没有只留一份**
- [ ] 筛 3 的抽取结果给出了命中数、命中文件数、抽样 20 条人工复核
- [ ] 筛 4 的设计源清单可数，且每份都有入选理由

### 7.2 第 1 层（裁决）验收

- [ ] 素材里所有 `作者裁决*.md`、`裁决记录.md` 已全部提取
- [ ] **筛 3 抽出的推翻句已并入裁决层**（不另立一套）
- [ ] 每条裁决有编号、有原话、有出处行号
- [ ] 被后续裁决推翻的裁决，**两条都在**，并互相标注推翻关系

### 7.3 第 2 层（概念卡）验收

- [ ] 扫描器输出 CSV 行数与实建卡数可对账（合并/拆分/落空三项有账）
- [ ] 每张卡八段齐全（缺项写"无"）
- [ ] 每张卡 ② 至少有一个可点击到行号的出处
- [ ] 每张卡 ⑤ 是五选一，无"待定"
- [ ] 每张卡 ⑦ 有实际命令输出或写"无证据"
- [ ] 每张卡 ⑧ 至少填了"实现/消费/名义/无"之一

### 7.4 第 3 层（冲突）验收

- [ ] 每条冲突是概念级，不是句子级
- [ ] 每条冲突**至少两个**互斥出处
- [ ] 候选处置**不给推荐**（防 AI 代作者裁决）
- [ ] 设计冲突与状态冲突已分离

### 7.5 全局验收（本文件夹交付时）

- [ ] `README.md` 的核心概述准确描述本文件夹性质（提取整理，非新设计）
- [ ] 无任何原始文件被修改（`git status` 对只读素材夹为 0）
- [ ] 所有数字都带口径（多少份、多少条、按什么切分得出）

## 九、最终交付物：《修正清单》

`05-修正清单/` 是 `理论-文档` 的最终产出，也是"修正版理论"的直接原料。

它不重写理论，只给出**逐条改动指令**：

```
| 卡 | 原文（净版行号） | 裁决结果 | 改动类型 | 改动后表述 |
|---|---|---|---|---|
| 因果在主干的定位 | L1215 约定3.5 | 裁决 B（主干） | 改写 | 「因果层是主干的一部分，不设旁路」 |
| 命运的观测性 | L141 1.4节 | 未裁决 | 待决 | — |
```

**当这张表的每一行都有「裁决结果」时，修正版理论就是机械回填的结果**——不需要再"写一遍"，也就不存在"又写歪"的可能。

## 十、本规程自己的失效条件

本规程也会失效，必须预先登记：

| 失效情形 | 后果 | 应对 |
|---|---|---|
| 筛 1 误杀真设计文档 | 卡池缺母体 | 大文件必须人工看首 200 字确认性质，不许只看大小 |
| 筛 2 版本族归错 | 冲突来源丢失 | 版本族必须按"内容相似度"而非仅文件名判定 |
| 筛 3 抽不到推翻句 | 裁决层不全 | 抽样核对；命中率过低说明关键词表要扩 |
| 扫描器锚点漏识别 | 卡池不全 | 用**第二种独立方法**反向核对（如按"定义/假设/约定/开放问题"四词 grep 与扫描器结果对账） |
| 卡片粒度过粗 | 冲突无法归并 | 拆父子卡 |
| 卡片粒度过细 | 卡数爆炸、裁决成本高 | 合并同概念 |
| 作者裁决缺位 | 修正清单卡在"待决" | 不硬猜，保持并列 |
| 只读素材夹被改 | 证据失效 | `git status` 为 0 是硬门禁 |

**最重要的一条**：

> **本文件夹里任何一个数字（多少卡、多少冲突、多少已实现），如果没有附带复现命令和口径说明，就不得被引用。**
