## 一、为什么要做两份再对照

按文件名和开头判断类别，**机器做不稳**——实测机器版给出了 0 份「版本副本」，
而全库实测有 **326 个同名族 / 692 份同名文件**。这说明机器的文件名规则**没有利用同名信息**，
它把 `10-命运理论-净版.md` 的 4 个副本全判成了「设计源」。

子代理逐份读文件名与开头，理论上能补上这个洞。但子代理也可能出错（漏行、惯性归类、对目录先验过度自信）。
**两份都跑，然后只对"分歧项"人工裁决**，比任何一份单独跑都可靠。

---

## 二、两套判据（必须是同一套标准，只是信息来源不同）

| 类别 | 定义 |
|---|---|
| **设计源** | 承载理论/架构设计的正文：定义概念、方程、假设、算法、模块划分 |
| **版本副本** | 与另一份同名，或是同一文档的另一版本/快照/备份 |
| **过程产物** | 轮次报告、进度记录、任务派发、临时笔记、会话整理、检查报告 |
| **审计报告** | 对项目做检查/评审/核查的报告 |
| **配置说明** | README、环境说明、索引、使用说明 |
| **转储导出** | 机器导出的数据/文档转储 |

## 五、对撞规则（子代理回来后执行）

### 5.1 一致项
两边类别相同的，**采信**，不复查。

### 5.2 分歧项
两边不一致的，按下列优先级裁决：

| 分歧形态 | 裁决方式 |
|---|---|
| 子代理判"版本副本"、机器判"设计源" | **采信子代理**（机器的已知缺陷） |
| 机器判"转储导出"、子代理判其他 | 看字符数；>400KB 采信机器 |
| 两边都是"过程产物/配置说明"之争 | 看开头是否含 `#` 标题结构；无标题采信过程产物 |
| 其余 | **进人工复查清单**，逐份看开头摘要裁决 |

### 5.3 对账校验
- 子代理 4 批合计必须 = 1,400 行，且序号无重复、无遗漏
- 任何一批缺行，该批重跑
