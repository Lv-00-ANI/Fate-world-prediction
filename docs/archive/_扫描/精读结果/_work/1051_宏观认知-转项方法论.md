# 宏观认知 · 转项方法论

> **本文件的任务**：为《命运》理论在 Lean4 + Mathlib 上的形式化，给出**「部分命题不可证时如何转项」的系统方法论**。
>
> **本文件不解决的问题**：它不替你证明任何一条命题。它只规定：**当一条命题证明不了时，允许把它变成什么，禁止把它变成什么，以及事后如何机械地检查你没有偷偷挖洞。**
>
> **上位文档**（本文件与它们不冲突，只补充它们未覆盖的部分）：
> - `_规格/02-证明路线/00-总纲.md` §二（三类陈述判据）、§三（Mathlib 两栏）

> - `_规格/02-证明路线/04-假设登记.md` §1.2–1.4（三类归属、六字段、一条纪律）、§4.1（前件三种来源）
> - `_规格/02-证明路线/01-路线图.md` 六（验收标准）、`债务清账台账.md` 三（终态纪律）
>
> **本文件的自我限界**：**不虚构文献、作者、年份、数字**。凡引用外部数学结果，一律按项目既有惯例标 `[已知]` 并注明「本框架内未证」，且**不给出处的作者年份**（本项目尚未完成出处核验，本文件不越过这一状态）。**本文件中的所有 Lean 代码块都是「写法示例」，其 `by` 体一律以 `sorry` 占位**——它们的用途是说明**类型怎么写**，不是声称可编译、更不是声称已证。唯一例外是 §三 与 §八 中明确标为「可编译、不含 sorry」的**检查脚本**，它们只做语法与命名空间分析，不证明任何数学。

## 〇、本文件的核心区分：转项 与 逃避

**这是全文件的核心，其余各节都在为它服务。**

| | **转项**（合法） | **逃避**（违规） |
|---|---|---|
| **做了什么** | 把「证明不了的 P」改写成「**能证明且能引用**的 P′」，并**保持 P′ 与 P 的差距可陈述、可登记、可被下游看见** | 把「证明不了的 P」改写成「**看起来已被证明**的 P′」，而 P′ 与 P 的差距**不出现在任何地方** |
| **判据一：前件合取是否引入新内容** | `P′ = H → C`，且 `H` 与 `C` 的逻辑内容**互不包含**；`H` 是一条**独立的、可被单独检验/证伪**的命题 | `P′ = C → C`，或 `H` 蕴含 `C`（`H` 比 `C` 强），或 `H` 是 `C` 的换一种写法 |
| **判据二：前件是否可写成 Lean 类型** | `H` 在 Lean 中是一个**具体的 `Prop`/结构体/类型类**，能在 `#check` 后独立存在 | `H` 是「模型足够正确」「假设大致成立」「在合理条件下」这类**只在自然语言里存在**的谓词 |
| **判据三：差距是否被立案** | 差距在**假设登记表**（A/E 编号）或**开放问题表**（O 编号）中有一条**带六个字段**的记录，且该记录**进入本轮的债务增量报表** | 差距只出现在一份进展报告的散文里，或在台账中占一个无归属状态（「进行中」「待办」「后续处理」） |
| **判据四：结论强度是否如实下降** | 结论 P′ 明确比 P 弱，**并说出弱在哪（丢失的量词、丢失的一般性、丢失的精度）**，且**下游若引用 P，会编译失败或至少被检查拦下** | 名字与 P 相同、陈述被悄悄改写，下游引用者以为拿到的是 P |
| **判据五：时间上是否收敛** | 转项**降低**了不确定性：要么缩小了未知的范围（部分识别），要么证伪了一条（负结果），要么明确了一个可实验方向 | 转项**推迟**了判断：没有新信息，只是把「不会」改写成「在假设下会」 |

**一句话判据**：

> **转项使「我们不知道什么」变得更小、更精确、更可操作。**
> **逃避使「我们不知道什么」变得看不见。**
> **凡使不可见者，不论其形式多规范，均为逃避。**

**为什么这值得单列一节**：这个项目的核心风险不是「证不出」，而是「**证不出却看不出来**」。项目里已经发生过两类实例，本文件把它们当作**标本**使用，而不是当批评：

- **标本一（合法的转项）**：`04-假设登记.md` 把 A15「路径测度存在」从「假定存在」**升级**为 T0.2 的构造性命题（Kolmogorov 扩张 + 连续性判据）。这是**反向转项**——把假设变成待证定理，差距**缩小**了。同处把 A21 标注「**可能重分类为经验假设**」并挂开放问题 4.4，这是**合规的降级登记**：降级本身合法，因为它被写进了登记表并给出理由。
- **标本二（逃避的高危形态）**：`02-定理清单.md` §5.1 的核查结论——原文第 31 轮把 8 项外部结果标为「已证」，而本框架内证明数为零。**这 8 项全部是 `[已知]`，不是本框架成果。** 其危险不在于错，而在于**它看起来是这批命题里唯一「已经完成」的部分**——一旦这种标注进入进度统计，「已证 8 项」会给出一个虚假的、令人安心的完成度信号。**这就是「逃避」的定义性特征：它不改变数学，只改变可见性。**

### 0.1 一条总原则：**转项不得降低命题的可否证性**

数学命题的合法性在于「它可能为假」。转项后的 P′ **仍然必须可能为假**，否则它不是命题。

- 若 P′ 变成恒真（如 `C → C`，或前件为空却挂着条件定理的名号），它**不再是命题**，而是**同一律的一个实例**。
- 若 P′ 的域被缩到单点（如「对 $n=1$ 成立」而原命题是全称），它**仍然**是命题，但你要在登记里写明「域已缩至 ⟨描述⟩」，并说明**为什么不缩到空**。
- 若 P′ 是「存在某个对象使之成立」，须给出**该对象的构造**，否则它是存在性空话。

**机械检查**：对每条转项后的 P′，回答「**什么观测/什么反例会推翻它？**」若答不上来，P′ 不是命题，退回重写（对应 §一 原因 3）。

## 第一部分 · 不可证的原因分类（分类决定对策）

**方法论的第一原则**：**不同原因必须不同对策。**把「不知道怎么办」笼统归为「不可证」，是本项目最贵的错误——因为它把 8 类性质完全不同的问题塞进同一个抽屉，导致**本该立刻证伪的（原因 1）被当成开放问题挂账，本该换刻画的（原因 3）被当成数学困难攻关**。

`00-总纲.md` §二 已给出**三层划分**（①可证 / ②条件定理 / ③经验假设），那是**陈述的法律地位**划分。本节给出的是**失败原因**划分，两者正交：一条 ② 类条件定理的**失败原因**可以是 4、5、6 中的任意一种，对策完全不同。**不要把两张表混成一张。**

### 1.1 分类总表

| # | 原因 | 一句话判据 | 判定方法 | 可否机械检查 | 典型对策 |
|---|---|---|---|---|---|
| 1 | **数学上为假** | 存在反例 | 构造反例并**在 Lean 中证出否定** | 部分（否定须编译） | D |
| 2 | **不可判定（独立于 ZFC）** | 在标准集合论中既不能证也不能否 | 归约到已知不可判定命题，或证「在可数模型/力迫扩张中真假翻转」 | 否（须论证） | H（极少见，先怀疑是 3/6） |
| 3 | **表述不精确** | 写不成 Lean 类型 | **试写类型失败**：写出 `def`/`theorem` 头，Lean 报「unknown identifier / failed to synthesize / type mismatch」 | **是**（写出骨架即判） | F / G |
| 4 | **依赖不可验证的经验假设** | 前件含「真实世界」断言 | 前件中出现真实对象（真实分布、真实因果图、真实数据生成过程） | 部分（前件须可写类型） | A + 登记 E |
| 5 | **桥缺失（中间对象未定义）** | 两端有定义、中间无 | 沿依赖链找**第一个未定义的节点** | 是（`#check` 逐点探） | A + 补桥 |
| 6 | **超出当前能力** | 无已知方法/方法巨大 | 文献穷举后仍无构造、无下界；或引理链长度超阈值 | 否 | E / B / H |
| 7 | **只对特殊情形成立** | 一般情形有反例 | **在一般情形下真的去找反例**（不是「觉得可能」） | 是（反例证完即判） | B |
| 8 | **需要不可获得的数据** | 前提超出观测 | 结论所依赖的量在数据中不可识别（如反事实点值、真图 $G_0$） | 部分 | C |

**共同的前置动作（对全部 8 类）**：**先问「这条命题是否已经被证明过」**。本项目的一句教训是：`第1xx轮` 系列文档反复出现「查明根因」「工具已找到」——**大量「不可证」实为「还不知道该查什么」**，属 **元层误分类**，见 §1.3。

### 1.2 逐类判定的精确程序

#### 原因 1：数学上为假

**判定方法（三步，顺序不可颠倒）**：

1. **在最小载体上试反例**。把命题中的每个结构替换为最小实例（`Bool`、`Fin 1`、单点测度、常值函数）。本项目已有成功的先例：`泛化为假-独立验证.md` 里 `obsOnQuotBy_injective_iff` 的反例就是取 `SCM := Bool`、`Obs := fun _ => ()`、`F := {true}`、`r := ⊥`。
2. **把反例写成 Lean 定理**，结论为**否定式**：

```lean
-- 写法：否定式定理 + 反例见证。这样「P 为假」本身成为一条已证定理。
-- 注意：这需要先有 P 的完整形式化，见 §二 策略 D 的代价说明。
theorem counterexample_exists_<slug> :
    ∃ (M : SCM) (r : Setoid M.SCM) (F : Set M.SCM),
      ¬ (obsOnQuotBy M r (by sorry) F).Injective := by
  sorry
```

3. **登记为负结果**，编号不动、类别改为「已证否」，并在定理清单的「现状」栏写 `[可证·已证否]`。**不得删除条目**（编号纪律：一经分配永不复用，`02-定理清单.md` §1.1）。

**何时应怀疑原因 1 而非原因 6**：命题中出现「对所有」「任意」「存在唯一」这类强量词，且**没有被任何一般性定理支持**。**先证伪，再攻关**——这是本项目最省时的默认动作。

#### 原因 2：数学上不可判定

**判定方法**：

1. **先做尽职调查，排除 3、5、6**。在实践上，被误标为「不可判定」的命题，九成是「表述不精确」或「桥缺失」。理由很简单：**真正的 ZFC 独立命题在应用数学中是稀有事件**，且它们几乎全部来自集合论/描述集合论/无限组合，而不是来自因果推断、FCA、动力系统。
2. 若确要主张独立，须给出**可陈述的归约**：找到一个已知独立命题 φ，并证「本命题 ⟺ φ」（在 ZF 下）。
3. **在 Lean 语境下的一条特殊事实（必须记录）**：Lean 的 `Prop` 宇宙里，Mathlib 的标准配设包含**选择公理 `Classical.choice`**，并普遍采用**希尔伯特选择**；此外 `propext`、`quot.sound` 等也是常备公理。因此**「在 Lean 中可证」不等于「在 ZF 中可证」，反之亦然**。主张一条命题「在标准数学中不可判定」而同时在 Lean 中证明它，需要说明你**用了哪些额外公理**。这一条并不罕见地**反过来**制造问题：你以为「不可判定所以不必证」的命题，**在 Lean 里其实完全可以证**（因为它用了 `Classical.choice`）。

**何时**：**几乎从不。** 本项目的命题域（FCA、d-分离、do-calculus、SDE、泛化界）里，**没有一条有独立性的先验理由**。若你把某条标为原因 2，请把它当作**你自己分类失败的证据**，优先返工为 3/5/6。

#### 原因 3：表述不精确

**判定方法（可机械执行）**：**写出类型骨架，编译。** 判定的产物不是文字判断，而是 Lean 的报错。

```lean
-- 判据：能否写出 `def`/`theorem` 头，使 Lean 不为「符号未定义」报错。
-- 以下三种失败模式对应三种不同的不精确：

-- (3a) 谓词未命名 —— Lean 直接报 unknown identifier
-- def 模型足够正确 (M : SCM) : Prop := ...

-- (3b) 前件写得出但无法实例化 —— 类型有了，但没有任何构造子/实例
-- （能写类型 ≠ 有对象，这是 §三 纪律 3 要拦的第二种情况）
def 合理条件 (ε : ℝ) : Prop := ε ≤ 0.05   -- 能写，但「0.05 从哪来」没有依据

-- (3c) 依赖「差不多」「可接受」这类连续统判断 —— 写出来必然是任意阈值
-- def 可接受 (e : ℝ) : Prop := e < 0.1        -- 任意阈值，属 G 类（定义性约定）
```

**登记**：原因 3 的命题**不进入定理清单**（未命名谓词不立项，`02-定理清单.md` §1.2 硬性纪律），而进入**开放问题表**，并在其中写明「缺的是哪个谓词的定义」。

#### 原因 4：依赖不可验证的经验假设

**判定方法**：把命题的**前件集合**写出来，逐条问：「这条前件是对**数学对象**的断言，还是对**真实世界**的断言？」

- 数学对象：「$f$ 是 Lipschitz 的」——可在给定 $f$ 后判定。
- 真实世界：「所观测数据由某个 SCM 生成」（E5）、「真实分布关于 $G^*$ 因子分解」（E1）、「不存在未观测混杂」（E3）——**不可判定，只能否证或敏感性分析**。

**判定产物**：一条 E 类编号。`04-假设登记.md` §3.1 已登记 16 条，**新发现的必须续编号，不得另起体系**（§1.1 硬性规定）。

**关键区分（易错）**：**「不可验证」≠「不可形式化」。** E1–E7 每一条**都能**写成 Lean 类型（它们是对概率测度、图、分布的可测断言），只是**无法证明其成立**。因此它们**表现为定理的前件参数**，而不是定理清单里的条目。这正是「②条件定理 + ③经验假设」分工的含义。

#### 原因 5：桥缺失

**判定方法（依赖链逐点探法）**：

1. 写出命题需要但当前**没有定义**的对象清单（自然语言即可）。
2. 对每个对象，**在 Lean 中 `#check` 其名字**：

```lean
-- 探针文件：每个对象一行，编译后看哪些报 unknown identifier。
-- 这是本项目已有做法（第 xx 轮系列反复出现「查明某符号是否存在」），此处把它制度化。
#check @Fate.SCM
#check @Fate.doOp
#check @Fate.scaleOp        -- 尺度化算子 ς（A32 的前置，原文对此只有「未分析」一句）
#check @Fate.ruleLength     -- 规则长度（A21 重分类候选的前件 E16）
```

3. **第一个 `unknown identifier` 就是桥的位置**。桥的缺失是**可定位的**，这是它区别于原因 6（不可定位）的关键。
4. 判定产物：**一条定义条目（D 编号）的缺口**，+ 一个「只在桥的这一侧可证」的**条件定理**。

**本项目的头号桥**：A32 的**尺度化算子 $\varsigma$**（连续 $x_t \mapsto$ 二值形式背景 $(A_t, B_t)$）。其误差命题 E8 的形式「若 $\varsigma^{-1}(\varsigma(x)) \ni x$ 且阈值间隔 $\ge \gamma$，则 $d(x,\varsigma^{-1}(\varsigma(x)))\le g(\gamma)$」**依赖 $\varsigma$ 存在**，而原文对该误差的处理**只有「未分析」一句**。**这是教科书级的原因 5**：桥的两端（连续状态空间、形式背景）都有定义，中间没有。

#### 原因 6：超出当前能力

**判定方法**：

1. 完成文献检索并**记录检索行为**（查了什么、查到什么）。本项目的反面教训：`00-总纲.md` §二 记录原文「do-calculus 1–2 年、总计 5–10 年」这一成本数字**该轮无任何检索行为**，且数字加不起来，**下一轮作者自己推翻**。**凡无检索记录的能力判断，不得作为转项依据。**
2. 判断「无已知方法」还是「有方法但工作量巨大」。这两者对策不同：
   - **无已知方法** → 策略 H（开放问题），且必须写出「卡在哪一步」。
   - **有方法但巨大** → 策略 A（把中间结论做成条件定理）+ 策略 E（先证受限版）。
3. 用**相对档位**而非时间表述（项目惯例：低/中/中高/高/极高，`02-定理清单.md` §6.3）。**不给年数估计。**

**本项目的头号原因 6**：T3.11（do-calculus 完备性）。清单判定其前置依赖 **≥ 20 条**、Mathlib 覆盖为零、**不可绕过**。它的困难**不是任何单个缺口**，而是**四组高难度条目的汇合**。这类命题的转项**不能是单点降级**，必须是**分段策略**（见 §四 与 §五 建议 3）。

#### 原因 7：只对特殊情形成立

**判定方法**：**在一般情形下找反例**（不是「猜可能不成立」）。

- 本项目的珍贵先例：`第44轮-Equiv1单调性不成立.md`、`第45轮-单调性两向皆假.md`。**两向皆假**这一结论的价值，远高于「单调性未证」——它把一条不可做的事情**永久关闭**，释放了全部相关工作量。
- 判定产物：**一般情形的否定式定理** + **子类的正定理**，两者都进入清单（同编号体系下分配两条新编号）。

**操作细则**：把全称命题的**每一个前提**视为可放弃的旋钮，逐旋钮放松，看命题在何处失效。**失效的第一个旋钮 = 子类的边界。**这个边界就是策略 B 的收口位置，且它是**被反例逼出来的**，而非拍脑袋选的。

#### 原因 8：需要不可获得的数据

**判定方法**：问「结论依赖的量，能否由观测数据唯一确定？」

- 若能 → 属原因 6（只是算得多）。
- 若**不能但可约束**（给出区间、下界、上界）→ 属原因 8，对策 C。
- 若**完全不能**（既不唯一也不能被任何界约束）→ 该量**没有观测意义**，命题应降为 G 或删。

**本项目的典型**：反事实点值 $Y_{X=x}(u)$。项目文档 `05-误差界路线.md` §E7 的分析是本方法论的一个范例：**点值不可观测，但群体版（QTE、中介效应）在单调性/秩保持下部分识别，因此 $\delta$ 的上界可由识别区间宽度 witness**。**这是「原因 8 → 策略 C」的正确做法：不放弃命题，把它从点识别降为区间识别，并让区间宽度成为可测量量。**

### 1.3 元层误分类（最贵的一类，独立成节）

**定义**：**「不可证」在事实上是「还不知道可证性」**。它与原因 6 的区别：原因 6 是**已知无方法**，元层误分类是**分类工作本身没做完**。

**本项目的实测证据**（作为方法论的依据，不作评判）：

- `工具缺陷-任务提取错位.md`：派发脚本把背景段编号误当任务，导致**三个批次各错位 2–3 位**——**任务与产出的对应关系错误**，于是「某任务未完成」可能是**映射错**，不是数学困难。
- `第104轮-查明代理失败根因.md`、`第105轮-代理完全恢复与新风险.md`、`第106轮-倒退与git回滚与新发现.md`、`第114轮-第四次倒退与元问题诊断.md`：反复的「倒退」与「恢复」。
- `第99轮-回读验证自动化与陈旧断言更正.md`、`第161轮-诚实修正命名.md`：**陈旧断言**与**命名不诚实**被反复发现。

**方法论结论**：

> **在把任何命题判为原因 6 之前，必须先排除元层误分类。排除的标准不是「我想过了」，而是：**
> 1. 该命题的**编号在定理清单中唯一存在**，且其陈述与理论原文档的对应段落**逐字核对过**（防错位）；
> 2. 该命题的**全部前件已在登记表中，且无循环前件**（见 §三 纪律 5 的 A30 案例）；
> 3. 该命题的**依赖链全部编号存在**（`#check` 通过），无 `unknown identifier`；
> 4. 该命题**已被至少一次独立检索确认无现成结果**（记录检索行为）。

**只有 1–4 全部通过，「超出当前能力」才是合法的原因 6 判定。** 否则拒绝转项，退回补分类工作。**这一条是本文件最省钱的规则**：它拦下的不是数学困难，而是**把非数学问题当成数学困难**——那是唯一一种会无限期消耗预算的错误。

## 第二部分 · 转向策略库（核心产出）

**八个策略 A–H。每个给出：精确适用判据 / Lean 落地写法 / 后果 / 反例与失败模式。**

**共同的写法约定**：下面所有 Lean 块的 `by sorry` 都是**占位**，只表示「证明在此处」，不表示已证。真实使用时，`sorry` 只允许出现在**尚未开工的条目**里，且必须计入 §三 纪律 7 的债务报表。

### 策略 A · 降为条件定理

**内容**：把不可证的困难部分做成**具名前件**，陈述改为 `H → C`。

**适用判据**（三条须同时满足）：
1. 困难集中在**某一组可命名的前提**上，而不是散布在整个证明里；
2. `H` **能写成 Lean 类型**（有具体 `Prop`/结构/类型类）；
3. `H` **与 `C` 逻辑独立**（`H` 不蕴含 `C`，`C` 也不蕴含 `H`）。

**Lean 落地**：

```lean
open MeasureTheory ProbabilityTheory

variable {Θ Χ U Ε : Type*} [MeasurableSpace Χ] [MeasurableSpace Ε]
variable {Ω : Type*} [MeasurableSpace Ω]

-- 前件做成具名结构体，而不是一串匿名匿名参数。
-- 这样每条前件都有名字，可被单独 #check、单独证伪、单独登记。
structure TrajRegular (μ σ : Θ → Χ → ℝ) : Prop where
  /-- Lipschitz 条件。来源：A10。可数值验证（见 04-假设登记 §4.2 T0.2 行）。 -/
  lipschitz : ∃ L : ℝ, 0 ≤ L ∧ ∀ θ, LipschitzWith ⟨L, by positivity⟩ (μ θ)
  /-- 线性增长。 -/
  linearGrowth : ∃ C : ℝ, ∀ θ x, ‖μ θ x‖ ≤ C * (1 + ‖x‖)
  /-- 扩散项非退化。 -/
  nondegenerate : ∀ θ x, σ θ x ≠ 0

/-- T0.2：路径测度存在性。原始陈述是「结论」；转项后是「前件 → 结论」。
    前件 TrajRegular 是**具名、独立、可证伪**的：取一个无界 μ 即可构造其否定。 -/
theorem pathMeasure_exists
    (h : TrajRegular μ σ) :
    ∃ (P : Measure (∀ t : ℝ≥0, Χ)), IsProbabilityMeasure P := by
  sorry
```

**多前提的写法纪律**：`H₁ → H₂ → ... → Hₙ → C` 是等价的，但**必须把每条 `Hᵢ` 做成具名 `Prop`/结构体**，不得写成匿名 `(... : ... )` 参数。理由：匿名参数无法被登记表引用，而**登记表的引用完整性是纪律 4 的前提**。

**后果**：
- **下游必须显式传递** `h : TrajRegular μ σ`。这是**好处**——它使前件不可被遗忘（见 §三 纪律 2 的连带价值）。
- 下游可以自由**弱化或分拆**前件：若某条子前件后来被证明（如从 $f$ 的形式推出），只需重写一条桥引理，不必动定理本体。
- 统计口径变化：该条目从「① 可证」变为「② 条件可证」。**必须同步更新 `02-定理清单.md` §6.1 的计数**，否则进度统计失真。

**反例/失败模式**：

> **失败模式 A-1（前件即结论）**：把 P 的前件写成 `H := ∀ x, f x = g x`，而 `C := ∀ x, f x = g x`。这是同一律，不是定理。
>
> **失败模式 A-2（前件强于结论）**：`H := 存在唯一的因果图且已知`、`C := 因果图已知`。`H` 蕴含 `C`，定理退化为 `C → C`。
>
> **失败模式 A-3（不该用 A 的时候用 A）——本项目的真实案例**：T3.11（do-calculus 完备性）**不能**用策略 A 收口。原因是它的困难在于**≥20 条前置依赖的汇合**，不集中于某一组可命名前提。若强行写 `H := 「三条规则足以改写一切可识别表达式」`，则前件**直接就是结论**（失败模式 A-1 的精确形态）。**A 只适用于「困难可定位到一个前提」的情形；困难若弥散在整个证明链上，A 会退化为同义反复。**
>
> **失败模式 A-4（把桥的缺失伪装成前件）**：见下述策略 A 桥混合型。

#### A 的变体：条件定理 + 补桥（针对原因 5）

**适用判据**：中间对象未定义，**但两端已定义**。

**Lean 落地**：**先定义桥（哪怕先只给类型），再写条件定理；条件定理的前件是「桥满足某性质」，而不是「桥存在」。**

```lean
/-- 桥本体：尺度化算子 ς。**先给类型，值域暂留实现。**
    A32 的前置正是这个对象；原文对该误差只有「未分析」一句。 -/
def scaleOp (γ : ℝ) (hγ : 0 < γ) (x : Χ) : FCA.Concept Χ :=
  sorry  -- 值域实现。关键：它现在是**一个 D 编号的定义**，不再是一段自然语言

/-- 条件定理：把「桥存在」的诉求，换成「桥满足逆向包含」的**具体性质**。
    E8 的原始形式（05-误差界路线.md 的 E8）就是这样写的，本文件只是指出它是策略 A 桥混合型。 -/
theorem fca_discretization_error
    (γ : ℝ) (hγ : 0 < γ)
    (hcover : ∀ x, x ∈ scaleOp γ hγ ⁻¹' {scaleOp γ hγ x})   -- 逆向包含
    (hgap   : ∀ x y, ¬ SameCell γ x y → γ ≤ dist x y)        -- 阈值非退化
    : ∀ x, dist x (by sorry : Χ) ≤ g γ := by                   -- g 待定
  sorry
```

**关键点**：转项后**「桥缺失」被拆成两部分**——(i) 一个**定义条目**（可以立刻立项，不必等数学困难解决）；(ii) 一组**前件**（可被单独证伪：给出一个使 `hcover` 失败的 $x$ 即可）。**这是把不可定位的困难变成两个可定位的任务。** 这一步的价值与本项目「把 A15 升级为 T0.2」同构。

**失败模式**：

> **失败模式 A-5（桥定义成空壳）**：`def scaleOp ... := ⟨⟨∅, ∅⟩, sorry⟩` 之类的实现，使 `scaleOp` **对任何输入都返回同一个值**。此时 `hcover` 自动成立，条件定理变成空洞真。**机械检查**：桥的定义必须至少能通过**两个不同输入的输出不同**的测试（给两个 $x$ 使 `scaleOp` 结果不同），否则视为空壳。
>
> **失败模式 A-6（桥的方向反了）**：条件定理的前件依赖桥的输出，但桥的定义依赖条件定理的结论，形成循环。**检查**：`#check` 桥的定义体中出现的每个符号，不得包含该条件定理自身。

### 策略 B · 缩到可证子类

**内容**：一般情形为假（或疑似为假），**只在子类上陈述**。

**适用判据**：
1. 已**证出一般情形的否定**（原因 7 的判定方法已完成）；
2. 该子类**由反例的失效点自然界定**，而不是由「这样好证」反向挑选；
3. 子类**非退化**（不是单点、不是空类）。

**Lean 落地**：

```lean
-- 本项目的实际形态：「以图表征」只在 CPDAG 等价类内成立。
-- 一般情形：G 已知 ⟹ 后门准则可用。
-- 子类：只知道 CPDAG。

/-- 子类谓词必须**具名**，且其定义体中不得出现待证的结论。 -/
def KnowsCPDAG (G : DAG V) (P : Measure V) : Prop :=
  P.IsMarkovEquivTo G   -- 占位：只知等价类，不知方向

/-- 子类版：方向不可全定，但**不做方向修正时**的效应界仍成立。
    一般情形（≔ 已知全部方向）为假：T2.8 已证方向不可识别。 -/
theorem backdoor_bound_upto_cpdag
    (h : KnowsCPDAG G P)
    (hbounded : ∀ z, 0 ≤ w z)   -- 敏感性权重有界
    : ∀ x, |trueEffect x - estEffect x| ≤ Δ := by
  sorry
```

**收口写法技巧**：把子类**做成类型类**，让下游「自动」只在子类中工作：

```lean
class CPDAGKnown (G : DAG V) (P : Measure V) : Prop where
  equiv : P.IsMarkovEquivTo G

-- 下游凡是需要方向的引理，都带上 [CPDAGKnown G P]，
-- 于是「在子类外调用」在类型上就是不可能的——这是策略 B 的最强形态。
theorem some_identifiable_lemma [CPDAGKnown G P] : ... := by sorry
```

**后果**：
- **丢失一般性**。必须在登记里写明：原命题的全称域是什么，收口后是什么，**收口依据是哪条反例**（给编号）。
- 下游若需要一般情形，会**编译失败**——这**正是想要的**（见 §三 纪律 4 的连带价值：让错误无法静默传播）。
- 若子类后来又发现是空的（无任何实例），`C → C` 的空洞真问题重新出现（见 §0.1）。

**反例/失败模式**：

> **失败模式 B-1（收口到空类）**：子类谓词是 `False` 或不可满足。此时定理恒真，**且没有对象**。**检查**：子类谓词必须有**至少一个实例**（在 Lean 中给出一个具体例子并证明它满足谓词），否则退回。
>
> **失败模式 B-2（收口到平凡类）**：子系统变成 `Subsingleton` 或 `Fintype` 的 1 元类型。此时「对子类成立」接近恒真。**检查**：子类中必须存在**两个不同构的模型**。
>
> **失败模式 B-3（偷偷收口而不声明）**：定理陈述里悄悄加了 `[Finite V]`、`[IsProbabilityMeasure P]` 等假设，而**没有在登记表登记、也没有在定理清单的类别栏体现**。这是本文件最常被忽视的逃避形式，因为**它在 Lean 里看起来完全正常**。见 §三 纪律 4 的机械检查脚本。

### 策略 C · 改为部分识别

**内容**：不能点识别，**给区间/界**。

**适用判据**：
1. 目标量 $q$ **不可由数据唯一确定**（原因 8）；
2. 但存在**可计算的上下界函数** $\underline q \le q \le \overline q$，且这些界**由可观测数据决定**；
3. 区间**非平凡**（宽度 $< \infty$，且**不是** $[-\infty, +\infty]$）。

**Lean 落地**：

```lean
/-- 部分识别的正确形态：**逐模型给出界**，且界只依赖可观测部分。
    注意 `PartialIdentification` 是一个**关系**，不是一个点。 -/
structure PartialIdentification (Obs : Type*) (q : SCM → ℝ) : Prop where
  lower : Obs → ℝ
  upper : Obs → ℝ
  /-- 关键：界只依赖观测（该类型），不依赖模型的隐藏部分。 -/
  sound_lower : ∀ (M : SCM) (o : Obs), M.toObs = o → lower o ≤ q M
  sound_upper : ∀ (M : SCM) (o : Obs), M.toObs = o → q M ≤ upper o

/-- 反事实的群体版：QTE 的界。点值不可得（原因 8），区间可得。 -/
theorem qte_bounds
    (M : SCM) (o : Obs) (hmono : MonotoneRankPreserving M)
    : lower_qte o ≤ qte M ∧ qte M ≤ upper_qte o := by
  sorry
```

**后果**：
- **结论变弱但可用**：下游可以用界做决策（最坏情况、鲁棒优化），而不是使用一个没有意义的点值。
- **区间宽度成为新的可观测量**。这是策略 C 的真正收益：它把「不可观测的 $\delta$」变成「可测量的区间宽度」，从而使上游的误差界命题（如 E7）**获得可实验确认的前件**——本项目的 `05-误差界路线.md` §E7 正是这样处理的，应作为模板推广。
- 必须登记：**原命题声称的是什么（点识别），现在给出的是什么（区间），区间宽度是多少**。

**反例/失败模式**：

> **失败模式 C-1（平凡区间不算结果）**：$\underline q = -\infty$、$\overline q = +\infty$（或对实值量取 `⊤`/`⊥`）。这**不是部分识别**，是「完全没有识别」。`01-路线图.md` §R2.4 已对界命题给出同构要求：「每条界必须在其定义域上有限」。**策略 C 的界必须满足同一要求。**
>
> **失败模式 C-2（界依赖不可观测量）**：`lower` 的定义体中出现了 `M.exogenous`（外生变量真值）。此时「界」不提供任何信息，因为要算它得先知道真值。**检查**：`lower`/`upper` 的**签名中不得出现 SCM 的隐藏字段**——这一点在 Lean 里**由类型保证**（`lower : Obs → ℝ`）。**这是 Lean 相对于纸面数学的一个真实优势：它能机械地强制「界只依赖观测」。**
>
> **失败模式 C-3（用宽松的界掩盖「不知道」）**：区间宽度 $10^6$ 的界在数学上正确、在实践中无用。必须同时报告**宽度**，并与其他方法的宽度比较。**只说「有界」不说「多宽」是回避。**

### 策略 D · 改为反例证伪（负结果）

**内容**：命题为假 → **证明其为假**。

**适用判据**：**只要怀疑为假就应当尝试**。这一策略的适用门槛最低，收益却最确定。

**Lean 落地**：

```lean
-- 形态一：否定式定理（最常需要）
theorem not_equiv1_monotone :
    ¬ (∀ (M : SCM) (a b : Intervention), a ≤ b → effect M a ≤ effect M b) := by
  sorry

-- 形态二：把反例做成结构体，便于复用与引用。
-- 这样「反例」本身成为本库的一个**对象**，后续定理可以直接拿它做否定见证。
structure CounterexampleToMonotonicity where
  M : SCM
  a : Intervention
  b : Intervention
  le : a ≤ b
  violation : ¬ (effect M a ≤ effect M b)

theorem monotonicity_fails : ∃ _ : CounterexampleToMonotonicity, True := by
  exact ⟨⟨by sorry, by sorry, by sorry, by sorry⟩, trivial⟩
```

**后果**：
- **这是最干净的成果**：它**永久关闭**一条路线，释放全部相关工作。
- 它的正确登记方式是**改类别而不删编号**（`[可证·已证否]`），并**在理论侧文档同步更正**——因为原文若据该命题推出过别的结论，那些结论须重新审视（**下游污染检查**，见下）。
- **不能做的事**：证伪之后**不得**「顺便」把原命题改弱成子类版而不声明——那属于策略 B，须走 B 的登记流程。

**反例/失败模式**：

> **失败模式 D-1（反例不是反例）**：反例的构造**用了被否命题之外的额外假设**（如引入了一个原命题排除的奇异模型），于是它否证的只是自己的假设组合。**检查**：反例必须满足原命题的**全部**前提，逐条列出并证明。
>
> **失败模式 D-2（证伪了但下游照旧用）**：`第44轮`/`第45轮` 类型的发现之后，若库中仍有定理以该命题为引理，**库是不一致的（在语义上）**。**检查**：证伪后必须全局搜索该命题的引用者，逐个改判。**这是纪律 7 的债务报表必须覆盖的一项**：`负结果 → 受影响的下游条目列表`。
>
> **失败模式 D-3（把「找不到证明」当成「证伪」）**：反例**必须是构造出来的且已验证的**（在 Lean 中编译通过），不能是「数值实验显示不成立」。数值证据属于**证据而非证明**（本项目对 E4 的措辞即是此规），可以支撑「值得尝试证伪」，不能替代证伪。

### 策略 E · 改为复杂度结果

**内容**：不能构造 → 证下界/上界。

**适用判据**：
1. 目标是「存在某对象/某算法」，但**构造不可得**；
2. 存在一个**可定义的复杂度度量**（时间复杂度、概念格规模、规则长度、样本复杂度、概念数）；
3. 能证明**至少一侧**：构造不可能（下界），或构造有界（上界）。

**Lean 落地**：

```lean
/-- 上界型：概念格的规模上界。**注意：这是关于数值的定理，不是关于算法的定理。** -/
theorem concept_lattice_card_bound
    (hfin : Fintype Χ) (hfinI : Fintype I)
    (hq : k = Fintype.card I → False)   -- 属性数 ≥ ...（占位）
    : Fintype.card (Concept Χ I) ≤ 2 ^ Fintype.card Χ := by
  sorry

/-- 下界型：不存在多项式时间算法——这是**否定存在量词**的命题，
    必须在明确的模型内陈述（图灵机/TM 编码），否则无法写成类型。 -/
theorem no_poly_algorithm_for_dg_basis
    (basisComputableByPolyTM : Prop)   -- 前置：明确的复杂度模型
    : ¬ (∃ (t : ℕ → ℕ), Poly t ∧ CompilesAt (ComputeDGBasis) t) := by
  sorry
```

**后果**：
- **「换个说法」是真话**：你不给出构造，你给出构造的边界。这对下游是有用的——下游可以据此**选择算法/放弃路线**。
- **本项目的一个具体潜力**：`多路线台账.md` 记录 FCA 路线的实测结论「属性数 $= k\times d$（线性），而闭集枚举是属性数的**指数**」。这是一条**结构性事实**，其形式化版本（上界型）比任何「尝试改进编码」都更有价值，且**难度低**——因为它是组合事实，不依赖外部理论。**这是本文件中建议最高优先级的单条做法之一**（见 §五 建议 2）。
- 复杂度模型必须**显式**。若写成「不存在高效算法」而无复杂度模型，则它是原因 3（表述不精确），不是策略 E。

**反例/失败模式**：

> **失败模式 E-1（下界没有模型）**：「无多项式算法」若不指定计算模型（TM / RAM / 实数 BSS），**不可陈述**。本项目 T8.7「计算不可约性」正是这个失败模式的现成案例——清单明写「概念本身尚未形式定义」「无处可评估」。**策略 E 的前提是先有复杂度模型的定义条目。**
>
> **失败模式 E-2（上界是平凡上界）**：`|𝔅| ≤ 2^|G|` 对任何有限形式背景都成立，**不提供信息**。必须有**紧性证据**：存在实例使上界被达到，或至少给出上界与下界之比有界。`01-路线图.md` §R2.4 的「趋于 0」要求在此处的对应物是「**上界可被某些实例达到**」。
>
> **失败模式 E-3（用复杂度结果替换了原命题而没有登记）**：原命题是「存在 $\alpha$ 且可计算」，转项后是「$\alpha$ 的存在性有组合上界」。**这两条不是同一条命题**，必须在登记中写成**两条独立条目**（原命题挂账 + 新条目成立），不得把原编号改写成新内容（编号纪律：一编号一类别，内容实质变更须分配新编号）。

### 策略 F · 换等价刻画

**内容**：原表述不可写成类型 → 找**可写、且等价的**形式。

**适用判据**：
1. 原表述属于原因 3（写不成 Lean 类型）；
2. 存在一个候选刻画，它**可以用已定义的对象写出来**；
3. **等价性本身是一条待证命题**——这一条最容易被忘。

**Lean 落地**：

```lean
-- 原表述（写不成类型的典型）：「条件独立于给定 σ-代数」
--   理由：条件期望的核值在一般情形下不存在（除非正则条件概率存在）。
-- 候选刻画：用 Indep 与 comap，**完全避开核值**。

/-- 第一步：给出候选刻画的类型。 -/
def CondIndepAlt (μ : Measure Ω) (m₁ m₂ m₃ : MeasurableSpace Ω) : Prop :=
  ProbabilityTheory.Indep (MeasurableSpace.comap id m₁)
                          (MeasurableSpace.comap id m₂) (μ.trim (by sorry))

/-- 第二步：**证明等价性**。这一步是本策略的真正工作量，
    也是「换刻画」与「偷换概念」的分界线。 -/
theorem condIndep_iff_alt :
    CondIndep μ m₁ m₂ m₃ ↔ CondIndepAlt μ m₁ m₂ := by
  sorry
```

**本项目的真实先例（作为模板）**：`第167轮-根本性路线转折.md` 中代理 Z22 的做法——**不证 `bridgeStatement`，而换等价形式**，把「要算 `condExpKernel` 的核值 + 处理 `μ.trim hm'` 差异」的路线，替换为「只需证 `CondIndepFin → Indep (comap projX) (comap projY) μ`」。主控**核实了两个被引用的 Mathlib 引理确实存在**，并据此判定这是根本性的成本降低。**这是策略 F 的标准示范**，它同时展示了策略 F 的必要配套：**核实候选刻画所依赖的既有 API 确实存在**（`#check` 实测，不是凭记忆）。

**后果**：
- **可能失真**：新刻画也许**不等价**，只是**更弱**。此时必须按 B 或 C 处理（它其实是子类或部分结果），**不得挂在 F 名下**。
- 下游全部改用新刻画，旧刻画的引用点须逐个迁移——**这是 F 的主要工程量**。
- 定义层加入一条永久债务：**等价性定理**（如上 `condIndep_iff_alt`）。若它从未被证，F 就是一次未完成的转项——必须计入债务报表。

**反例/失败模式**：

> **失败模式 F-1（换成了同义反复）**：把「条件独立」重新定义为「满足某个看起来像条件独立的性质」，然后「证明」两者等价——两步都是定义，没有数学内容。**检查**：新刻画的定义体中**不得出现**旧概念的名字或其任何 API。
>
> **失败模式 F-2（等价性从未被证，却当作已换）**：这是 F 最常见的形态，且**极难被发现**，因为两种刻画在文本上「显然一样」。**唯一可靠的防御**：等价性定理必须**立即立项并分配编号**，且其状态进债务报表。**凡「显然等价」未立项者，一律当作未换。**
>
> **失败模式 F-3（依赖了不存在的 API）**：候选刻画用到了「记忆中存在」的 Mathlib 引理。本项目有实证：`00-总纲.md` §二 记录原文的成本数字无检索行为；`第120轮-查明sum_prod_type的import根因.md` 等案例显示 API 存在性与版本强相关。**规则：策略 F 的候选刻画，必须先 `#check` 实测其依赖的全部 API，并记录版本（`lean-toolchain` 为 `leanprover/lean4:v4.33.0-rc1`，非规格要求的正式版）。**
>
> **失败模式 F-4（该用 F 的时候用了 A）**：若「写不成类型」的原因只是**谓词未命名**（如「模型足够正确」），那不需要换刻画，只需**定义那个谓词**——但如果定义出来必然含任意阈值，则它其实是 G。**F 只在「原表述在数学上意义明确、只是语言层不适配」时适用**；表述本身含义不明时，F 只是把模糊从一处搬到另一处。

### 策略 G · 降为定义性约定

**内容**：承认这是**建模选择**而非事实。

**适用判据**：
1. 该陈述**没有真假可言**（是对记号/参数化方式的选择），或
2. 该陈述含**任意阈值**，且无独立依据确定其值，而**结论对该阈值不敏感**（或在给定阈值下是精确的）。

**Lean 落地**：

```lean
/-- 约定做成 `def`（或 `abbrev`），**不是 `theorem`**。
    这是本策略的核心：在类型层面就区分「选择」与「事实」。 -/
abbrev errorTolerance : ℝ := 0.05
-- 注意：这里**没有**也不应有 `theorem ; errorTolerance_optimal`

/-- 若结论确实依赖该约定，则定理把它作为**参数**而非常数——
    这样「结论对该约定敏感」在类型上是可见的。 -/
theorem decay_bound (ε : ℝ) (hε : 0 < ε) (hconv : ...) : ... := by sorry
```

**后果**：
- **失去「定理」地位**。这是**应有的**——它不是定理，是选择。
- 该选择**进入符号与方程规范**（本项目 `03-规范与裁决/04-符号与方程规范.md`），成为**全局约定**，此后不得在多处出现不同取值（否则是**同一符号两个含义**，属严重缺陷）。
- 登记表类别栏写「定义性约定」，且「前件如何确认」栏写「**不需确认，是选择**」——这是项目已确立的格式（`04-假设登记.md` §1.2 表）。

**反例/失败模式**：

> **失败模式 G-1（用 G 掩盖实质假命题）**：命题「误差界是 0.05」为假（或未验证），于是把它改称「约定」——**这不是约定，是把假话改名为规定**。**判据**：约定必须是**关于记号/参数化方式**的选择；若它是关于真实世界量的断言，它是原因 4，须走 E 类登记。
>
> **失败模式 G-2（约定不断增殖，无人总账）**：每条命题自带一个阈值约定。最终生成系统有 30 个互不一致的「可接受」。**防御**：全部约定必须集中在符号规范一份文件，且**同一量只有一个约定**（本项目 `多路线台账.md` 的「噪声尺度」是正面样板：裁决 K 把误差判据统一到噪声尺度，使多条路线共用同一口径）。
>
> **失败模式 G-3（该用 G 的时候用了 A）**：把「我选了决策损失作主量纲」写成条件定理的前件 `H := 量纲是决策损失`。这是**把选择伪装成前提**——它在形式上合规，但前件永远为真（因为它是我们的定义），于是定理恒真。**检查**：前件的类别栏若为「定义性约定」，则它**不应出现在前件中**，而应出现在**定理参数的默认值**里。

### 策略 H · 登记为开放问题

**内容**：诚实挂账。

**适用判据**：**以上 A–G 全部不适用时的兜底**。具体地：困难不可定位到单一前提（否则 A），不成立子类无自然边界（否则 B），目标量连区间都不可约束（否则 C），无反例也无正例（否则 D），无复杂度模型（否则 E），表述精确但语言不适配的问题不存在（否则 F/G）。

**Lean 落地**：开放问题**不写成 Lean 声明**——写进去就必须给证明，那是撒谎。落地方式是：

1. **理论侧**：在主文档第 8 章的开放问题表（`O<n>.<m>`，本项目已用 O8.1–O8.18、O5.3 等编号）中分配编号；
2. **证明侧**：在定理清单中把该条目标为 `[开放问题]`，并把**结论**栏写成「当前无法陈述该命题，原因见 O<n>.<m>」；
3. **台账侧**：在债务台账的「已登记为裁决项」中写一条，附三要素。

**三要素（缺一即挂账不完整）**：

```text
① 卡在哪一步（精确到引理/定义，不是「整条不会」）
② 已排除的可能方向（附证据：检索记录、已证否的子命题编号）
③ 解除条件（什么事实成立后此问题可解；或「解除条件本身是开放问题」，则写明）
```

**后果**：
- **理论完整性得到保全**：读者知道哪一条是空的。
- **风险是真实的**：「挂账即遗忘」。本项目的实证是 `债务清账台账.md` 的建立动因——**作者指令「一切需要处理的都处理，不留一切债务」**，台账纪律要求每项必须是「已清 / 已登记为裁决项 / 已明确不可做」三种终态之一，**禁止「进行中」「待办」「后续处理」这类无归属状态**。

**反例/失败模式**：

> **失败模式 H-1（挂账即遗忘）**：登记之后无人再读。**防御**是 §三 纪律 7 的债务增量报表 + 每条挂账必须带**复核触发条件**（「当 X 完成时复核本条」），使其进入自动检查的范围。
>
> **失败模式 H-2（把原因 1/7 挂成开放问题）**：**已知为假**或**已知只在子类成立**的命题，挂为「开放问题」是**最坏的逃避**：它把「已经知道的事」伪装成「还不知道的事」，从而**永久阻止**了证伪带来的路线关闭。**检查**：任何 `[开放问题]` 标记前，必须先证明「已尝试证伪且无反例」——把这个尝试写成一段带日期的记录。
>
> **失败模式 H-3（挂账代替分层，无「卡在哪」）**：只写「该问题未解决」。这是无信息挂账。**检查脚本**：每条 O 编号必须匹配三要素的正则模式，否则退回。

### 2.y 策略的不可逆性排序（谁该最后用）

| 策略 | 可逆性 | 说明 |
|---|---|---|
| D | **最高** | 证伪是永久关闭，不会反转（除非反例本身错） |
| F | 高 | 换刻画可换回，只要等价性没丢 |
| B | 中高 | 收口可再放宽，代价是重做证明 |
| C | 中 | 从区间回到点值需新数据或新结构假设 |
| A | 中 | 前件可被后续证明消去（A15→T0.2 即此） |
| E | 中低 | 复杂度结果难以反向供给构造 |
| G | **低** | 约定一旦全局化，改动牵动整个系统（本项目符号规范被冻结正是为此） |

**用法**：当多个策略同时适用时，**优先选不可逆性高的**。理由：不可逆性高的策略**缩减了未来的可能状态数**，而可逆性低的策略**只是把状态数维持了下去**。在成本相同的情况下，减少不确定性优于推迟不确定性——这是 §〇「转项使不知道的东西变小」的直接推论。

## 第三部分 · 转项的纪律（防止转项变成逃避）

**七条禁止性规则。每条给出：为什么需要（动机，最好有本项目实例）/ 违反后果 / 机械检查。**

**贯穿全节的一个观察**：**Lean 的类型检查器能拦住的，只是纪律的一小部分。** 下面七条中，只有第 2、3 条能被编译器强度地拦住；其余五条必须靠**外部脚本 + 台账流程**。**因此「Lean 说没问题」绝不等于「转项合规」。**这是本文件最重要的一条工程判断。

### 纪律 1 · 不得把结论写进前件（同义反复）

**为什么需要**：这是最自然、最难自查的失败。当你证明不了 `C` 时，把 `C` 稍微改写成一个「前提」，就能立刻 `intro h; exact h`。**Lean 完全接受它，而且它在库里看起来像一条正经定理。**

本项目已有相应的检查传统：工作区中存在 `check-tautology.ps1`、`_rewrite_tautology.ps1`、`_audit_vacuous.ps1` 等脚本，说明这类问题已被认识到——**本纪律的作用是把它从「事后审计」提前到「转项时禁止」。**

**违反后果**：
- 定理集变大，**信息量为零**。
- 更坏的：**它使真实的缺口从视野中消失**——因为「这条已经证了」，于是没人再去找桥。
- 若它在链中被多次使用，会形成**「循环前件」的变体**：`A → B → A` 被拆成两条「条件定理」，形式上无环（因为中间隔了蕴含），语义上是环。

**机械检查（三步）**：

1. **量词/自由变量检查**：`C` 中出现的全部自由变量，**必须**在前件 `H` 中同样自由出现。若 `H` 引入了一个 `C` 中不出现的新参数，则 `H` 只是把 `C` 的论域缩小了——这不是 A，是 B（须走 B 的登记）。

```lean
-- 违规形态：
theorem bad1 (h : ∀ x, P x) : P x := h x
-- 检查结果：`h` 的自由变量集 ⊇ C 的自由变量集且**恰好相等**，
-- 但 `h` 的**逻辑内容蕴含** `C`（`∀x, P x` 强于 `P x`）。→ 违规

-- 合规形态：
theorem good1 (h : LipschitzWith L f) (hx : ‖x‖ ≤ R)
    : ‖f x - f 0‖ ≤ L * R := by sorry
-- `h` 与结论互不蕴含：Lipschitz 不说 x 的范围，x 的范围不说 f 的伸缩。
```

2. **归约检查**：若 `H` 在**去掉某个子句**后仍能推出 `C`，则该子句是**装饰**，`H` 有冗余（未必违规，但说明它在掩盖真正的困难）。
3. **替换检查**：把 `C` 逐字代入 `H` 中对应的谓词位置，若 `H` 变成恒真，**违规**。

**脚本化（可编译、不含 sorry）**：见 §八 的 `check_tautology.lean` 与 `check-tautology.ps1` 的对接说明。

### 纪律 2 · 不得用 `sorry` / `axiom` 掩盖

**为什么需要**：`sorry` 使文件编译通过而命题未证；`axiom` 更强——它**把未经证明的断言永久注入环境**，此后任何基于它的定理都只是**条件地**成立，但库里看不出条件在哪。

**违反后果**：
- **`sorry`**：编译通过 → 构建"绿" → 进度报告把条目计入完成。项目的 `count-sorry.py`、`count-sorry2.py`、`exact-sorry.py`、`find-sorry.py` 的存在说明这是持续发生的。
- **`axiom`**：比 `sorry` **更危险**，因为它是**可传递的**——一条 `axiom` 会污染所有下游证明，且随被引用次数扩散。而 `sorry` 是局部的。
- 本项目的正确做法已确立：待证命题应有**具名前件**，而不是 `axiom`。`04-假设登记.md` §1.2 明写「待证命题」的 Lean 体现是「一个尚缺证明的 `theorem`（**或以 `axiom` 暂列并登记**）」——**注意「并登记」是强制条件**，不是可选的。

**机械检查**：

| 对象 | 检查方法 | 通过条件 |
|---|---|---|
| `sorry` | 全库正则 `\bsorry\b`（**须排除注释与字符串**） | 出现次数进入债务报表；**任何进入「验收通过」统计的条目不得含 `sorry`** |
| `axiom` | `grep -n '^\s*axiom\b'` + `#print axioms <name>` | 每一条必须有 A/E 编号登记 |
| 传递污染 | 对关键结论 `#print axioms Foo` | 输出只含 `Classical.choice`/`propext`/`quot.sound` 与已登记公理 |

```lean
-- 关键：用 #print axioms 做传递检查。这是唯一能看见 axiom 扩散的手段。
#print axioms Fate.Core.bridgeStatement
-- 期望输出：'Fate.Core.bridgeStatement' depends on axioms: [propext, Classical.choice, ...]
-- 若出现非标准公理名，说明有 axiom 被引入，须核对登记表。
```

**本项目的一条特别提醒**：`count-sorry.py` 之类的脚本**未必能排除注释中的 sorry**、也未必区分 `sorry` 与 `sorryAx`。**报告数字前必须抽验 3 处**，否则「sorry 数 = 0」可能是脚本缺陷而非真实状态。这类「检查器自身的 bug」在本项目有先例（`第112轮-检查11与其自身bug.md`）——**检查器的正确性与被检查对象的正确性同等重要**。

### 纪律 3 · 前件必须可写成 Lean 类型

**为什么需要**：前件若不可写成类型，那么「条件定理」只是一句自然语言，它既不能被证明也不能被误用，**而它会占据一条编号、一个难度档位、一份工作量**，使统计失真。

本项目已把这条写进上位规范（`04-假设登记.md` §1.4「一条纪律」）：**「不得把前件不可写成 Lean 类型的条目登记为条件定理」**，且处置明确——「只能降为经验假设并登记，不得以含糊语言伪装成一条条件定理」。**本纪律是它的操作化。**

**违反后果**：
- 定理清单的条目数与真实工作量**脱钩**。
- 最难看的后果：这类前件在**实验侧**也无法确认（因为实验需要判据），于是它**既不能证也不能测**——它是全项目唯一的「绝对死结」形态。
- 本项目已确认的实例：「可接受的误差界」（`O8.2`）——`02-定理清单.md` §1.2 明写「本清单**不为它立任何定理**」。这是正确的处置，本纪律要求把它推广为默认反应。

**机械检查（两条，第二条更常见）**：

1. **可写性检查**：前件谓词在 Lean 中能给出 `def`/`structure`/`class` 声明，且 `#check` 通过。
2. ****可实例化检查**（易漏）**：类型写得出来，但**没有任何对象满足它**。「能写类型 ≠ 有对象」。检查方法：给出至少一个具体见证，或在登记里明说「当前无已知实例」。前者的例子：

```lean
-- 前件类型合法，但须给出实例：
structure ReasonableTolerance (ε : ℝ) : Prop where
  pos : 0 < ε
  bounded : ε ≤ 1

-- 实例（否则该前件是空中楼阁）：
example : ReasonableTolerance 0.05 := ⟨by norm_num, by norm_num⟩
```

**若两个检查都通过但实例是「拍脑袋选的」**，则它其实是 G 类（定义性约定）——**前件的类别标签必须写对**（见失败模式 G-3）。

### 纪律 4 · 降级必须登记（否则等于删除）

**为什么需要**：转项在 Lean 中往往是**完全静默的**。把 `theorem foo (x : ℝ) : P x` 改成 `theorem foo [Fintype V] (x : ℝ) : P x`，加了三个字符，**编译器一声不响，下游一声不响，而可证性从不可证变成可证**。**这类改动如果没有登记，就等于把命题删了，还留着它的名字。**

本项目的制度基础：**「本表是唯一的假设总账」**（`04-假设登记.md` §1.1 第 3 条），且 `E` 编号是**视图**，不得构成第二套体系——这正是为了防止「同一前件在五处写法不同、登记三处、漏两处」。

**违反后果**：
- **重复计数**：同一假设被登记为两条不同的 A 编号，于是「假设总数」虚高，而真实缺口被稀释。
- **静默弱化**：见上。
- **反向污染**：日后若要撤销某降级，**找不到全部受影响点**。

**机械检查（三条，按强度递增）**：

1. **编号唯一性**：任何前件谓词在登记表中**恰好出现一次**（作为 A/E 编号的「内容」栏），其余出现均为引用。
2. **登记完整性**：每条 A/E 编号的**六个字段齐全**（`04-假设登记.md` §1.3）。脚本可直接检查表格列数非空。
3. **签名漂移检查（最强，强烈建议落地）**：保存每条定理的**签名哈希**，每轮与基线比对；**签名变化即视为降级候选**，必须附说明。

```lean
-- 签名快照的落地方式：本项目已有 SigCheck.lean 与「签名冻结」机制（`00-签名冻结.md`，版本 SIG-0.1.0）。
-- 做法：把待检定理的名字列成表，用 #check 输出签名，规范化后取哈希。
#check @Fate.T1A.alpha
#check @Fate.Core.bridgeStatement
-- 与冻结基线比对：任何 **签名文本** 变化（不只是名字变化）都必须有裁决记录。
```

**本纪律最重要的落地形态**：**把降级做成显式的「名字」而不是隐式的「签名」**。即：降级后的定理**换名**（加 `_under_A19` 之类后缀），使下游引用**必然**需要人工改动。这与本文件 §四 的决策树配合，是唯一能保证「降级可见」的结构性手段。

### 纪律 5 · 「不可判定」与「不知道」必须分清

**为什么需要**：二者在语言上都是「证不出来」，但**对策相反**：不可判定 → 永久挂账（H）；不知道 → 立刻去查/去构造。**混淆的代价是把可做的事永久封存。**

**违反后果**：
- 把「尚未检索」标为「不可判定」，于是**永远不去检索**。
- 把「已知无方法」当成「还没试」，于是**反复重启已经失败过的路线**。本项目的实证是反复出现的「倒退」轮次（第104、114 轮等），其诊断文档明写要追到根因——**反复倒退的一个结构性原因是：路线关闭的决定没有以「终态」记录，所以下一轮又打开了它。**
- 最严重的一种：**把「循环前件」当成「不可判定」**。本项目的现成案例是 **A30**：`02-定理清单.md` T9.6 已定位——A30 写「收敛性分析的数学前提……**在使用处成立**」，而「使用处」正是引用收敛定理之处。**这是一条假定结论所需前提的循环前件。** 它**不是**不可判定，它是**待证的桥**（破环路线：从 $f$ 与 $\mathcal{D}_\varepsilon$ 推出三条件）。若误判为不可判定，则会永久放弃一条可破的环。

**机械检查（判定表，必须逐条填，不许跳过）**：

| 问题 | 若答「是」 | 若答「否」 |
|---|---|---|
| 已归约到某已知独立命题并证了等价？ | 原因 2（H） | 不是原因 2 |
| 已完成检索且记录了检索行为？ | 倾向原因 6 | **元层误分类**，先做检索 |
| 依赖链上每个符号 `#check` 存在？ | 继续 | **原因 5**（桥缺失） |
| 前件中有循环（`A` 的证明用到「A 在使用处成立」）？ | **不是不可判定，是桥** | 继续 |
| 已尝试证伪且无反例（有记录）？ | 倾向原因 6 | 先做证伪（原因 1/7） |
| 能在可数模型/力迫扩张中翻转真假？ | 原因 2 | 不是原因 2 |

**并把判定结果写进登记**：`02-定理清单.md` 已有 `[开放问题]` 与 `[不可评估]` 两个标签，但**它们未区分原因 2 与原因 6**。建议新增第三列（原因码），使「不可判定」一词**在库中不再作为自由文本存在**。

### 纪律 6 · 负结果也是结果（证伪优于含糊）

**为什么需要**：组织行为上，「证伪」看起来像失败（「这条没证出来」），「在假设下成立」看起来像成功。**这个激励结构会系统性地把团队推向策略 A/G，远离策略 D。** 而 D 恰恰是唯一能**减少**未来工作量的策略。

本项目的正确表述已存在：「`04-假设登记.md`」对 A25 明写「**若界不存在，则产出否命题 $\textsf{B}_1$、$\textsf{B}_2$、$\textsf{B}_4$，同样构成 A25 的闭合**」。**这是本纪律的权威依据，本文件只是把它从「A25 一条」推广为「全部条目」。**

**违反后果**：
- 假命题以「条件定理」的形式长期存活（失败模式 D-2）。
- 工作量无法回收：一条已证伪的路线，其全部下游条目应当关闭；未关闭则继续消耗。
- 统计失真：负结果不计入成果，于是「已完成」数低估，而**「在假设下成立」数高估**，两者叠加产生乐观偏差。

**机械检查**：

1. **每个条目必须有终态**，取值域为「已证 / 已证否 / 条件可证 / 登记为裁决项 / 明确不可做」——即 `债务清账台账.md` 的三终态加上证明侧的两个。**禁止「进行中」「待办」**（项目已有明文）。
2. **负责字段**：每条负结果必须有「受影响的引用者」字段，列出所有需改判的下游条目。**空列表也要写 `—`**，表示已检查过。
3. **注销检查**：证伪一条命题后，全局搜索该名字的引用：

```powershell
# 简化示意。项目内已有同类脚本（check-orphans.ps1、verify-ax.sh 等）。
Select-String -Path "命运\**\*.lean" -Pattern "foo_monotone" -SimpleMatch
# 期望：命中集合 ⊆ 登记中「受影响引用者」字段
```

**一条反向纪律**：**不得为了「有负结果」而证伪平凡命题**（如证伪一条没人用的、显然错的陈述）。负结果的价值在于**关闭一条有人走过或有成本的路线**。空转的证伪只增加条目数。

### 纪律 7 · 每轮必须报告债务增量（防挂账遗忘）

**为什么需要**：前六条都是**静态**的（某一刻的转项是否合规）。只有这条是**动态**的：它防止「每一轮都合规，但总量失控」。

本项目的直接动因是 `债务清账台账.md` 的建立——作者指令「一切需要处理的都处理，不留一切债务」。**但台账只要求「终态」，不要求「增量」**：一份台账可以是「全部项都有终态」而同时「每轮新增 30 项债务」。**纪律 7 补的正是这个缺口。**

**违反后果**：
- 债务按轮次线性增长而无人知晓，直到某一轮突然发现「有 200 条挂账」。
- 「挂账即遗忘」的制度化（失败模式 H-1）。
- 进度指标（已证条数）上升而真实缺口同时扩大——**两个数字都在涨，没人发现它们不是同一件事**。

**机械检查（每轮必出，四张表）**：

```text
表一：债务增量表（本轮新增 / 减少）
  | 编号 | 类型（A/E/O/T9） | 动作（新增/消去/降级/改判） | 原因码（1–8） | 策略（A–H） | 复核触发条件 |

表二：策略使用分布
  | 策略 | 本轮使用次数 | 其中「不可逆性高」的占比 |
  → 警戒：若 A+G+H 占比 > 60%，说明本轮主要在推迟而非解决。

表三：前件密度
  → 每条已证定理的**前件个数**
  → 警戒：若某定理的前件数 ≥ 5，它实质上是「把 5 个问题打包成 1 个」，须拆分或说明。

表四：sorry / axiom 计数（分文件），含**抽查 3 处**的核对记录。
```

**表二的阈值 60% 是本文件给出的唯一硬数字，理由**：A/G/H 都是**低不可逆性**策略（§2.y）。若一轮中这三种占多数，则该轮在数学上几乎无进展，而只在**形式上**有进展。**这个阈值不需要精确**——它是"触发复核"的信号，而非"判定违规"的判决。

**关于纪律 7 的一个诚实提醒**：**报表本身会变成新的逃避形式**——「表都填了」的感觉会替代「问题都解决了」的感觉。**防御**：报表的每一行必须能被**第三人复核**（编号可查、结论可编译、引用可定位）。**不可复核的报表行等同于无该项。**

## 第四部分 · 转向的优先级（决策树）

### 4.1 主决策树

**读法**：从根向下，**每次只问一个问题**；一旦命中叶子，**立即停止**（不要再往下问）。**顺序即优先级，不可重排。**

```text
命题 P 不可证
│
├─ ⓪ 【元层闸门】P 的编号唯一、陈述已逐字核对、依赖链全部 #check 通过、
│     无循环前件、检索行为有记录？
│     │
│     └─ 否 → 【禁止一切转项】→ 退回补分类（元层误分类）
│
├─ ① P 为假？（已构造出满足全部前提的反例）
│     └─ 是 → 策略 D：证伪（最干净，永久关闭一条路线）
│           （同时登记「受影响引用者」清单）
│
├─ ② P 只对子类成立？（一般情形已证否，且子类由失效点自然界定）
│     └─ 是 → 策略 B：缩类（子类谓词须非空、非退化、具名）
│
├─ ③ P 的困难在中间对象缺失？（沿链找到第一个 unknown identifier）
│     └─ 是 → 策略 A + 补桥：先立定义条目，再写「桥性质 → 结论」的条件定理
│           （本项目的头号桥：A32 的尺度化算子 ς）
│
├─ ④ P 需要不可得的数据？（目标量不可由观测唯一确定，但可被界约束）
│     └─ 是 → 策略 C：部分识别（界须有限、非平凡、且只依赖可观测类型）
│
├─ ⑤ P 的表述不精确？（写出类型骨架后 Lean 报 unknown identifier）
│     └─ 是 → 策略 F（换等价刻画，等价性须立即立项）
│           或 策略 G（降为定义性约定，若确实无真假可言）
│           （分支：谓词未命名 → 定义它；若定义必含任意阈值 → G）
│
├─ ⑥ P 的困难是「有方法但工作量巨大」？（检索有记录，方法已知）
│     └─ 是 → 策略 A（把中间结论做成条件定理）+ 策略 E（先证受限版/复杂度版）
│           （T3.11 属此分支：分段处理，不得单点降级）
│
├─ ⑦ P 的困难是「无已知方法」？（检索有记录，且无构造、无下界）
│     └─ 是 → 策略 H：开放问题 + 写清三要素（卡在哪 / 已排除方向 / 解除条件）
│
└─ ⑧ 以上都不行
      └─ → 这通常意味着 ⓪ 没通过，或问题实际落在 ③⑤ 之间的灰区。
          回到 ⓪ 复核；若复核通过而仍无解，登记 H **并明确标注「分类未定」**
          （不得伪装成 ⑥ 或 ⑦）。
```

### 4.2 决策树的三条使用纪律

1. **顺序即证据**：能否往下走一步，取决于**当前这一步的证据是否齐备**。①需要反例，②需要反例 + 失效点，③需要 `#check` 结果，以上**都没有「我觉得」的位置**。
2. **命中即停**：**不允许「多重转项」**（先 B 再 A 再 G）。若确需复合，必须拆成**两轮**，每轮各出一次债务报表。理由：复合转项是**逃避的最佳掩护**——读者只能看到最终形态，看不到中间丢了什么。
3. **「不知道哪个分支」是合法状态**，且**它属于 ⓪**（分类未完成），不属于 ⑧。**把它写成 ⑦（开放问题）是本决策树要禁止的头号行为。**

### 4.3 何时「不该转」

**有一条分支不在树里，但必须单列：**

| 情形 | 处置 |
|---|---|
| 命题**目前不可证**，但**预期在 ≤ 一次迭代内可证**（如缺一个已知可查的 API） | **不转项**。转项的成本（登记、改名、下游迁移）高于等待 |
| 命题虽不可证，但**没有任何下游依赖它** | **不转项，登记为 H 并标注「无下游」**。转项的资源应投入有依赖链的条目 |
| 命题的不可证性**源于一个尚未决定的建模选择**（如误差量纲未定） | **不转项，先裁决**（本项目 `05-误差界路线.md` §1.1「不定量纲则全部无从谈起」即是此规） |
| 命题是**外部既有结果**（`[已知]`），本框架内无法证 | **这不是「不可证」，这是 T9.x 适配层**。转项对象是**适配性命题**，不是原命题 |

**最后一行值得强调**：项目已有 35 条 `[已知]` 条目，清单的正确判定是「**它们省下的是「证明 R 本身」的工作，但必须付出「证明 T9.x」的工作**」。**把 `[已知]` 当作「已证」是本项目已记录的最大的单点误判**（`02-定理清单.md` §5.1）。**策略上，`[已知]` 条目的转项对象永远是 T9.x，而不是原命题。**

## 第五部分 · 在本项目语境下的具体建议

**8 条，每条给出：目标条目 / 原因码 / 策略 / 落地物 / 验收。**

> **优先级排序依据**：① 是否在**有下游依赖**的链上；② 是否**低成本**（Mathlib 覆盖、组合事实 vs 外部理论）；③ 是否**能立刻关闭一条路线**。
>
> **本文件不给年数估计**，只用项目的相对档位。

### 建议 1（最高优先）：先把「元层分类」做成可机械执行的闸门

- **目标**：全部条目，尤其是将被判为原因 6 的。
- **原因码**：元层误分类。
- **为什么最高**：§1.3 已论证——本项目最贵的问题不是数学困难，而是**把非数学问题当成数学困难**。而「①–⑧」八个原因里，⑦（开放问题）是全项目最容易滥用的出口。**先装闸门，再谈转项**，否则后面七条建议都会把错误判断固化为永久债务。
- **落地物**：
  1. `check_turnable.ps1`（或并入既有 `一键验收.ps1`）：对每个拟转项条目检查——编号唯一性、陈述与理论原文档逐字比对、`#check` 全部依赖符号、前件无环、检索记录存在。
  2. 定理清单新增**「原因码」列**（取值 1–8 + 「元层」）。
- **验收**：任一条目标「拟转项」时，闸门脚本返回 0；否则拒绝转项并输出缺哪一项证据。

### 建议 2：把 FCA 的「闭集指数爆炸」做成一条复杂度定理（上界型）

- **目标**：新条目（建议编号续 T8 层）。
- **原因码**：6（原命题「FCA 能作入口」在无界属性数下不成立）。
- **策略**：**E（复杂度结果）+ D（负结果）的复合**，但**分两轮**（依 §4.2 纪律 2）。
- **为什么值得**：`多路线台账.md` 已实测出结构性事实——**属性数 $= k \times d$（线性），闭集枚举是属性数的指数**，因此「提高分辨率必然导致格爆炸……**这是结构性事实，换机器只改常数**」。**这条事实目前只是台账里的一句文字，它应当是一条组合定理。** 它难度低（纯组合）、不依赖任何外部理论、Mathlib 的有限集合基数 API 齐备，且**一旦证出，就永久关闭「靠换编码方案绕过爆炸」这一整类尝试**（台账已有 6 方案 × 3 规模 × 7 分辨率的实测支撑，数学证明与实测互相印证）。
- **落地物**：

```lean
/-- 上界型：形式背景的概念数不超过对象集的幂集。 -/
theorem concept_count_le (hG : Fintype G) :
    Fintype.card (Concept G M) ≤ 2 ^ Fintype.card G := by sorry

/-- 紧性型：存在实例达到上界（否则上界无信息，见失败模式 E-2）。 -/
theorem concept_count_attained :
    ∃ (G M : Type) (_ : Fintype G) (_ : Fintype M) (I : G → M → Prop),
      Fintype.card (Concept G M) = 2 ^ Fintype.card G := by sorry
```

- **验收**：两条都编译通过；在债务报表的「策略使用分布」中计为 D+E。

### 建议 3：T3.11（do-calculus 完备性）用「分段条件定理」处理，**不做单点降级**

- **目标**：T3.11。
- **原因码**：6（难度 = ≥20 条前置依赖的汇合；不是单点缺口）。
- **策略**：**A 的复合形态**——按前置依赖组**分段**，每段一条条件定理；段的边界由 `#check` 实测决定。
- **为什么不能单点降级**：详见失败模式 A-3。若写 `H := 三条规则足以改写一切可识别表达式`，前件就是结论。
- **具体分段**（依清单 §七 的四组前提）：

| 段 | 内容 | 前件类型 | 可独立立项 |
|---|---|---|---|
| ① | d-分离可判定（T2.1–T2.2） | 无前件（①类） | 是，已是独立条目 |
| ② | 识别性的**类型化定义**（T3.14） | 无前件 | 是，已是独立条目 |
| ③ | 三条规则可靠性（T3.8–T3.10） | A19 | 是，已是独立条目 |
| ④ | **完备性本体** | ①②③ 全部成立 + **正规形存在性** | 注意：这一段的「正规形存在性」是真正的新缺口，须单独命名 |

- **关键动作**：**把「hedge/正规形」提升为一个具名定义条目**（D 编号），并让 ④ 的前件引用它。**这一步把弥散的困难收敛成一个可定位的对象**——从原因 6 变成原因 5（桥缺失），从而可用 A+补桥处理。**这是本建议的全部价值。**
- **验收**：④ 的前件中每一项都能 `#check` 且被登记；④ 的陈述在去掉任一前件后**不可证**（给出反例或说明）。

### 建议 4：A30 的循环前件必须**破环**，而不是转项

- **目标**：A30 / T9.6。
- **原因码**：**不是原因 2，是原因 5 的变体（循环桥）**。
- **策略**：**不做任何 A–H 转项**。理由是——它看起来像「需要假定前件」，实际是「前件可从已有对象推出」。清单已给出破环路线：**从 $f$ 与 $\mathcal{D}_\varepsilon$ 推出遍历性三条件**。且登记表已指出「**三条件中两条可直接检验**（不可约、非周期），确认成本低」。
- **落地物**：

```lean
/-- 破环：不假定三条件，而从转移核的性质推出。 -/
theorem ergodicity_conditions_from_transition
    (P : Kernel Χ Χ) (hP : IsMarkovKernel P)
    (h : TransitionInducedBy P f Dε)        -- 桥：P 由 f 与 Dε 诱导
    (hirr : Irreducible P) (haper : Aperiodic P)   -- 两条**可检验**的前件
    : Ergodic P := by sorry
```

- **为什么这条值得单列**：「循环前件」是全项目最隐蔽的结构缺陷——它在形式上是一条正常的前件，在语义上是 `C → C`。**而它甚至通过了纪律 1 的朴素检查**（因为中间隔了两次引用）。**唯一可靠的检测手段是画依赖图找环**，这正是清单 §1.3「依赖不得成环」规则的实际用途：**该规则不是格式要求，是防止循环前件的主要工具。**
- **验收**：A30 在登记表中由「待证命题（循环前件）」改为「待证命题（破环路线：−）」，且破环路线写成具名定理。

### 建议 5：编码损失（A32 / E8）用「定义条目 + 桥性质前件」，并把 $\varsigma$ 立起来

- **目标**：A32、E8。
- **原因码**：**5（桥缺失）**，教科书型。
- **策略**：**A + 补桥**。
- **具体做法**（三步，独立可交付）：
  1. **立 D 编号**：$\varsigma$ 的 Lean `def`（哪怕值域暂为 `sorry`）。**这一步单独就有价值**：它把「未分析」变成「已定义但未实现」。本项目已用同一手法处理过 A17/A28 类问题（把约定写成 `def`）。
  2. **写前件**：`hcover`（逆向包含）+ `hgap`（阈值非退化）。**每条都能单独证伪**。
  3. **写条件定理**：`hcover → hgap → dist x (ς⁻¹(ς x)) ≤ g γ`。
- **反例防护**：见失败模式 A-5——$\varsigma$ 必须对**两个不同输入产出不同输出**，否则前件自动成立、定理空洞。**建议：把这条做成一个 `example` 断言**：

```lean
-- 防空壳测试：桥必须有区分力。若此例无法提供见证，则 ς 是空壳。
example : ∃ x y : Χ, scaleOp 0.1 (by norm_num) x ≠ scaleOp 0.1 (by norm_num) y := by sorry
```

- **验收**：三步各自的条目都在清单中；`example` 有见证（或登记为「当前无见证，$\varsigma$ 视为未定义」）。

### 建议 6：反事实与真实因果图，一律走「部分识别（C）」+「图距敏感性（A）」，不走「假定已知」

- **目标**：E6（外生可识别）、E10（A19 因果图已知）、T4.x、E4（结构误差）。
- **原因码**：8（数据不可得）+ 4（经验假设）。
- **策略**：**C 为主，A 为辅；把「已知」换成「距真图的界」**。
- **为什么**：`04-假设登记.md` 把 E10 的确认成本判为**「极高（须走完整个因果发现流程）」**，把 E6/E14 判为**「不可直接检验」**。**对「确认成本极高或不可直接检验」的经验假设，策略 A 的条件定理是空的**——因为前件永远无法被确认，条件定理永远不可用。**这类前件必须被替换为可测量的量。**
- **具体做法**：
  - **A19（图已知）→ 改为图距**：不写 `h : G = G₀`，写 `h : dist G G₀ ≤ Δ`，结论给 $g(\Delta)$。清单的拟命题 $\textsf{E}_4$ 已是此形式，**应把它从「拟命题」提升为立项条目**，因为它是全项目中**第一个把「不可检验前件」转成「可测量量」的实例**。
  - **A23（外生可识别）→ 改为识别区间**：不假定 $\delta$，而是让 $\delta$ 由群体版反事实的**识别区间宽度** witness（`05-误差界路线.md` §E7 已给出这条分析）。**关键**：$\delta \le$ width 是**证据**不是证明，必须在登记中保持这个措辞。
- **反例防护**：见失败模式 C-2——界的签名中不得出现 SCM 的隐藏字段。Lean 的 `lower : Obs → ℝ` 签名天然拦住这一点，**但若把 `Obs` 定义为含隐藏字段的大结构体，则拦不住**。**检查：`Obs` 类型中不得有 `exogenous`/`u`/`structuralEq` 之类字段。**

### 建议 7：外部既有结果（35 条 `[已知]`）的转项对象是 **T9.x 适配层**，不是原命题

- **目标**：T9.1–T9.9。
- **原因码**：**不属于 1–8**（这是 §4.3 第四行的情形）。
- **策略**：**F（换等价刻画）的实例**——把「引用外部结果」转成「证明本框架的对象与外部对象同构/等价」。
- **为什么**：清单已明判：「**本清单对「适配层」的评价是：它是本路线中被原文完全遗漏、但在实施上必然最先遇到的一层。**」而 §5.2 明写 8 项「已证」**无一例外全部是外部已证、本框架内零证明**。**所以转项的正确对象永远是 T9.x。** 把 T9.x 当作「附带工作」是路径最依赖的误判。
- **优先落地三个**（清单自己判定「难度最低、优先级最高」的）：**T9.1**（形式背景类型同构）、**T9.3**（四个删边图记号定义一致）、**T9.7**（四条经验假设的定义一致性）。它们的成本主要在**逐字核对**而非数学创造，但**不核对则后续全部工作建立在未验证的接口上**。
- **反例防护**：见失败模式 F-3。**T9.x 的每一步都必须 `#check` 实测 Mathlib 侧 API**，且记录 `lean-toolchain`（本项目为 `v4.33.0-rc1`，**非规格要求的正式版**——这本身是一条必须随每份验证记录携带的限定条件）。
- **验收**：T9.1/T9.3/T9.7 各有 Lean 陈述（可以是 `theorem ... : Prop := sorry` 的形式，但**必须在线**），并在清单中由「待证」标为「已立项」。

### 建议 8：所有「可接受」「合理」「足够」类谓词，一次性做「G 化裁定」

- **目标**：全库的自然语言谓词（O8.2「可接受的误差界」、A21「规则长度一致有界」、各处「合理条件」）。
- **原因码**：3（表述不精确）。
- **策略**：**F 或 G，逐条二选一，不允许第三条路**。
- **具体做法**（一次性清点，逐条裁定）：

|---|---|
| 无真假可言（是建模选择） | **G**：写成 `def`，进符号规范，全局唯一值 |

## 第六部分 · 附录：机械检查脚本

**本节代码的定位**：**可编译、不含 `sorry`、不证明任何数学**。它们只做语法分析与命名空间枚举。**把它们当作纪律的可执行部分，而不是数学成果。**

### 6.1 Lean 侧：`Fate/TurnCheck.lean`（建议路径）

```lean
import Lean

/-!
# 转项合规检查器（语法层，不含 sorry，不证数学）

用途：对指定的定理名做四项检查：
  1. 该定理的**前件个数**（用于 §三 纪律 7 表三「前件密度」）
  2. 前件是否为**匿名的**（应为具名 Prop/结构体，见 §二 策略 A 写法纪律）
  3. 是否依赖 `sorryAx`（用于 §三 纪律 2）
  4. 是否依赖非标准公理

用法：
  lake env lean Fate/TurnCheck.lean -- 目标1 目标2 ...
或在 Provider 内调用 `TurnCheck.check "Fate.Core.bridgeStatement"`。
-/

open Lean Elab Command

namespace TurnCheck

/-- 收集一条定理的显式前件（`Arrow`）个数。
    注意：这**只是语法计数**，不理解语义，故 §三 纪律 1 不能用它替代人工/脚本的蕴含检查。 -/
def countBinders (type : Expr) : Nat :=
  let rec go (e : Expr) (acc : Nat) : Nat :=
    match e with
    | .forallE _ _ body _ => go body (acc + 1)
    | _ => acc
  go type 0

/-- 返回目标名的 (名字, 前件个数, 是否含 sorryAx)。 -/
def inspectConst (env : Environment) (name : Name) : IO (Name × Nat × Bool) := do
  match env.find? name with
  | none => throw <| IO.userError s!"未找到常量: {name}"
  | some ci =>
    let n := countBinders ci.type
    -- `sorryAx` 的传递依赖须用 `#print axioms` 检查；
    -- 此处只做**直接**依赖的廉价检查，作为粗筛。
    let hasSorry := ci.type.getUsedConstants.contains ``sorryAx
    pure (name, n, hasSorry)

/-- 命令：`#turnCheck foo bar` 打印一张表。 -/
elab "#turnCheck " ids:(ident)+ : command => do
  let env ← getEnv
  for id in ids do
    let nm ← liftCoreM <| realizeGlobalConstNoOverloadWithInfo id
    let (n, k, s) ← liftCoreM <| liftIO <| inspectConst env nm
    let flag := if s then "含 sorry" else "ok"
    logInfo s!"{n}\t前件数={k}\t{flag}"

end TurnCheck
```

**使用说明与诚实提示**：

- `countBinders` **是语法计数**，包含 `variable` 提升出来的隐式参数。**故它给出的数字通常大于「真实前件数」**。要得到真实的「概念前件数」，须排除 `[inst : ...]` 与 `{...}` 隐式参数——本脚本**故意不做这个过滤**，因为**漏报比误报危险**（漏报会让你以为某定理前件少）。
- `sorryAx` 的**直接**检查很弱（`axiom` 的传递依赖看不见）。**必须**配合 `#print axioms`。
- **本脚本的价值**：它使「前件密度」与「sorry 存在」成为**可批量获取的数字**，从而让纪律 7 的表三、表四**不依赖人工清点**。人工清点会漏，脚本不会——但脚本会用错，所以**每轮抽验 3 条**（纪律 2 已有此要求）。

### 6.2 PowerShell 侧：`check-tautology.ps1`（补充既有脚本）

工作区已有 `check-tautology.ps1` 与 `_rewrite_tautology.ps1`，说明同义反复检查已有基础。**本文件建议补的一条**：不只检查「定理体是否 `exact h`」，还要检查**前件的逻辑内容是否强于结论**。

```powershell
<# 转项合规粗筛：在给定目录的 .lean 文件中，标记「疑似同义反复 / 疑似结论入前件」的模式。
   这是**文本级启发式**，不是证明器。命中必须人工复核。
   设计取舍：宁可多报（假阳性可复核），不可漏报（假阴性会变成永久债务）。 #>

param([string]$Root = "命运")

$patterns = @(
  @{ Name = "intro-exact 同义反复"; Pat = 'intro\s+(\w+)\s*$\s*exact\s+\1' },
  @{ Name = "前件与结论同名";       Pat = '\(\s*h\s*:\s*([^)]+)\)\s*:\s*\1' },
  @{ Name = "sorry 直接出现";        Pat = '(?<![A-Za-z])sorry(?![A-Za-z])' },
  @{ Name = "匿名前件（应具名）";    Pat = '^\s*theorem\s+\S+\s*\([^)]*\.\.\.' }
)

$hits = foreach ($f in Get-ChildItem -Path $Root -Recurse -Filter *.lean) {
  $lines = Get-Content -LiteralPath $f.FullName
  for ($i = 0; $i -lt $lines.Count; $i++) {
    foreach ($p in $patterns) {
      if ($lines[$i] -match $p.Pat) {
        [pscustomobject]@{
          文件 = $f.FullName; 行 = $i + 1; 类别 = $p.Name; 内容 = $lines[$i].Trim()
        }
      }
    }
  }
}

$hits | Group-Object 类别 | Select-Object Name, Count | Format-Table -AutoSize
$hits | Export-Csv -NoTypeInformation -Encoding UTF8 "turn-check-report.csv"
```

**脚本的两条诚实提示**：

1. **这些正则会对注释与字符串误报**。项目里 `sorry` 作为中文叙述的一部分出现在文档字符串中是常见的。**故「命中数」不等于「违规数」**，必须在报表里分开报告。

## 第七部分 · 结语：三条不可让渡的原则

1. **转项的产物不是一条定理，而是一条「记录」。** 若一条转项之后，除了 Lean 文件里的一行 `theorem` 之外什么都没有增加，那这次转项**没有发生**——它只是一次改名。

2. **Lean 编译通过是必要条件，不是充分条件。** §三 的七条纪律里，编译器只能强度地守住两条。**其余五条必须靠脚本 + 台账。**把「CI 绿」当成「转项合规」，是本方法论最想阻止的那一次跳跃。

3. **最诚实的一句话，比最漂亮的一条定理更有价值。** 项目的既有文件已多次示范这一点：`06-构建验证-未完成.md` 写「未验证，非已验证」，`02-定理清单.md` 写「本框架内已证者：0 条」，`1xx轮-诚实修正命名.md` 主动更正命名。**本方法论的唯一目的是让这种诚实变得可机械维持——而不是依赖每一轮的人品。**
