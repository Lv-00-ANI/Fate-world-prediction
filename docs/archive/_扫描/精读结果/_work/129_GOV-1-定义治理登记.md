## 第 146 条：查「两概念有无连接」时只 grep 两者名字相邻

**现象**：

```lean

## 规则 G14（新立）

## 规则 G46（新立）：**「被消费」的精确定义（唯一权威）**

**定义**：模块 M 被**真消费** ⟺ 存在另一个文件 F 的**证明项或类型签名**里
出现了 M 的某个**已声明名字**（全限定名或经 open 的短名）。

**不算消费**：

- 只在 docstring / `/-! -/` 里提到

# 真消费：精确全限定名 + 排除注释行
Select-String -Path Fate/*.lean -Pattern "Fate\.M\.\w+" -Encoding utf8 `
  | Where-Object { $_.Filename -notmatch "M\.lean" } `
  | Where-Object { $_.Line -notmatch "^\s*(--|/-|\*)" }
```

**验证法（最可靠）**：删掉 `import Fate.M` 那一行，
若文件**不能编译**，则 M 被真消费；若仍能编译，则**没被消费**。

## G61 · 禁止限制边界表述（第 1049 轮，来源：作者裁决 E2）

**禁止**在报告、提交消息、文档中把以下内容写成结论：

- 「概率侧仍特化」「图侧到极限、概率侧未到」

## G62 · 「到极限」表述废止，主线改为逐步组合（第 1049 轮，来源：作者裁决 E3）

**「到极限」不存在，只是一种表达方式，不得作为判据或验收标准。**

**主线方向**：
1. **终极目标**：一条**包含整个理论的大定理**
2. **当前阶段**：**逐步的组合定理**（相邻要件组合成一条）
3. **优化方式**：给这条（或这几条）大定理逐步优化（前件变弱、载体变一般、结论变强）

**禁止**：
- 汇报「N/9 到极限」
- 用「是否到极限」作验收
- 补单要件内的定理数量当作进展

**要求**：
- 每轮汇报必须说明：**本轮组合了哪几件、覆盖了什么链**
- 验收标准改为：**组合定理是否存在、前件能否弱化、载体能否推广**
