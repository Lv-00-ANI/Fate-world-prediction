## 4.2 净版对「主链目标」的正面表述是什么

**【净版】** 第 4 章本章结论第 1 条（`:1722`）：

> 确定动力系统与随机过程是生成轨迹的**两套数学语言**：确定系统给唯一轨迹，随机系统给分布轨迹，混沌系统给不可预测轨迹

**【净版】** 第 7 章本章职责（`:2828`）与 7.1.2 节（`:2927-2938`）：

> 「终点是预测，不是解释。因果解释是预测的副产品，不是目的」
> 裁决 7.1：保留该判词，但**必须补加限定语**——「终点是预测。因果的**解释性叙事**是预测的副产品；但**干预量 $a_t$ 不是副产品**」

## 6.5 关于 E7 的 `RuleSystem`（我的判断，**需要你确认**）

E7 给的草案是：

```lean
structure RuleSystem where
  rules : Finset Rule
  apply : Rule → State → State
```

**【推断】这个草案有两个隐患，建议在实施前改：**

1. **`Finset Rule` 要求 `Rule` 可取等（DecidableEq）。** 而 `Rule := C → X → Measure Y` 是**函数类型**，一般**没有** `DecidableEq`。要么加 `[DecidableEq (Rule C X Y)]` 作前件（但这几乎不可能满足），要么改用 `Set Rule`（= 已有的 `Rules`）。**⟹ 建议 `rules : Set Rule`，与 `Rules`（`WorldModel.lean:123`）统一。**
2. **`apply : Rule → State → State` 把规则强制成点值映射。** 这**丢掉了净版定义 5.2 的核形式**（分布输出）。**⟹ 建议 `apply : Rule → State → Measure State`**，与净版 `R:P(y|x,c)` 一致；点值情形由 `Rule.IsDet` 特例给出（`Frame.lean:398` 已有）。

**【推断】改了这两点后，E7 的 `gstepOfRules` 就变成：**

```lean
structure RuleSystem (C X : Type) where
  rules : Set (Rule C X X)
  apply : Rule C X X → X.Carrier → Measure X.Carrier   -- = Rule.kernel 的抬高

/-- ⚠ 这一层才是「规则生成动力学」 -/
def gstepOfRules (R : RuleSystem C X) (S : Selector C X X) (c : C.Carrier)
    : X.Carrier → X.Carrier :=
  fun x => Classical.choose …   -- 从 predOfRules S R.rules c x 取支撑点（要求每核 Dirac）
```

**⟹ 这样 E7 的「前件包含规则的性质」就有内容了**：前件不再是 `|1-η|<1`，而是「`Rs` 中每条规则在 `c` 处都是 Dirac（`Rule.IsDet`）且选择器 `IsValid`」。**这两条都是可验证的、真实的、关于规则的断言。**
