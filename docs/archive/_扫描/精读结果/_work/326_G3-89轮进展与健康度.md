### 2.1 · 「326 个模块扇入 = 0（占 41%）」

**提交**：`7ac4e91` "feat(G59): 扇入检查上线 —— 326 个模块扇入=0（占 41%）"

#### (a) 复算这个数字

`7ac4e91` 引入的脚本文本（`git show 7ac4e91 -- _audit/count_metrics.ps1`）：

```powershell
$zeroFanin = @()
foreach ($k in $imported.Keys) {                       # ← $imported = Fate.lean 的 import 列表
    $resolved = $k -replace "\.", "\"
    if (-not (Test-Path -LiteralPath "$desk\Fate\$resolved.lean")) { continue }
    $fanin = 0
    $imp_files = Get-ChildItem "$desk\Fate" -Recurse -File -Filter "*.lean" | Where-Object { $_.FullName -notmatch [regex]::Escape("$resolved.lean") }

}
```

#### (b) 判断：是「真的没人用」还是「统计口径问题」？

**判定：主要是统计口径问题。准确的说是——「扇入=0」这个指标在本项目的架构下，从定义上就不可能不为 0。**

**硬证据（决定性）**：

```
$ (Select-String -Path 命运\Fate.lean -Pattern "^import Fate\.([A-Za-z0-9_]+)$").Count
801
$ (Get-ChildItem 命运\Fate -File -Filter "*.lean").Count
801
库内但 Fate.lean 未直接 import: 0
```

**`Fate.lean` 把库内 801 个顶层模块**全部**`import` 了，一个不漏。**

于是：

- 每个模块的**唯一** import 者都是 `Fate.lean`；
- 扇入的定义是「被多少个其他模块 import」；
- `Fate.lean` 不是 `Fate/*.lean` 里的成员（它在仓库根），脚本的 `$imported` 来自 `Fate.lean`，但扇入计数时**不把 `Fate.lean` 算作 import 者**；
- 结果：**任何模块只要没有被别的 `Fate/*.lean` 再 import 一次，扇入就等于 0。而 `Fate.run` 的架构是「一个根文件 import 全部」，本来就不需要模块之间互相 import。**

**所以「扇入=0」在本库的真实语义是「这个模块没有被其他模块直接 import，仅被 `Fate.lean` import」——这是 `Fate.lean` 扁平架构的必然产物，不是「无人使用」。**

**题目要求的核查——这 282 个里有多少在 `Fate.lean` 里？**

```
扇入=0 且被 Fate.lean import: 282 / 282 = 100%
扇入=0 且 NOT 被 Fate.lean import（真正完全孤儿）: 0
```

**100% 都在 `Fate.lean` 里。** 也就是说：**这 282 个模块没有一个是「完全够不着」的，它们全部在构建图内、全部会被 `lake build` 编译、全部对 `Fate` 命名空间可见。**

**进一步：扇入=0 不等于没内容：**

#### (c) 但也不能全推给口径：`24dd8ce` 换的 G46 口径同样失真

`24dd8ce` 把 G59 改成 G46「严格口径」（脚本 diff）：

```powershell
$hits = Select-String -Path $f.FullName -Pattern ("Fate\." + [regex]::Escape($k) + "\.\w+") -Encoding utf8 | Where-Object { $_.Line -notmatch "^\s*(--|/-|\*)" }
$refs += ($hits | Measure-Object).Count
```

**这个口径测的是「`Fate.<模块名>.` 这个字符串在别的文件的非注释行里出现几次」。** 三个结构性缺陷：

1. **与 import 无关**：只要在别处写一句 `Fate.Foo.bar`（哪怕是 `#check Fate.Foo.bar` 或一行 `example : ... := Fate.Foo.bar`），就算「被消费」，**不需要真的 import 该模块**；
2. **反向也失真**：一个模块被 `import` 且其定理被 `open` 后以**无限定名**使用，字符串 `Fate.Foo.` 不出现，会被误判为 zero_consumption；
3. **测不出「使用」vs「提及」**：一行 `#print Fate.Foo.thm` 也算消费。

**实测（`_scratch_audit13/confront.py`）：**

```
zero_consumption (原口径): 557 / 801
  其中扇入>0（有真实 import 者）却被判 zero_consumption: 280
```

**280 个模块——明明有真实模块 import 了它们（扇入 > 0），却被 G46 判为「零消费」。** 这证明 G46 口径与真实依赖**基本脱节**。

#### (d) 两个口径的交叉结论

```
扇入=0（282）  ∩  零消费（557）  =  277
```
