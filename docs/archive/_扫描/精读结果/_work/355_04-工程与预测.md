## 架构与各层设计

### 一、两层来源：总纲版与工程卷版

「预测系统」在原文中出现过两次，且**详略与层数不同**，必须先分清，否则会把第 15 轮的简纲误当成第 21 轮的实现。

| 来源 | 层数 | 层清单 |
|---|---|---|
| 第 15 轮总纲 §5.2（`C-总纲与因果数学.md:540-554`） | 7 层 | 数据层 → 因果发现层 → 结构因果模型层 → 规则提取层 → 规则泛化/完善层 → 预测/干预/反事实层 → 评估与反馈层 |
| 第 21 轮卷 VI §1.2（`F-工程实现.md:54-99`） | 9 层 + 反馈层 | 数据层 → 因果发现层 → SCM 层 → 规则提取层 → 规则泛化层 → 预测层 → 干预与反事实层 → 评估层 → 反馈与更新层 |

两版的差异有两处实质变化：

1. **第 15 轮把「预测/干预/反事实」压成同一层**（`C:551`），第 21 轮将其**拆为预测层与干预反事实层两层**（`F:81-88`）。这是该轮唯一一次把三者的层级地位显式分开——但拆开的是**实现位置**，不是**语义区分**（见下文第三节）。
2. **第 21 轮新增「反馈与更新层」**（`F:96-98`），第 15 轮只有「评估与反馈层」这一合并层。

### 二、第 21 轮各级层的设计内容（按原文 §1–§13）

卷 VI 的结构为 13 节（`F:24-36` 目录）：系统架构总览、数据层、因果发现层、SCM 层、规则提取层、规则泛化层、预测层、干预与反事实层、评估层、工具栈、代码实现、部署与运维、统一框架中的工程。

**§1 系统架构总览**（`F:40-121`）

- 七条设计原则（`F:44-50`）：分层解耦、因果优先、规则可插拔、干预可追溯、反事实可计算、持续学习、可解释性。
- 「因果优先」被写成流程约束：「**先结构，后规则，再预测**」（`F:45`）。这一条是全卷的架构前提，也是第 22 轮被推翻的那一条。
- 模块接口表（`F:110-121`）给出 10 个模块的输入/输出二元组。该表是**唯一一处跨层契约描述**，但只有 I/O 名义，没有类型、没有误差传播、没有维度约定。

**§2 数据层**（`F:125-228`）

- 六类数据类型（时序、面板、图、文本、事件、领域知识），表在 `F:129-136`。
- 预处理五类：缺失值、异常值、标准化、平稳化、特征工程（`F:140-180`）。
- 存储选型表（`F:184-191`）与数据管道 `DataPipeline` 代码（`F:195-217`）。
- **判定**：`DataPipeline` 是**真实现**——`SimpleImputer(strategy='median')` + `StandardScaler` 的 fit/transform/fit_transform 三段式是自洽且可直接运行的（`F:201-217`）。这是全卷少数几个不是空壳的代码块之一。
- §2.5「科学映射」表（`F:219-228`）把数据层映射到「运 / 规则 / 命 / 因果 / 记忆」。该表**无定义来源**：「预处理 → 规则」「标准化 → 命」「存储 → 记忆」这三条映射在原文任何地方都没有给出构造或判据，属于命名类比，不构成理论内容。

**§3 因果发现层**（`F:231-399`）

- 算法选择表（`F:235-245`）列 PC / FCI / GES / NOTEARS / DYNOTEARS / TCDF / PCMCI / LiNGAM / ANM 九种，每行给出「假设 / 输出 / 适用」。
- **PC 实现**（`F:254-306`）：`skeleton_discovery` 是**真实现**（条件独立检验 + 分离集收集的双层循环，`F:258-278`）；`ci_test` 是**真实现**（空条件集用 `pearsonr`，非空用线性回归残差偏相关，`F:280-291`）；`orient_edges` 是**半实现**——v-结构部分写了（`F:296-303`），**Meek 规则只剩注释占位 `# Meek 规则` + `# ...`**（`F:304-305`），直接 `return dag`（`F:306`）。
- **NOTEARS 实现**（`F:315-345`）：`forward` 给出重构损失、无环约束 `h = trace(exp(W∘W)) - d`、L1 正则三元组（`F:322-332`），数学形式正确；`fit` 写了 Adam + 增广拉格朗日 + 乘子更新（`F:334-345`）。
  - **但存在两个未声明缺陷**：(a) `self.rho` 与 `self.alpha` **在 `__init__` 中从未初始化**，`__init__` 只定义了 `W` 和 `lambda1`（`F:316-319`），`fit` 里直接使用 `self.rho`、`self.alpha += ...`（`F:340,344`），运行即 `AttributeError`；(b) 缺 `torch.abs`，`torch.norm(self.W, 1)` 在 PyTorch 中传入整数 p=1 需 `torch.linalg.norm` 或 `torch.norm` 的等价形式，原文写法为直译。
  - 结论：NOTEARS 块是**形式正确但不可运行的实现**，不是空壳，但也**从未被验证过能跑**。
- **DYNOTEARS 实现**（`F:351-369`）：`fit` 做了滞后数据构造（`F:361-365`），随后**核心优化段只剩注释 `# 优化 W (同期) 和 A (滞后)` + `# ...`**（`F:367-368`），直接 `return self.W, self.A`（`F:369`）——而 `self.W`、`self.A` 在 `__init__` 中也从未定义（`F:352-355`）。这是**空壳**。
- **PCMCI 实现**（`F:375-386`）：`fit` 只有三步注释（「1. PC 条件独立检验 / 2. MCI 条件独立检验 / 3. 方向确定」）+ `# ...`（`F:383-385`），直接 `return self.causal_graph`（`F:386`），`self.causal_graph` 未定义。这是**空壳**。
- §3.1 表中列出的 FCI、GES、TCDF、NOTEARS(时序以外)、LiNGAM、ANM **在卷 VI 中完全没有代码**，仅出现在算法表与 §10.1 工具栈（`F:1048` 的 causal-learn, CDT, gCastle）。**声称覆盖 9 种算法，实际给代码的 5 种，其中能跑的 3 种。**

**§4 SCM 层**（`F:405-523`）

- `StructuralCausalModel`（`F:406-443`）：`fit` 按父节点有无分派到外生变量或结构方程（`F:412-424`），`_fit_equation` 用 `GradientBoostingRegressor`（`F:426-431`），`predict` 逐节点计算（`F:433-443`）。**这是真实现**，且是全卷最完整的一段。但它同时暴露了一个理论缺口：**外生变量被直接赋值为观测数据本身**（`self.exogenous[node] = data[node].values`，`F:418`），这在 SCM 语义下是把外生项等同于观测值，反事实所依赖的 `P(U)` 因此无从谈起。
- `Intervention.do`（`F:449-462`）：**真实现**——`copy.deepcopy` → 删除指向 `node` 的入边（切断父节点依赖）→ 把该节点方程替换为常数函数（`F:456-461`）。这是卷 VI 中**语义最正确**的一段代码，do 算子的「图手术 + 方程替换」两步都在。
- `Counterfactual.compute`（`F:468-479`）：**半实现/实为空壳**——注释声明三步「1. 更新外生变量 / 2. 修改结构方程 / 3. 计算 Y」（`F:474-476`），实际只有第 2 步的 `deepcopy` + 方程替换（`F:477-478`），**第 1 步「更新外生变量」根本没有代码**。而按第 18 轮卷 III §6.3 的定义，反事实的第 1 步正是「给定证据 e，更新外生变量 `P(U|e)`」（`C-总纲与因果数学.md:1369-1373`）。缺了这一步，`Counterfactual.compute` 与 `Intervention.do` **在代码上等价**，两者算出的是同一个量。
- `backdoor_adjustment`（`F:485-494`）与 `frontdoor_adjustment`（`F:500-512`）：**真实现**，公式与第 18 轮卷 III §4.7/§4.8（`C:1266`、`C:1281`）一致。但前门实现中 `p_m_given_x = data[data[M] == m][X].mean()`（`F:505`）取的是 `X` 在 `M=m` 子集上的均值，而公式要求的是 `P(M=m|X=x)`；这是**从公式到代码的对应错误**，不是空壳但是错的。

**§5 规则提取层**（`F:531-644`）

- `RuleExtractor`（`F:532-560`）：三路分派 `decision_tree` / `association` / `causal`（`F:536-542`）。前两路是真实现（`_extract_tree` 用 `DecisionTreeRegressor(max_depth=3)` + `export_text`，`F:544-548`；`_extract_association` 用 mlxtend 的 apriori + association_rules，`F:550-554`）。**第三路 `_extract_causal` 是空壳**：函数体只有注释 `# 因果规则提取` + `# ...`（`F:557-558`），然后 `return causal_rules`（`F:559`）——`causal_rules` 从未被定义，是 `NameError`。
- **致命处**：第 21 轮的完整流程 `FatePredictionSystem.fit` 第 4 步调用的是 `RuleExtractor(method='causal')`（`F:1136`），即**主流程恰好调用了三层中唯一空壳的那一层**。这不是边角缺陷，是主链路断裂。
- `extract_rules_from_tree`（`F:567-571`）、`extract_association_rules`（`F:580-588`）：真实现，且与 §5.1 内部重复（同一套 apriori 逻辑写了两遍）。
- `CausalRuleLearner`（`F:593-616`）：真实现，三步（估计 CATE → 离散化 → 树提取）都有代码（`F:599-611`）。**但 `self.estimator.estimate(X, T, Y)` 的具体估计器在全文未给出**（`F:595` 只接收一个 `causal_effect_estimator` 参数），且 `_discretize` 中 `cate.reshape(-1,1)`（`F:616`）要求 `cate` 为 numpy 数组，而 `estimate` 返回类型未定义。属**接口未闭合的实现**。
- `symbolic_regression`（`F:624-633`）：真实现（gplearn `SymbolicRegressor` 参数完整）。
- §5.4 标题写「因果规则（**CURLS 风格**）」（`F:590`），但正文与代码未出现 CURLS 的任何具体引用、公式或对照；第 15 轮 §4.5 把 CURLS/CRTRE/STRIM 列为「因果规则学习」现有方向（`C:518`），也只给了方向名。

**§6 规则泛化层**（`F:652-757`）

这是空壳密度最高的一层。

- `LLMRuleRefiner.refine`（`F:653-678`）：**真实现（但实现的是一个 prompt）**——构造一段自然语言 prompt，要求 LLM 输出「泛化规则 / 规则依赖图 / 新规则 / 完善建议」四项（`F:658-676`），然后 `return self.llm.generate(prompt)`（`F:677`）。
  - **关键缺陷**：返回的是**未被解析的原始文本**。调用方 `FatePredictionSystem.fit` 第 5 步把 `refined_rules` 直接喂给 `CausalEnhancedPredictor(self.scm, refined_rules)`（`F:1141-1144`），而预测器需要一个可迭代的规则集。**文本 → 规则对象之间没有任何解析层**。因此这一层的产出在整个系统中不可用。
- `transfer_rules`（`F:684-690`）：**空壳**——四步全是注释（`F:686-689`），`return target_rules`（`F:690`）未定义。
- `MetaRuleLearner`（`F:696-708`）：**半空壳**——`meta_train` 有循环骨架（`F:700-704`），但 `self._update_meta(rules)` 未定义；`meta_test` 直接 `return self._adapt(self.meta_knowledge, new_task)`（`F:708`），`_adapt` 与 `self.meta_knowledge` 均未定义。属**双层未定义**。
- `bayesian_rule_update`（`F:714-723`）：**半实现**——先验×似然、归一化两步写了（`F:717-723`），但 `compute_likelihood(rule, data)` 未定义（`F:719`），且后验未做归一化前的合法性检查；**先验从何而来在全卷未回答**（第 22 轮助手自己指出「贝叶斯更新需要先验，先验哪来」，`F:1435`）。
- `RuleEvolution.evolve`（`F:729-746`）：**骨架**——选择/交叉/变异/更新四步的循环结构完整（`F:734-746`），但 `_select`、`_crossover`、`_mutate` 三个方法**全部未定义**。属**一处未定义三连**。

**§7 预测层**（`F:765-867`）

- `Predictor`（`F:766-782`）：真实现（分派 + fit/predict 转发）。
- `CausalEnhancedPredictor`（`F:787-808`）：**核心空壳位于此处**。`predict` 声明三步「1. SCM 预测 / 2. 规则修正 / 3. 融合」（`F:796-804`），第 1 步 `scm_pred = self.scm.predict(data)` 有代码（`F:798`），第 3 步 `return scm_pred + rule_correction` 有代码（`F:804`），**但第 2 步 `rule_correction = self._apply_rules(data)` 所调的 `_apply_rules` 函数体只有一句 `return 0`**（`F:806-808`）。
  - 后果是精确的：`rule_correction` 恒为 0，`scm_pred + 0 = scm_pred`。**所谓「因果增强预测」在代码上退化为纯 SCM 预测**，规则层对预测的贡献恒等于零。「因果增强」这一命名在该实现下**不成立**。
- `TimeSeriesPredictor`（`F:814-825`）：真实现（ARIMA(1,1,1) + forecast）。
- `gp_predict`（`F:834-839`）：真实现（Matern(nu=2.5) + `return_std=True`）。
- `LSTMPredictor`（`F:848-856`）：真实现（LSTM + Linear），但**无训练循环**，只有 `forward`。
- §7.1 分派出的第三种方法 `hybrid` → `HybridPredictor`（`F:775-776`）**在全卷任何地方都没有定义**。
- 另注：`TimeSeriesPredictor.predict(data)` 接收 `data` 参数却完全不用，直接用 `self.model.forecast`（`F:824-825`）——签名与实现不一致。

**§8 干预与反事实层**（`F:875-960`）

- `InterventionOptimizer.optimize`（`F:876-892`）：**骨架且调用了不存在的方法**——用 `scipy.optimize.minimize` 包住 `loss`，`loss` 内部调用 `self.scm.do(data, intervention)`（`F:887`）。但 §4.2 定义的干预算子在 `Intervention` 类上（`F:449`），**`StructuralCausalModel` 类上没有 `do` 方法**。属**跨类接口断裂**。
- `PolicyOptimizer.optimize`（`F:898-915`）：真实现（枚举动作取最大 reward），但同样调用 `self.scm.do(data, action)`（`F:909`），同一断裂。
- `RLAgent`（`F:924-933`）：真实现（stable_baselines3 PPO 的 train/predict 封装）。
- `CounterfactualInference.infer`（`F:939-950`）：**与 §4.3 `Counterfactual.compute` 逐字重复**（`F:943-950` vs `F:472-479`），同样缺「更新外生变量」一步，注释同样声明了三步（`F:945-947`）。这是**同一段空壳被复制成两个类**。

**§9 评估层**（`F:968-1034`）

- `evaluate_prediction`（`F:969-976`）：真实现（MAE/RMSE/R2/MAPE，含 MAPE 的除零隐患）。
- `evaluate_causal_effect`（`F:982-987`）：真实现，但 **`true_effect` 是参数**——评估需要真值，而真值在真实数据上不可得。
- `evaluate_counterfactual`（`F:993-997`）：同样需要 `true_cf` 参数，**反事实真值在原则上不可观测**（第 18 轮卷 III §6.5 明确「反事实不可直接观测」，`C:1391-1395`）。因此该函数在真实场景中**无法被调用**。
- `evaluate_rules`（`F:1003-1010`）：**空壳**——五个指标 `compute_coverage` / `compute_confidence` / `compute_lift` / `compute_complexity` / `compute_interpretability` **全部未定义**，且「可解释性」如何计算全文无数值定义。
- `evaluate_generalization`（`F:1016-1023`）：真实现，但 `model.score` 要求模型实现 sklearn 接口，而卷 VI 的 `CausalEnhancedPredictor` 等类**未继承 sklearn BaseEstimator**，接口不匹配。

**§10 工具栈**（`F:1040-1102`）：12 类核心库表格 + DoWhy/EconML/Causica + mlxtend/gplearn/imodels 用法片段。这些是**外部库的调用示例**，不是本理论自身的实现。

**§11 代码实现**（`F:1109-1202`）：`FatePredictionSystem` 完整流程 + 配置 + 运行示例。这是卷 VI 的收口，也是所有断裂的汇聚点（见下文矛盾清单）。

**§12 部署与运维**（`F:1208-1304`）：API Gateway / Prediction Service / Data Storage 三层部署图；FastAPI 三个端点（`/predict`、`/intervene`、`/counterfactual`）；Prometheus+Grafana / ELK / Jaeger / Alertmanager / GitHub Actions+ArgoCD / Docker+K8s；`ContinuousLearner.update`。
- `ContinuousLearner.update`（`F:1275-1293`）：**半实现**——四步都有代码，但第 2 步 `self.system.rule_refiner.refine(new_rules)`（`F:1285`）**只传了 1 个参数，而 `LLMRuleRefiner.refine` 需要 `(rules, domain_knowledge)` 两个参数**（`F:657`）；第 4 步 `self.system.evaluate(new_data)`（`F:1291`）**只传 1 个参数，而 `FatePredictionSystem.evaluate` 需要 `(y_true, y_pred)` 两个参数**（`F:1164`）。两处签名不匹配。
- `/predict` 端点把置信度硬编码为 `[0.95]*len(result)`（`F:1252`）——**常量伪置信度**，与 §7.4 声称的 GP 可返回 `sigma`（`F:838`）矛盾：既然能算不确定度，端点却输出常数。

**§13 统一框架中的工程**（`F:1310-1364`）：工程映射表（10 行）、完整公式 `x_{t+1}=f(x_t,u_t,ε_t;θ,do(a_t))`、规则式 `R:P(y|x,c)`、规则演化式 `R_{t+1}=Update(R_t,Data_t)`；结论段称「每层可独立替换 / 每层可独立验证 / 每层可独立优化」（`F:1360-1362`）。
- **「每层可独立验证」这一条被本卷自身否定**：§9 的评估函数需要真值参数，而反事实真值不可观测、因果图真值未知、规则层「可解释性」无定义。三层不可独立验证。

### 三、预测 / 干预 / 反事实的严格区分

原文中三者的区分只在**第 18 轮卷 III** 被严格给出，卷 VI 只承接了符号而未承接定义。

**第 18 轮的定义性文本**（`C-总纲与因果数学.md`）：

| 区分点 | 原文位置 | 内容 |
|---|---|---|
| 概率论层的三分 | `C:1031-1041` | 相关 `P(Y\|X)`（观测到）／干预 `P(Y\|do(X))`（主动改变）／反事实 `P(Y_{X=x})`（替代路径）；并写明三句断言：「相关不等于因果。干预不等于观测。**反事实不等于预测。**」 |
| 因果阶梯 | `C:1360-1366` | 关联 `P(Y\|X)`「看到 X，Y 如何」／干预 `P(Y\|do(X))`「做 X，Y 如何」／反事实 `P(Y_{X=x}\|e)`「若当时做 X，Y 会如何」 |
| 反事实的定义 | `C:1353-1357` | 给定外生变量 `u`，若 `X=x`，则 `Y` 为何 |
| 反事实的三步算法 | `C:1369-1373` | ①给定证据 `e`，更新外生变量 `P(U\|e)`；②修改结构方程 `X=x`；③计算 `Y` 在新模型中的分布 |
| 反事实 vs 干预 | `C:1379-1389` | 干预 `P(Y\|do(X=x))`；反事实 `P(Y_{X=x}\|e)`；**「反事实更细：条件于具体证据」** |
| 反事实不可观测 | `C:1391-1395` | 「同一对象只能走一条轨迹。反事实是替代路径的推演。不可直接观测，只能通过模型计算。」 |
| 干预的语义 | `C:1254` | 「区别：干预切断 X 与其父节点的依赖」 |
| 观测分布 | `C:1214-1218` | `P(V)=∫P(U)∏𝟙[V_i=f_i(pa(V_i),U_i)]dU` |

**据此，三者的严格区分可归纳为四条正交判据**（全部有原文依据）：

1. **算子判据**：预测用观测条件分布 `P(Y|X)`；干预用 `P(Y|do(X))`，其数学内容是在图上删除指向 `X` 的入边（`C:1328` 的 `G_{\overline X}`、`C:1254`）；反事实用 `P(Y_{X=x}|e)`，其数学内容是**在固定外生变量 `u` 后**替换 `X` 的方程。
2. **外生变量的地位**：预测与干预**不条件于特定 `u`**（干预分布对外生分布取期望）；反事实**必须条件于证据 `e` 从而反推出该个体的 `u`**（`C:1371`「给定证据 e，更新外生变量 P(U|e)」）。这是三者唯一不可互换的判别式。
3. **可观测性判据**：预测的检验对象是未来观测（可观测）；干预的检验对象是实验/AB 结果（需实验可获得）；**反事实的检验对象不可观测**（`C:1393-1395`），因此 §9.3 的 `evaluate_counterfactual(true_cf, ...)` 在原则上无法取得 `true_cf`。
4. **粒度判据**：干预是**群体/分布层面**的量（`P(Y|do(X=x))` 无 `e`）；反事实是**个体层面**的量（`C:1389`「条件于具体证据」）。

**卷 VI 对这三条区分的处理**：§1.4 模块接口表把三者列为独立模块（`F:118-120` 干预/反事实行），§8 给三者各自一节。但**卷 VI 全文未复述上述任何一条判据**，也未在代码中体现判据 2。证据是 `Counterfactual.compute`（`F:468-479`）与 `Intervention.do`（`F:449-462`）的**代码差异仅为类名**：两者都是 `deepcopy` + 替换方程 + `predict`，前者缺的恰好是判据 2 所要求的「更新外生变量」那一步。

**结论**：三者的严格区分在原文中**只存在于第 18 轮（卷 III）**，卷 VI 承接了三个术语却未承接区分；在实现层面，**干预与反事实被实现为同一段代码**，「反事实不等于预测」这句断言在卷 VI 的代码里没有对应物。

## 技术裁决

### 一、工程可行性

**裁决：卷 VI 作为「实现」不成立；作为「模块清单」有部分残留价值。**

判据来自上表而非印象：

1. **主链路断裂**。`FatePredictionSystem.fit` 的八步中，第 4 步走空壳分支（`F:1136` + `F:557-559`），第 5 步的产出（LLM 文本）无解析层进入第 6 步（`F:1141-1144` + `F:677`），第 6 步中规则校正恒为 0（`F:806-808`）。**该系统的三个核心卖点（因果规则、LLM 泛化、因果增强预测）在代码上全部为空。** 系统即使跑通，其行为等价于「数据管道 + SCM/GBR 回归 + ARIMA」，即一个普通的监督学习基线。
