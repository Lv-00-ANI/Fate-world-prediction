### D1. 数据层输入（第 21 轮）

- **原始数据** \(\mathcal{D}\)：原文未给出数学定义，仅以表格列举六种类型：时序 \(\{x_t\}\)、面板 \(\{x_{it}\}\)、图 \(G=(V,E)\)、文本（「序列」，未定义）、事件（「点过程」，未定义具体测度）、领域知识（「规则」，未定义）。

- **面板数据** \(\{x_{it}\}\)：\(i\) 为主体索引，\(t\) 为时间索引。**\(i\) 的取值集合、\(t\) 与 \(i\) 的依赖关系、是否要求平衡面板，原文未定义，需补充**。
- **标准化**（第 21 轮 §2.2）：

  \[
  z=\frac{x-\mu}{\sigma},\qquad x'=\frac{x-\min}{\max-\min}
  \]

  其中 \(\mu,\sigma\) 为样本均值与样本标准差，\(\min,\max\) 为样本极值。**\(\sigma=0\) 与 \(\max=\min\) 的退化情形原文未处理，需补充**。

### D2. 因果发现层接口（第 21 轮 §1.4）

- **输入**：数据 \(\mathcal{D}\)（类型见 D1）。
- **输出**：**因果图** \(G=(V,E)\)。原文在 §1.4 接口表中统一写作「因果图」，但在 §3.1 表中各算法输出分别为 CPDAG / PAG / DAG / 时序 DAG / 「时序因果」（未定义）。

### D3. PC 算法（第 21 轮 §3.2）

原文给出类定义：

- `alpha`：显著性水平，默认 \(0.05\)，语义为条件独立检验的拒绝阈值。
- `ci_test(data, i, j, cond_set)`：返回布尔值，判据为 \(p > \alpha\)（即「不拒绝独立」判为独立）。返回值为 `bool`，但函数名与惯例（`ci_test` 通常返回独立性判定）一致。
- `skeleton_discovery`：输出骨架 `skeleton`（邻接表）与分离集 `sep_sets`。
- `orient_edges`：输出 `dag`。

**未定义项**：原文未说明「CPDAG」如何由该 `dag` 得到；`orient_edges` 返回的是含双向边的对象还是 DAG，原文未定义。

### D4. NOTEARS 目标函数（第 21 轮 §3.3）

原文给出：

\[
\text{loss\_rec}=\frac{0.5}{n}\,\lVert X M\rVert^2,\qquad M=I-W
\]
\[
h=\operatorname{tr}\!\left(\exp(W\circ W)\right)-d,\qquad \text{loss\_reg}=\lambda_1\lVert W\rVert_1
\]

其中：\(X\in\mathbb{R}^{n\times d}\)（\(n\) 为样本数，\(d\) 为变量数），\(W\in\mathbb{R}^{d\times d}\) 为待学邻接权重矩阵，\(\circ\) 为逐元素积（原文写作 `self.W * self.W`，在 PyTorch 中对 `nn.Parameter` 是 Hadamard 积），\(\lambda_1\) 为正则系数（默认 `0.1`），\(h\) 为无环性等式约束。

**语义澄清**：\(\operatorname{tr}(e^{W\circ W})=d\) 是无环性的等价刻画；原文表述为「无环约束」，正确。

**未定义项**：
- 原文代码中 `torch.norm(X @ M)` 使用默认 Frobenius 范数，与 \(\lVert\cdot\rVert^2\) 一致；但 `torch.norm(self.W, 1)` 在 PyTorch 中对矩阵的 `p=1` 是**矩阵 1-范数（最大列和）**，而 NOTEARS 论文中的稀疏惩罚是**逐元素 \(\ell_1\)** \(\sum_{ij}|W_{ij}|\)。**原文未察觉此差异，需修正**（详见「内部矛盾」C9）。
- 增广拉格朗日中的乘子 \( \rho,\alpha \) 在 `__init__` 中**未定义**（`self.rho`、`self.alpha` 从未初始化），却在 `fit` 中被读取与更新。这是**运行期必然报错的未定义变量**。

### D5. SCM（第 21 轮 §4.1）

原文实现：

```python
class StructuralCausalModel:
    def __init__(self, graph): ...
    def fit(self, data):
        for node in self.graph.nodes():
            parents = list(self.graph.predecessors(node))
            if not parents: self.exogenous[node] = data[node].values
            else: self.equations[node] = self._fit_equation(X, y)
```

- **代数对象**：\(\mathcal{M}=\langle V,U,F,P(U)\rangle\)（此定义**不在本模块**，由模块 G §4.5 给出；第 21 轮未写出该四元组，只给出代码）。
- **结构方程**：原文以 `GradientBoostingRegressor` 拟合，即 \(f_i\) 被**隐式定义为梯度提升树**。原文未讨论 \(f_i\) 的函数类、可识别性、additive noise 假设。
- **外生变量**：原文定义为「无父节点的节点的数据列」`data[node].values`。**这是本模块最严重的定义缺陷**：把「无父节点」等同于「外生」，在观测数据上无法保证外生性（可能仅是无观测父节点），且外生变量应是从结构方程残差获得，而非直接取数据列。**原文未定义，需补充**。
- **干预算子**（§4.2）：`do(node, value)` 实现为「删除 \(node\) 的所有入边 + 将方程替换为常数函数」。这是 do-算子的标准图操作，**语义正确**。但代码中 `modified_scm.equations[node] = lambda X: np.full(len(X), value)` **不更新 `graph.predecessors`**，而 `predict` 又以 `predecessors(node)` 判断是否外生，故干预后的 `predict` 仍会走原父节点分支——**干预实现与预测实现不一致，需修正**（详见 C7）。
- **后门调整**（§4.4）：\(\sum_z P(Y\mid X,Z)P(Z)\)，公式语义正确，但代码 `p_y_given_xz = scm.predict(subset)[Y].mean()` 实为 \(\mathbb{E}[Y\mid X\in\text{subset}]\) 而非 \(P(Y\mid X,Z)\)；且**未指定 \(Z\) 需满足后门准则**，函数签名接受任意 `Z`。
- **前门调整**（§4.5）：公式 \(\sum_m P(M\mid X)\sum_{x'}P(Y\mid M,X')P(X')\) 语义正确；但代码 `p_m_given_x = data[data[M]==m][X].mean()` 计算的是 \(\mathbb{E}[X\mid M=m]\)，与 \(P(M\mid X)\) **方向相反**，属实现错误。同样未指定 \(M\) 需满足前门准则。

### D10. 评估指标（第 21 轮 §9）

- **预测**：MAE、RMSE、\(R^2\)、MAPE \(=\frac{1}{n}\sum|\frac{y_{\text{true}}-y_{\text{pred}}}{y_{\text{true}}}|\times 100\%\)。**MAPE 要求 \(y_{\text{true}}\neq 0\)，原文未声明，需补充**。
- **因果**：bias \(=\overline{\hat\tau-\tau}\)、rmse、coverage \(=\frac{1}{n}\sum \mathbb{1}[|\hat\tau-\tau|<0.1]\)。**阈值 \(0.1\) 为原文硬编码，未说明其与被估量尺度的关系，需补充**。
- **反事实**：mae、correlation（皮尔逊相关系数）。**注意**：相关系数不能度量反事实估计的**值**准确性，只能度量共变；原文用它作为反事实指标，语义可疑。
- **规则**：coverage、confidence、lift、complexity、interpretability。**这五个函数在原文中从未定义**（`compute_coverage` 等全部只出现于调用处），**原文未定义，需补充**。
- **泛化**：train/test 分数与 gap \(=\text{score}_{\text{train}}-\text{score}_{\text{test}}\)。**`model.score` 的语义依赖于未定义的 `model`，需补充**。

| 误差类型 | 来源 | 能否形式化 | 能否压 |

## 核心命题

本模块**没有任何数学定理**。以下逐条列出的是工程命题、设计原则与经验断言，并标出来源轮次与性质。

### P1. 七条设计原则（第 21 轮 §1.1）

1. 分层解耦：每层可独立替换
2. 因果优先：先结构，后规则，再预测
3. 规则可插拔：规则表示与推理分离
4. 干预可追溯：所有干预可审计
5. 反事实可计算：SCM 层支持反事实
6. 持续学习：规则可更新，模型可演化
7. 可解释性：规则可读，因果可追溯

**性质**：设计口号，非命题。**P1.2（因果优先）与第 22 轮的结论 P2 直接冲突**。

### P2. 八条架构缺陷（第 22 轮，原文自我批判）

| 编号 | 缺陷 | 原文表述 |
|---|---|---|
| P2.1 | 因果发现是空中楼阁 | PC/FCI/NOTEARS 真实数据基本不可用；马尔可夫等价类使方向不可定；忠实性几乎不成立；高维 CI 检验做不动；隐混杂无处不在；非平稳非线性使算法失效 |
| P2.2 | SCM 结构方程无法拟合 | 外生变量估不出来 → 反事实依赖外生变量 → 反事实是垃圾；后门需知全部混杂（现实中不知道）；前门需完全中介（现实中很少） |
| P2.3 | 规则提取的「因果规则」是伪因果 | 决策树=相关、关联规则=相关、符号回归=拟合；真因果规则需因果效应估计 → 依赖 SCM → 依赖因果发现 → **循环依赖** |
| P2.4 | LLM 精炼是胡说八道 | LLM 不懂因果；迁移学习需域适应但因果结构跨域可能完全变；元学习需大量任务但因果任务不多；贝叶斯更新需先验但先验无来源 |
| P2.5 | 层数太多，误差累积 | 每层有误差、每层依赖上一层；无闭环验证、无端到端优化 |
| P2.6 | 预测和因果是两个问题 | 真实世界预测常不需显式因果；时序预测用 ARIMA/LSTM 直接预测即可；因果推断适合政策评估/AB 测试，不适合预测 |
| P2.7 | 计算复杂度爆炸 | 因果发现 \(O(n^3)\) 起步；SCM 高维爆炸；规则提取组合爆炸；LLM 慢且贵 |
| P2.8 | 未处理非平稳与分布偏移 | 整体方案假设因果结构固定，现实中不成立 |

**总结论断（第 22 轮）**：「这个工程方案在理论框架上自洽，但在真实数据上跑不通。」
**核心归因（第 22 轮）**：「因果发现和 SCM 不该作为预测系统的前置层。」

> **本模块的权威结论**。P2.6 尤为关键：它从**问题定义层面**切断了「因果→预测」的强制串联。

### P3. 四条替代路径（第 22 轮）

- **方案 A**：跳过因果发现，直接用预测模型 + 局部规则。梯度提升/LSTM/Transformer 做预测；SHAP/LIME/决策树提取局部规则；规则只做解释不做因果；干预用 A/B 测试或强化学习，不依赖 SCM。
- **方案 B**：因果只用于特定场景（政策评估、效应估计）；预测系统独立；两者通过领域知识连接，不通过 SCM。
- **方案 C**：规则系统独立。规则从数据提取而非从 SCM 提取；规则有时效、局部、依赖；规则泛化用统计方法不用 LLM；预测用规则 + 统计模型。
- **方案 D**：端到端学习。不做显式因果发现；用表示学习隐式捕捉因果；用因果正则化约束表示；预测和干预端到端训练。

**性质**：架构选型建议。**原文未选择其中任何一条**，第 22 轮以提问「你想往哪个方向讨论？」结束。**需补充决策**。

> **P3 与第 21 轮第 6 条设计原则（持续学习）及 §6.1 LLM 精炼直接冲突**：方案 A/C 都明确弃用 LLM 做规则泛化。

### P4. 形式化优先级（第 23 轮 §七）

原文给出的正确顺序：
1. 定义清楚
2. 条件定理证清楚
3. 误差界给清楚
4. 假设列清楚
5. 再写工程

**核心论断**：「工程不是不要，是应该在证明之后。但全部证完再工程，时间上不可行。」
**最终路线**：「局部形式化 + 假设显式化 + 端到端验证。」

### P5. 五阶段形式化路径（第 23 轮 §四）

- **阶段 0**：只定义不证明（概率空间、随机变量、图、d-分离、SCM、干预、反事实、规则、命运轨迹）
- **阶段 1**：证条件定理（d-分离→CI、因子分解→马尔可夫性、后门/前门准则→可识别、do-calculus 三条规则、反事实计算、Lyapunov 稳定性、马尔可夫链收敛、鞅收敛），每条显式列假设
- **阶段 2**：证误差界（统计估计、数值近似、泛化、反事实），不可压的给下界或不可识别性证明
- **阶段 3**：证算法正确性（因果发现、规则提取、预测、干预优化），规范为「在假设下，算法输出满足规范」
- **阶段 4**：提取可执行代码（证明 → 提取参考实现 → 手写高性能实现 → 证明两者等价）
- **阶段 5**：工程实现，每模块对应一组定理，每假设对应一个运行时检查，假设不成立时报警或降级

**性质**：方法论路线图。**这是本模块最可保留的成果**（P4+P5+P0 的误差分层 D11）。

### P6. 四条务实路径（第 23 轮 §六）

- **路径 A** 局部形式化：只证后门、前门、do-calculus、反事实、收敛性、误差界；其余用数值+实验验证
- **路径 B** 假设显式化：每模块显式列假设，不成立时系统降级；追求「假设清楚」而非「证完」
- **路径 C** 端到端验证：预测误差可测、干预效果可测、反事实可校准；用实验代替形式化证明
- **路径 D** 分层推进：先证最底层数学，再算法，再系统，不跳步

**注意**：P6 的路径 A/B/C/D 与 P3 的方案 A/B/C/D **使用同一套字母标签但内容完全不同**。跨轮引用时极易混淆。

### P7. 时间成本估计（第 23 轮 §五）

**性质**：**作者主观估计，无任何依据，不可作为规划输入**。

## 内部矛盾与未定义项

> 本节为本模块最重要的一节。所有条目均给出轮次与行号定位。

### 一、跨轮自我矛盾（第 21 轮 vs 第 22 轮）

#### C1. 架构有效性：第 21 轮与第 22 轮完全对立【最严重】

- 第 21 轮 §1.1 原则 2：「**因果优先**：先结构，后规则，再预测」，并在 §13.4 断言「每层可独立替换。每层可独立验证。每层可独立优化。统一框架指导工程实现。**工程实现验证统一框架**。」
- 第 22 轮：明确断言「这个工程方案在理论框架上自洽，但**在真实数据上跑不通**」，且「**因果发现和 SCM 不该作为预测系统的前置层**」。
- **矛盾**：第 21 轮声称「工程实现验证统一框架」，第 22 轮则说该工程根本跑不通。**若第 22 轮成立，则第 21 轮 §13.4 的结论不成立**。
- **处理建议**：以第 22 轮为准，删除 §13.4。

#### C2. LLM 规则精炼：第 21 轮列为架构层，第 22 轮判为「胡说八道」

- 第 21 轮 §1.2 把「LLM 精炼」列为规则泛化层的**首要组件**，§6.1 给出实现，§11.1 主流程第 5 步调用 `LLMRuleRefiner`。
- 第 22 轮 P2.4：「**LLM 精炼规则？LLM 不懂因果，只会胡说**」，方案 C 明确「规则泛化用统计方法，**不用 LLM**」。
- **矛盾**：同一组件在相邻轮次中从「核心层」变为「应删除」。
- **处理建议**：删除 §6.1 与主流程第 5 步，或在 P3 选型时明确保留条件。

#### C3. 规则提取依赖 SCM：第 22 轮指为循环依赖

- 第 21 轮 §1.4 接口表：「规则提取 | **SCM**+数据 | 规则集」；§5.4 的 `CausalRuleLearner` 依赖因果效应估计器。
- 第 22 轮 P2.3：「真因果规则需要因果效应估计，因果效应估计依赖 SCM，SCM 依赖因果发现，因果发现不靠谱。**这是个循环依赖**。」
- **矛盾**：第 21 轮把该依赖作为正常数据流，第 22 轮指出其构成循环。**且第 22 轮的分析正确**——第 21 轮的链是 SCM→规则，而 §5.4 的因果效应估计又需要结构信息，确实回环。
- **处理建议**：采纳第 22 轮，切断「规则提取 ← SCM」的强制依赖（方案 A/C）。

#### C4. 预测与因果的关系：第 21 轮串接，第 22 轮判为两个问题

- 第 21 轮 §1.3 数据流：「… → 规则泛化 → **预测** → 干预 → 反事实 → 评估 …」，预测位于因果链下游。
- 第 22 轮 P2.6：「**因果推断适合做政策评估、A/B 测试，不适合做预测。把两者强行串起来，反而两边都不讨好。**」

#### C5. 非平稳性：第 21 轮假设结构固定，第 22 轮指为致命缺陷

### 二、第 21 轮内部自相矛盾

#### C7. 干预实现与预测实现不一致（SCM 层）

- §4.2 `do`：先 `graph.remove_edges_from(in_edges(node))`，再设 `equations[node]` 为常数。
- §4.1 `predict`：`if not parents: result[node] = data[node]  else: result[node] = self.equations[node].predict(X)`。
- **矛盾**：`do` 修改了 `equations[node]`，但 `predict` 依据的是 `graph.predecessors(node)` 的分支选择。因为 `do` 已删除入边，`parents` 变为空 → `predict` 会走 `result[node] = data[node]` 分支，**即直接取数据中的原值，而不是取 `value`**。故 `do(X=x)` 中设定的 `x` **永远不会生效**。
- **结论**：干预功能**在逻辑上是死的**，尽管代码看似完整。这是「真设计 vs 空实现」核对中的关键发现。

#### C8. 反事实与干预无区别（SCM 层 / 反事实层）

- §4.3 `Counterfactual.compute` 与 §8.4 `CounterfactualInference.infer`：**代码逐字相同**，都只做了 `modified_scm.equations[node] = lambda X: np.full(len(X), value)`，且**都没有删除入边，也没有更新外生变量**。
- 注释却写着三步（含「1. 更新外生变量」）。
- **矛盾**：反事实的定义性特征（在**同一外生变量实现**下，改变某个结构方程后重算）完全未实现。当前代码既不是反事实，也不是正确的干预。
- **补充**：反事实的正确实现需要 **abduction（由观测反推外生 \(U\)）→ action（改方程）→ prediction（前向传播）** 三步；原文只写了第二步的骨架。

#### C9. NOTEARS 稀疏惩罚项与实际算法不符

- §3.3 代码 `torch.norm(self.W, 1)`。
- 声明为「L1 正则」。
- **矛盾**：PyTorch 中矩阵的 `p=1` 范数是最大列和（induced norm），而 \(\ell_1\) 正则应是逐元素绝对值之和。**同名不同物**，会导致稀疏化行为完全不同。原文未察觉。

#### C10. `PCAlgorithm` 有 `fit` 调用但无 `fit` 定义

- §3.2 定义 `PCAlgorithm`，方法为 `skeleton_discovery`、`ci_test`、`orient_edges`。**没有 `fit`**。
- §11.1 主流程：`self.causal_discovery = PCAlgorithm(alpha=0.05); graph = self.causal_discovery.fit(data_clean)`。
- **矛盾**：主流程调用不存在的方法 → 必然 `AttributeError`。且 §3.2 的 `skeleton_discovery` 签名要求 `(data, nodes)` 两个参数，主流程只传了 `data`。

#### C11. `SCM.predict` 不做拓扑序传播（根本性设计错误）

- §4.1 `predict` 对每个节点独立使用 **观测数据** 的父节点值预测。
- 声明为「预测」并用于 `CausalEnhancedPredictor` 与 `do` 算子。
- **矛盾**：结构方程的前向传播要求按拓扑序，用**已预测的**父节点值递归计算。当前实现等于对每个节点做一次独立回归，**未利用图结构**。这使得 SCM 相对普通多输出回归**没有任何额外能力**——图结构仅用于决定「哪些列作为特征」。
- **推论**：在此实现下，`do` 算子的「删边」操作对预测结果**不产生任何结构影响**（仅影响特征列的选择），与因果图操作的理论语义脱节。

#### C12. 管道输出类型与下游类型不匹配（架构级断裂）

- §2.4 `DataPipeline.fit_transform` 返回 `numpy.ndarray`（`SimpleImputer` + `StandardScaler` 的输出）。
- §4.1 `StructuralCausalModel.fit` 需要 `data[node].values`、`data[parents].values`（**pandas DataFrame**）。
- §5.1 `RuleExtractor._extract_tree` 需要 `data.drop(columns=[target])`、`data[target]`（**pandas**）。
- §5.4 `CausalRuleLearner.learn` 需要 `X.columns`（**pandas**）。
- **矛盾**：主流程第 1 步把数据变成 ndarray，第 3/4 步却要求 DataFrame。**架构在数据层与上层的接口处断裂**，任何按 §11.1 组装系统的人都会立即遇到类型错误。原文未提供任何适配层。

#### C13. `FatePredictionSystem.__init__` 与 `fit` 的字段不一致

- `__init__` 定义 `self.evaluator = None`。
- `fit` 中**从未赋值** `self.evaluator`；`evaluate` 方法直接调用模块级函数 `evaluate_prediction`，不经 `self.evaluator`。
- **矛盾**：声明了评估层组件但从未接入。这与架构图 §1.2 中「评估层」的存在相冲突——评估层在实现中是**游离的函数集合，不是架构中的一层**。

#### C14. 缓存/状态字段缺失

- §3.5 `PCMCI.fit` 返回 `self.causal_graph`，从未定义。

### 四、裁决统计

| 类别 | 数量 | 说明 |
|---|---|---|
| 可保留 | 12 项（K1–K12） | 集中在第 22、23 轮的方法论成果；第 21 轮仅 4 项 |
| 需重写 | 10 项（R1–R10） | 覆盖第 21 轮全部九个层 + 接口表 + 架构图 |
| 应删除 | 14 项（X1–X14） | 第 21 轮的空壳实现、无效映射表、被否定的结论 |

**总体裁决**：
> 本模块的价值分布极不均匀。**第 21 轮（工程架构 + 代码）作为实现不可用**——43 项审计中仅 6 项为真实现，17 项为空壳或必然崩溃，且因果核心的四个概念（do、后门、前门、反事实）实现全部与理论不符。**第 22 轮（自我批判）是本模块的真正成果**，其八条诊断与四条替代路径应作为重构的出发点。**第 23 轮（形式化方法论）的误差分层与「能证/不能证」判据应被后续模块继承**，事实上已被模块 G 继承。F 的九层架构中，「因果发现 → SCM」前置链已被 G 的 FCA 概念格取代，**§3、§4、§5 在理论主线中已无位置**。
>
> 重构建议：本模块降级为**两份文档**——(1)《预测系统工程：失效分析报告》，收录 P2 八条缺陷、C1–C16 内部矛盾、P8 实现状态总表；(2)《形式化与假设管理规范》，收录 K1–K5。原第 21 轮的九层架构与代码，除 K9–K12 外，不进入正式理论文档。
