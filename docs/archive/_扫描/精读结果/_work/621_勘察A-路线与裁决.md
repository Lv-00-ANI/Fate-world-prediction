### 阶段 4 — 代码提取与手写实现的等价性证明（**裁决 C 恢复为必做**）

- **目标**：完成代码提取，**并证明**手写高性能实现与提取实现**等价**。两项**均为必做**，**无"可选"、无触发条件**。
- **范围**：① **代码提取**（经编译器 IR 或 `#eval` 路径）；② **手写高性能实现**；③ **等价性证明**——为手写实现建立**形式化的目标语言语义片段**并证"手写 ≡ 提取"（每个输入同输出，或差被显式界控制）；④ **算法规格冻结**（输入/输出/后置条件）作为比较基准；⑤ 交付物清单。
- **对原文的修正（2.4.2）**：
  - 原文这项**未计入成本**，而"两实现等价"的证明**往往比其中一个的正确性证明更贵**（需为手写实现建独立语义模型 + refinement 论证）。
  - **必要性三判据**：手写实现是否必须存在 → **取决于性能**（原文"提取的代码性能通常不行"是**未经验证的经验断言**，本应在实验阶段回答）；等价性证明是否能做 → 原则上能，但**成本未知**且**需求形式化目标语言语义，Mathlib 生态内没有**；是否值得做 → **必做**。理由：等价性只保证"两者都不会比对方更错"，**不保证任何一个是对的**——但**"不保证其中一个对"是性质边界，不是不做它的理由**；正确性（阶段 3）与等价性（阶段 4）是**两项独立义务**；等价性证明的价值在于**使手写实现成为可替换的、且替换不引入新误差**。
  - **处置四条**：收回本路线作必做项，不设触发条件；列入验收标准；**风险注记保留但不再作为移出依据**；**冻结规格为附加义务**（只提供比较基准，不替代等价性证明）。
- **验收标准**：① 交付物清单**每一项都存在且可构建**；② 每个被提取算法有**冻结的规格文件**；③ **等价性证明已完成**：每个手写实现须有三者齐备——(i) 目标语言语义片段形式化、(ii) refinement 论证、(iii) "手写 ≡ 提取"定理，**不得以"提取代码性能足够"为由跳过**；④ `degrade` 的类型被写出，**且其值域具体取值按 2.4.3(b) 四要素填出**，触发条件与输出契约已给出；⑤ **零 `sorry`**，**全部 `axiom` 列在验收报告显式清单中**；⑥ `03-假设登记.md` 与主文档第 8 章 **A1–A34 逐条对齐，不得两套编号**。
