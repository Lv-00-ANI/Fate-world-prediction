## 派单纪律（每个专项都要这几条）

1. **构建只准** `powershell -ExecutionPolicy Bypass -File _check.ps1 -Group A`（或相应组）
2. **不要跑 git**（协调者统一提交）
3. **不许** `sorry` / `admit` / 自定义 `axiom`
4. **不许空泛证明**：每条定理必须写「比定义多说了什么」
5. **不许改动只读区**：`命运-素材-*`、`理论-文档/`（除指定新目录）、`Legacy/`
6. **不许改 `FateV2.lean`**，新模块加进 `GroupA.lean`（**import 必须在文件最前**，门禁 G12 会抓）
7. **定理必须登记**到自己的 `_support_registry_T*.csv`，`声明来源` 填实测 `#print axioms`
8. **失败要登记**，不许静默降级；**"做不到"必须附最小复现**

## 已知红线（派单时附带）

详见 [`命运-v2/_代理须知.md`](../../命运-v2/_代理须知.md) 与
[`命运-v2/_报告/踩坑-mutual归纳族零公理写法.md`](../../命运-v2/_报告/踩坑-mutual归纳族零公理写法.md)。摘要：

| 写法 | 后果 |
|---|---|
| `List.map` 对元素递归 | 退化 WF → 带 `propext`/`Quot.sound` |
| 嵌套模式 `.lit (.logic _)` | 带 `propext` |
| `funext` | 带 `Quot.sound` |
| 并列模式 `match a, b` | 带 `propext` |
| `simp` / `decide`（Core 内） | 带 `propext` |
| `import` 不在最前 | 构建直接失败（G12 抓） |
| `.lean` 带 BOM | `1:0: expected token` |

**正确姿势**：手写列表遍历放进 `mutual` 块；逐点等式代替 `funext`；嵌套 `match`。
