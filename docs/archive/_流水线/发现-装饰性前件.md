# 发现：capstone 第 7 条腿的「前件」与「结论」无逻辑联系

> **日期**：2026-11-04
> **发现**：专项 T61
> **性质**：**比「空洞」更微妙** —— 前件可满足、结论也真，但**两者之间没有推导关系**

---

## 一、事实

`FateV2/Loop/WorldModelCapstone.lean` 的 `backdoor_interface_consistent`
（`worldModel_capstone` 的第 7 条腿）有两个前件：

```lean
(hsep : ∀ (x y : Bool), R277.zbBackdoorSep x y {v | ∃ z₂, ZVert.z₂ z₂ = v})
(hpos : ∀ z₂ : Bool, R277.pZ R277.zb () z₂ ≠ 0)
```

### ① 它们都为真（T61 证出）

```lean
theorem hsep_holds : ∀ (x y : Bool), zbBackdoorSep x y {v | ∃ z₂, ZVert.z₂ z₂ = v}
theorem hpos_holds : ∀ z₂ : Bool, pZ zb () z₂ ≠ 0    -- 7/20 与 13/20
```

### ② 它们不是恒真式（T61 做了自我对偶检验）

```lean
theorem hsep_not_vacuous :
    (∃ x y, zbBackdoorSep x y {v | ∃ z₂, ZVert.z₂ z₂ = v})
      ∧ (¬ zbBackdoorSep false false (∅ : Set (ZVert zb)))
```

同一谓词，`W = {全 z₂}` 真、`W = ∅` 假。**所以 `hsep` 是有内容的。**

### ③ 但它们在证明里被 `clear` 掉了

`FateV2/Predict/WiringBackdoorFixed.lean:376-378`：

```lean
have hz : pZ zb () false ≠ 0 ∧ pZ zb () true ≠ 0 := ⟨hpos false, hpos true⟩
clear hforced hz
exact zb_adjustLaw_eq x y
```

**`hsep` 推出的 `hforced` 与 `hpos` 推出的 `hz` 都被 `clear`，结论来自数值定理 `zb_adjustLaw_eq`。**

### ④ 我的独立验证

```lean
-- 完全不带 hsep/hpos，结论照样成立
theorem adjust_eq_do_no_premises (x y : Bool) :
    R277.adjustLaw R277.zb x y = R277.doLaw2 R277.zb x y :=
  R277.zb_adjustLaw_eq x y
-- 通过 ✅
```

**⟹ 前件与结论之间没有逻辑联系。**

---

## 二、这比「空洞」严重在哪

| 形态 | 表现 | 危害 |
|---|---|---|
| **典型空洞** | 前件不可满足 ⟹ 定理无条件成立 | 容易被 `capstone_premises_satisfiable` 这类见证发现 |
| **数值冒充见证** | 见证与定理无关 | G17 能抓（T59 建成） |
| **本形态** | **前件真、结论真、但无推导关系** | **G17 抓不到**（结论确实是命题，不是数值） |

**⟹ 需要新的判据：「前件是否被使用」。**

**可机检的形式**：若把某前件替换为 `False`（或在证明中 `clear`）后结论仍可证，
则该前件是**装饰性的**。

---

## 三、影响范围

`worldModel_capstone` 的第 7 条腿（后门调整 = 干预）：

- **结论本身**：真（`zb_adjustLaw_eq` 独立成立）
- **前件**：真（`hsep_holds`、`hpos_holds`）
- **但**：这是**两条独立的真命题并列**，不是「前件 ⟹ 结论」

**所以「七条腿总装」这个说法，在第七条腿上是「两个真命题的合取」，而不是「一个有前提的定理」。**
