# 证明架构索引

> **本文件是全部 1106 个模块的导航入口。**
> 它回答一个问题：**我要找的证明在哪？**
>
> **生成依据**：逐文件读文件头注释分类，**不看文件名**（上游已记录多起「名不副实」实例）。
> 分类数据：`_inventory/Legacy分类.csv`

---

## 一、两层结构

```
FateWorld/
├── FateV2/   254 模块   ✅ 已验证实现层（门禁通过，按总设计分层）
└── Legacy/   851 模块   ⚠️ 历史代码收容层（仅保证可编译）
```

### 为什么分两层

`FateV2` 是按 `09-总设计` 的六层链路**新写**的实现，每个模块都有明确的层级归属。
`Legacy` 是历史代码的**全量收容**——它不声称任何定理正确，只保证「能编译、可审计」。

### 一个关键事实（实测）

**722 个只在 Legacy 的模块，完全不引用 FateV2 的任何模块。**
⟹ 两套代码是**平行**的，不是继承关系。`Legacy` 不是 `FateV2` 的旧版本，
而是另一条独立发展出来的路线。

## 五、这份索引的局限

1. **分类是按文件头关键词做的**，49 个模块（508 定理）未能自动归类。
   这不代表它们没价值，只代表它们的文件头没写清楚主题。
2. **没有做逐定理的语义审查**。分类说明「这个模块大概在讲什么」，
   **不说明「里面的定理对不对」**。
3. **重名模块的对照只抽查了一个**（`FitBoundary`）。其余 128 个未逐个比对。

> 本索引解决「**找不到**」的问题。解决「**对不对**」需要公理测绘与逐条验证，
> 那是下一步工作（见 README 的下一步优先级）。
